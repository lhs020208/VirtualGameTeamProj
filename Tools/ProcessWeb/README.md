# 로컬 공정 UI · 조회, 수동 조작, 레시피와 자동 배치

**6단계 실제 GPU 검증 기록: `Saved/ProcessWebGPUIntegration_20261117_141411`의 `validation_report.txt` 참조. 항목별 실제 GPU/CPU/모의 결과를 구분합니다.**

대상은 `L_ProcessPlant_LowPoly_1111`의 기존 UI에 명시적으로 연결된 해석 Actor입니다. 웹은 기존 `ProcessControlService`를 통해 전체 정지, 계산만 재개/일시정지, 밸브, 호퍼 압력, 공급 연결부 공기, 목표 RPM과 혼합 시작/정지를 요청합니다. 3D 관찰은 언리얼에서 합니다. 4단계 웹 레시피·자동 배치·남은 양 재개를 연결했습니다. 5단계 전용 경로로 자동 이송 중 수취 압력 조절도 연결했습니다.

## 실행 환경 준비

- 프로젝트가 사용하는 Unreal Engine 5.8와 C++ 빌드 도구.
- **Windows Node.js 20 이상**과 Edge/Chrome. 서버 런타임의 외부 npm 의존성은 없습니다.
- 2026-11-17 실제 실행: **Windows Node.js 22.23.5 / npm 10.9.9**, UE **5.8.2**, Edge, NVIDIA RTX 4060 Laptop GPU. 이전 PATH 미설치 기록은 해소됐습니다. 새 PowerShell에서 `node --version`을 확인하세요.
- 1~5단계에는 WSL 모의 검사를 사용했고, 6단계는 언리얼·서버·브라우저를 **같은 Windows 호스트**에서 실행했습니다. 모의 시험과 실제 GPU 시험은 별도 기록입니다.

## 서버 시작·접속·종료

프로젝트 폴더 PowerShell에서:

```powershell
node .\Tools\ProcessWeb\server.mjs
# 또는
.\Tools\ProcessWeb\Start-Viewer.ps1
```

접속 주소: **http://localhost:8765**, 대체 주소 `http://127.0.0.1:8765`.
서버가 실행돼도 언리얼에 연결되지 않았다면 **언리얼 연결 대기**이며 모든 조작이 잠깁니다. 서버·페이지 시작, 조회, 장비 선택은 장비 명령을 발행하지 않습니다. 브라우저를 자동으로 열거나 포커스를 바꾸지 않습니다.

서버 콘솔의 `Ctrl+C`로 종료합니다. 정상 종료 시 현재 서버가 만든 `Saved/ProcessWeb/link.json`만 제거합니다. 이 파일의 인증값은 버전 관리하지 마세요. 강제 종료 후에는 다음 시작에서 새 인증값으로 교체합니다. 종료·연결 상실 시 제어권과 대기 요청 처리는 아래 정책을 따릅니다.

```powershell
node .\Tools\ProcessWeb\server.mjs --port 8875 --ingest-port 8876
```

두 포트 모두 **127.0.0.1**에만 바인딩합니다. 사용 중인 포트의 다른 프로세스를 종료하지 않습니다. 다른 PC·LAN·HTTPS 공개 배포는 지원 범위가 아닙니다.

## 언리얼 실제 연결 · 6단계에서 확인한 실행 순서

1. 에디터 종료 후 프로젝트를 일반 빌드합니다. `Saved/.../BuildProject`는 검사 전용이며 그 DLL을 실행 중인 프로젝트에 복사하지 마세요.
2. Windows에서 서버를 시작합니다.
3. 아래처럼 에디터를 시작합니다. 기존 **`-ProcessWebState`는 조회 전용으로 유지**됩니다. 수동 명령은 **`-ProcessWebControl`**이 있어야 활성화됩니다. 옵션 없는 실행에서는 웹 연결이 꺼져 있습니다.

```powershell
& 'C:\Program Files\Epic Games\UE_5.8\Engine\Binaries\Win64\UnrealEditor.exe' `
  'C:\GitHub\VirtualGameTeamProj\VirtualGameTeamProj.uproject' `
  '/Game/ProcessPlant_20261111_LowPoly/L_ProcessPlant_LowPoly_1111' -ProcessWebControl
```

4. PIE를 실행하고 웹의 레벨·Actor·실행 ID·세대·스냅샷을 확인합니다. 명시적 Actor가 없거나 대상이 여러 개이면 조작하지 않습니다. **모의 데이터·모의 조작** 배지가 없는 실제 연결에서 제어권을 명시적으로 가져옵니다.
5. 레시피를 불러온 뒤 전체 적용하고, 공정 화면에서 시작 조건을 확인해 한 번 시작합니다. 종료할 때는 웹 전체 정지의 작업자 적용 완료를 확인한 다음 PIE를 종료합니다.

6단계 C 시험 데이터는 `Saved/ScheduledAdditiveValidation_20261115_015804/Input_ABC_6000`입니다. A/B/C 각 2,000개가 들어 있습니다. 시험 중 중지된 **PIE Actor에만** 입력 경로를 지정하고 초기화했습니다. 기본 레벨 입력은 저장하거나 변경하지 않았습니다. 시험 레시피 `웹 GPU 통합 검증 20261117`은 기존 레시피를 별도 이름으로 저장한 A40/B40/C20 g ±2 g, 15 RPM, 6 해석초, C 예약4초, 이송 수취 −0.5 kPa(g) 조건입니다. 운전 기본값으로 지정한 것은 아닙니다.

## 수동 조작 순서

1. 연결 상태와 최신 확정 데이터를 확인합니다. 상단 **전체 정지**는 제어권 없이도 요청할 수 있습니다. 작업자의 공기 차단·압력 0·밸브 닫힘·RPM 0·계산 일시정지를 확인한 뒤 완료가 됩니다.
2. **제어권 가져오기**를 누르고 실제 소유자가 `웹 · 이 화면`으로 바뀔 때까지 기다립니다. 가져오기 자체는 장비를 움직이지 않습니다. 다른 웹 탭이나 언리얼 일반 운전 명령과 동시에 운전할 수 없습니다. 언리얼에도 현재 조작 주체가 표시되며 전체 정지는 사용할 수 있습니다.
3. 기존 정책에 따라 **계산만 재개**를 요청합니다. 자동 배치나 취소된 예약을 복원하는 버튼이 아닙니다.
4. 공정도의 장비를 선택합니다. 입력칸에 직접 입력하거나 −/+를 누른 뒤 **적용**을 누릅니다. Enter/휠/상태 갱신은 명령을 보내지 않습니다. 요청값과 아래 실제 적용값, 명령 처리 상태를 비교하세요.
5. 공급 압력은 **A~F 공통**, 칭량·수취는 각각 별도입니다. 공급/칭량 −1~+1, 수취 −1~0 kPa(g), 연결부 공기 0~1 kPa(g), RPM 0~30입니다. 원본 서비스의 추가 조건과 보호가 항상 우선합니다. 범위 밖 값은 보정하지 않고 거부합니다.
6. 연결부 공기는 **선택한 A/B/C 밸브 하류 전용**입니다. 공급 호퍼 압력과 다릅니다. D~F는 미지원입니다. 공급 밸브·칭량 출구 닫힘과 공기 압력 등 기존 조건이 필요합니다.
7. **목표 RPM 적용**과 **혼합 시작**은 별도 조작입니다. 계산 RPM을 확인하세요. 현재 일시정지 정책 `CloseThenPause`는 전체 정지 확인 절차입니다. 실제 수신한 정책을 화면에 설명합니다.
8. 마치면 **전체 정지**의 적용 완료를 확인하고 **제어권 반환**을 누르세요. 반환 자체가 이미 적용된 장비 상태를 되돌리는 버튼은 아닙니다.

자동 배치 중 일반 웹 수동 명령은 차단합니다. 일반 수동 압력 버튼으로 자동 운전 제한을 우회하지 않습니다. 아래 5단계 전용 버튼만 현재 이송에 사용할 수 있습니다. 중단은 전체 정지를 사용하세요. 비활성 버튼 옆에 현재 차단 사유를 표시합니다.

## 연결 상실·요청 결과

- 요청은 `요청 접수 → 적용 확인 중 → 적용 완료`로 표시합니다. 서비스 거부, 실패, 결과 미확인은 별도 상태입니다. HTTP 성공만으로 적용 완료가 되지 않습니다.
- 브라우저 새로고침은 기존 요청 ID 결과만 조회합니다. **이전 명령을 자동 재전송하거나 제어권을 자동 복원하지 않습니다.** `미확인 요청 결과 조회`로 다시 확인할 수 있습니다.
- 웹 세션 하트비트는 0.75초, 제어권 유효기간은 3초입니다. 백그라운드 탭의 타이머가 제한돼도 자동으로 권한을 되살리지 않습니다. 명시적으로 다시 가져오세요.
- 서버 대기열의 미전달 명령은 제어권 종료 시 취소됩니다. 이미 서비스에 전달됐고 적용 대기 중인 웹 수동 명령은 기존 전체 정지 경로로 안전하게 취소·확인합니다. 이미 적용 완료된 설정은 연결 상실만으로 자동 복원하지 않습니다. 단순 조회 탭의 종료는 배치를 중단하지 않습니다.
- 서버 재시작 시 결과 원장을 복원하지 않습니다. 이전 ID는 `결과 확인 필요`이며 자동 재전송하지 마세요. 최신 상태를 대조하고 새 사용자 요청을 사용하세요. 초기화·PIE 재시작은 이전 실행/세대의 명령을 거부합니다.
- 일반 명령은 서버 수명당 240개까지 보관·접수합니다. 한도 후 전체 정지를 확인하고 서버를 재시작하세요. 전체 정지는 별도로 우선 처리하며 이전 정지 결과는 압축된 미확인 영수증으로 남을 수 있습니다.

## 4단계 · 레시피와 자동 배치

웹의 **레시피 설정 열기**에서 목록 새로고침 → 선택 레시피 불러오기 → 편집 → **레시피 전체 적용** → 공정 화면으로 돌아가기 → **자동 배치 시작** 순서로 사용합니다. 조회·저장·적용은 운전 명령을 발행하지 않습니다. 배치 실행은 기존 언리얼 서비스가 담당합니다.

- 실제 파일은 기존 **`Saved/BatchRecipes`**, 규격은 기존 버전 2입니다. 버전 1은 기존 단계 압력을 채워 읽고, 새 저장은 버전 2로 합니다. 서버는 파일 경로를 받지 않고 언리얼이 발급한 파일 ID를 전달합니다. 언리얼이 연결되지 않은 기본 실행에서는 목록/조작을 사용할 수 없습니다.
- 지원: A 전량, A 목표량, A→B 순차 계량, C 사용·예약 ON/OFF·N, 원료 표시명, 목표량/계량 공차(g), RPM, 혼합 시간(해석초), 칭량→수취 수취 압력. C `예약 ON · 0초`와 `예약 OFF`는 별개로 저장됩니다.
- 공급 단계는 A~F 공통 +0.5 / 칭량 −0.5 / 수취 0 kPa(g), 이송 단계는 공급 0 / 칭량 +0.5 고정입니다. 이송 수취 압력만 −1~0 kPa(g)에서 편집합니다. 내부 JSON은 kg, simulation_s, rpm, Pa_g입니다. 편집하지 않은 수치는 원본 double을 그대로 유지합니다.
- **새 이름으로 저장**은 기존 이름을 덮어쓰지 않습니다. 덮어쓰기는 목록에서 대상 불러오기 → 이름/내용 확인 → 확인란 → **선택 레시피 덮어쓰기**입니다. 목록만 갱신해도 불러온 버전을 새 버전으로 바꾸지 않습니다. 파일이 바뀌었다면 다시 불러와 비교하세요.
- 저장 실패는 기존 파일/적용값을 보존합니다. 모든 프로젝트 레시피 작성자는 `.recipe-write.lock`을 즉시 획득한 경우만 원자적 교체합니다. 잠금이 남으면 다른 저장 작업/편집기가 끝났는지 확인한 후 정리하세요. 자동으로 타인의 잠금을 제거하지 않습니다.
- `편집값`, `현재 적용값`, `이번 실행값`을 분리합니다. 적용 시 전체 검증하며, 시작 시 기존 재고/입자 분해능/장비 조건을 다시 확인합니다. 시작 버튼 옆의 사유가 실제 서비스 판정입니다. 실행 중에는 불러오기·저장·적용과 일반 수동 조작이 제한됩니다.
- 현재 웹 제어권을 가진 화면만 저장·적용·시작·상태 확인·재개·포기를 할 수 있습니다. 목록 조회는 제어권 없이 가능하고, 불러오기도 읽기 조작이지만 실행 중에는 제한됩니다. 언리얼 개별 배치 설정과 레시피 편집도 웹 소유 중에는 잠깁니다.
- 시작 요청 ID와 생성된 배치 ID를 기록합니다. 네트워크 응답의 `적용 완료`는 **시작 접수/배치 생성 확인**이며 **배치 완료**와 다릅니다. 실제 종료는 진행 상태에서 확인하세요.

### 전체 정지 후 남은 양 재개

1. **전체 정지** 후 기존 공기 차단·압력 0·실제 밸브 닫힘·RPM 0·일시정지 확인을 기다립니다.
2. 필요하면 **계산만 재개**와 장비 수동 조작을 사용합니다. 계산만 재개는 취소된 자동 배치/예약을 복원하지 않습니다.
3. 수동 조치 후 다시 전체 정지를 확인하고 **배치 상태 확인**을 누릅니다. 기존 복구 서비스가 ID/공급원/질량/현재 위치를 대조합니다.
4. 원료별 이미 통과한 양, 연결부·배관 이동량, **추가 공급할 양**과 **남은 이송량**을 비교합니다. 재개 버튼 위의 원료·경로·양 설명을 확인하고 **남은 양 이어서 투입**을 누릅니다. 확정 입자와 배치 ID는 유지합니다. 작업자 재개 승인 후 적용 완료로 표시합니다.
5. 상태 확인 후 수동 명령, 해석 시간/제어 revision, 연결/초기화 세대가 바뀌면 확인을 다시 해야 합니다. 오원료·위치 미확인·예약 시각 경과·계량 상한 초과 등은 기존 서비스 사유대로 차단합니다.
6. **현재 배치 포기**를 펼쳐 대상 배치를 확인하고 확인란과 포기 버튼을 사용합니다. 원료/기록은 지워지지 않습니다. 이후 새 배치에 필요한 초기화·실제 시작 조건을 확인하세요.

새로고침·연결 종료는 배치를 다시 시작하거나 실행 레시피를 덮어쓰지 않습니다. 언리얼이 이미 접수한 자동 배치는 계속 관리합니다. 미전달 배치 요청은 취소되고, 재접속하면 결과와 현재 배치를 조회한 뒤 제어권을 명시적으로 다시 가져옵니다. 서버/에디터 재시작 뒤 이전 결과 원장을 자동 복원하지 않으며, 실제 배치 복구의 영속 저장 기능을 추가한 것은 아닙니다.

## 자동 배치 중 현재 구간 압력 조절

웹 제어권을 가져오고 레시피를 적용한 뒤 배치를 시작합니다. 공정도에서 현재 구간에 참여하는 장비를 선택하면 구간 이름, 레시피 기준값, 편집값, 접수된 요청값, 작업자 적용값과 계산 유량이 표시됩니다. 단위는 입력·표시에서 kPa(g), 명령을 처리하는 서비스와 레시피에서는 Pa(g)입니다.

| 구간 | 선택할 장비 | 편집 범위 |
|---|---|---|
| 선택한 공급원 → 칭량 | 현재 공급 중인 A~F 중 한 호퍼 또는 칭량호퍼 | 각각 −1~+1 kPa(g) |
| 칭량 → 수취 | 칭량호퍼 또는 수취호퍼 | 칭량 −1~+1, 수취 −1~0 kPa(g) |

편집 후 **압력 적용**을 누릅니다. 작업자가 해당 요청을 처리하고 최신 스냅샷의 적용값이 일치하면 적용 완료로 표시합니다. 유량은 같은 스냅샷의 현재 경로 계산값입니다. 보호 닫힘, 연결부 비우기, 계량 확정 및 정지 단계에서는 버튼 옆에서 잠긴 이유를 확인합니다. 단계가 바뀌면 편집 대상도 갱신됩니다.

실시간 조절은 해당 구간 한 건에 적용됩니다. 다음 구간에서는 배치 시작 때 확정한 레시피 기준값을 사용합니다. 수동 운전의 공급 공통 압력과 하류 연결부 공기 명령은 기존 조작을 사용합니다.

공급원별 기준값을 편집한 레시피는 버전 4로 저장합니다. `hopper_pressure_targets.supplier_feed_pa`에는 `supply-a`부터 `supply-f`까지의 공급 단계 기준값이 들어갑니다. 두 단계의 칭량·수취 기준값은 기존 단계 객체에 저장합니다. 버전 1~3은 기존 공통값을 각 공급원의 기본값으로 사용합니다.

호퍼별 확장은 구현 상태입니다. 아래 모의·GPU 기록은 이전 수취 압력 기능의 기록이며, 확장된 경로는 4번 작업 후 통합 검증 대상입니다.

**연결 상실 정책:** 적용 대기 중인 웹 압력 요청이 있으면 3단계와 같은 전체 정지 경로로 취소·확인합니다. 이미 적용 완료된 요청만 있는 경우 제어권이 사라져도 언리얼이 같은 자동 배치를 계속 관리합니다. 접속을 복원해도 새 조작에는 명시적인 제어권 획득이 필요합니다. 서버 재시작은 이전 요청 결과 원장을 복원하지 않습니다.

## 6단계에서 발견해 수정한 연결·표시 결함

- Unreal의 대문자 UUID와 브라우저의 소문자 UUID가 같은 요청임을 서버가 인식하도록 정규화했습니다. 원래 브라우저 요청 ID 표기는 응답에서 유지합니다. 이 문제로 실제 정지는 완료됐는데 웹 요청이 계속 처리 중이던 상태를 해결했습니다.
- 작업자의 전체 정지가 완료된 뒤에는 정지 중에만 필요한 미확인 장비 안내를 현재 정지 상태에 남기지 않습니다. 정지 진행 중/실패의 미확인 사유는 유지합니다.
- 배치 완료 후 일시적 수취 이송 플래그로 `진행/확인 중`을 표시하지 않습니다. 최종 도착량과 배치 완료를 안내하고 이전 요청은 이력에 보존합니다. 이 마지막 표시 정리는 실제 GPU 완료 기록을 근거로 했으며, 후속 두 해상도 검사는 모의 브라우저 검사로 구분합니다.

Windows에 Playwright 전용 Chromium이 없으면 기존 Edge로 **헤드리스 배치 화면 검사**를 실행할 수 있습니다. 앱 포커스와 실제 운전에 영향을 주지 않습니다.

```powershell
$env:PROCESS_WEB_BROWSER_CHANNEL='msedge'
npm run test:batch-browser
```

실제 GPU 시험의 수치·사진·단계별 시각과 미확인 항목은 `Saved/ProcessWebGPUIntegration_20261117_141411/validation_report.txt`를 기준으로 확인하세요. 화면 캡처 시각과 확정 GPU 스냅샷 시각은 다를 수 있으며 정밀 대조는 스냅샷을 사용합니다.
