# DEMPrototype 실행·검증 보고

UE 5.8.2 프로젝트에 독립 CPU 구형 DEM 플러그인과 `DEM_Sandbox`를 구현하고 빌드·실행·수치 검증·성능 측정을 수행했다. 기존 설비와 연결하지 않았으며, 기존 `.uproject` 사용자 변경 및 기본 시작 맵을 보존했다. 산업용 검증 해석기 또는 CFD–DEM 결과가 아니다.

## 1. 구현 완료

- `Source/DEMPrototype/Public/DEMSolver.h`: SI 단위 double, 단일 스레드, 해석적 고정 벽, 선형 스프링–댐퍼 법선력, 접선 변위 이력·쿨롱 마찰·회전, semi-implicit Euler.
- `DEMSimulationActor`: 고정 dt 누산기, 실행/일시정지/한 단계/초기화, 속도·표시 주기·Reset 설정, 계측·저장. 기본 요청 속도 0.05배. 처리량을 초과하면 지연을 표시하며 2초 지연에서 일시정지한다.
- `DEMParticleRenderer`: 공유 구 메시 ISM, 충돌·Chaos·내비게이션·입자 그림자 비활성화, 프레임당 한 번 일괄 변환 갱신. HUD Step과 Tick의 중복 업로드도 차단한다.
- `ADEMHUD`: 조작 버튼과 통계, 키보드 Space/N/R/S. `ADEMGameMode`: 카메라 및 HUD.
- `DEMPrototypeEditor`: 전용 맵·구 메시 생성 commandlet. `Tests`: 엔진·렌더러 없는 검증 및 벤치마크.
- 맵: [DEM_Sandbox](Content/DEM_Sandbox.umap). 저해상도 구: 122 vertices / 168 triangles, 원래 반지름 1 uu. 비교 구: 559 / 960, 반지름 50 uu. 물리 반지름은 두 경우 모두 0.01 m.

최종 가정값은 kn=500,000 N/m, kt=250,000 N/m, dt=10 µs, 감쇠비 0.2/0.2, 마찰 0.4/0.4이다. 200개, 반지름 0.01 m, 밀도 1,000 kg/m³, 용기 0.30×0.30×0.25 m, seed=20261021. 물성 보정값이 아닌 시험용 가정이다. 자세한 식·부호·단위·좌표 변환·빌드 방법은 [README](README.md), 기계가 읽는 설정은 [configuration.json](Results/configuration.json)에 있다.

## 2. 실행·검증 완료

Unreal Development Editor 대상으로 여러 차례 컴파일에 성공했다. 독립 Standalone 프로세스에서 맵과 플러그인을 반복 재로딩했다. 최종 빌드 근거는 [build_final.log](Results/build_final.log).

[기본 시험 26개](Results/basic_checks.csv), [퇴적·dt 민감도 16개](Results/deposit_checks.csv), [해석 성능 시험의 유한성 확인 9개](Results/bench_checks.csv)가 통과했다.

- **A 자유 낙하:** 0.1초 후 dt=100 µs 위치 오차 4.905×10⁻⁵ m, dt/2 오차 2.4525×10⁻⁵ m. 1차 위치 오차와 일치하며 속도 오차는 약 10⁻¹⁴ m/s.
- **B 정면 충돌:** 총 선운동량 오차 0. 감쇠 후 운동에너지 감소. dt/2 충돌 속도가 1 µs 기준해에 더 가까워짐을 확인. 반발계수의 정확한 보장은 하지 않는다.
- **C 마찰·회전:** +X 미끄럼에 −X 접선력·+Y 토크 발생, 접촉점 미끄럼 감소, 쿨롱 한계 준수. 이력의 접선 평면 이동·접촉 종료 시 삭제·자세 정규화도 검증.
- **D 이웃 탐색:** 음수 좌표·셀 경계를 포함한 64개 배치에서 brute force와 144개 접촉 키가 동일, 중복 없음. 최적화 전 정렬 격자와 공간 해시의 충돌 포함 궤적도 동일.
- **E/F:** 동일 초기조건으로 각각 5초, 500,000 / 1,000,000 step 수행. 개수 200·질량 0.837758040957 kg 유지. NaN/Inf·바닥 중심 관통·측면 탈출 0. 마지막 1초 평균 총 운동에너지 <10⁻⁵ J 기준 충족.

| 항목 | dt = 10 µs | dt = 5 µs |
|---|---:|---:|
| 전체 실행 최대 겹침/작은 지름 | 0.897594% | 0.891458% |
| 마지막 1초 평균 총 운동에너지 | 4.15965e-6 J | 3.13159e-6 J |
| 최종 퇴적 높이 | 0.019999918 m | 0.019999918 m |
| 마지막 1초 평균 바닥 지지력 | 8.218399 N | 8.218388 N |
| 전체 중량 | 8.218406 N | 8.218406 N |
| 활성 접촉 이력 최대 | 241 | 254 |
| 이력 버퍼 총 capacity | 6400 | 6400 |
| 실행 중 버퍼 확장 | 0 | 0 |

이 용기·입자 수에서는 입자가 거의 한 층으로 퍼져 퇴적한다. 에너지의 절대값은 작지만 두 dt의 잔류 에너지 상대 차이는 약 25%이므로 개별 운동까지 수렴했다고 주장하지 않는다. 높이와 지지력의 상대 차이는 각각 약 4.6e-10, 1.4e-6이다. 실제 집계는 [deposit_metrics.json](Results/deposit_metrics.json), 전체 시계열은 [deposit_trace.csv](Results/deposit_trace.csv).

- **G 언리얼 통합:** 200/1,000/5,000개 × 해석만/저해상도/고해상도 × 3회 = 27개 Standalone 실행 완료. 각 규모의 위치·속도·각속도·자세·힘·토크 및 접선 이력·법선 CSV가 바이트 단위로 동일했다. [해시와 집계](Results/summary.json).
- 별도 200개 10Hz 표시 시험도 60Hz와 동일한 상태·이력이다. [표시 주기 독립성](Results/frequency_invariance.json).
- 각 실행의 `*_controls.json`에서 Start/Pause/Step/Reset 핸들러를 실제 호출해 확인했다. Step은 정확히 한 dt, Reset은 seed와 초기 상태·빈 접촉 이력을 복원한다.

## 3. 실패한 검증 및 수정

요청된 초기 후보 kn=1,000, kt=500 N/m, dt=100 µs는 최대 겹침비 **20.2615%**로 1% 목표를 실패했다. [원래 실패 결과](Results/candidate_checks.csv)를 보존했다. 강성을 500배, dt를 1/10로 변경한 뒤 5초 및 dt/2 시험을 다시 수행해 목표를 통과했다.

시각 검사에서 생성 구의 앞면 방향이 반대여서 안쪽 면이 보이는 문제와 카메라 구도 문제를 발견해 수정했다. 메시 갱신 첫 시도는 에셋 패키지가 일부만 로드되어 저장에 실패했고, `LoadPackage/FullyLoad` 후 기존 메시를 갱신하도록 수정해 성공했다. 실패 로그는 `mesh_rebuild_failed_partial_load.log`, 성공 로그는 `mesh_rebuild.log`에 보존했다. 최종 시각화로 렌더 비교를 다시 측정했다.

최종 수치 시험에서 실패한 항목은 없다. 다만 이는 기록된 시험 범위에 한정한다. `unoptimized_partial_*`는 최적화 전 중단한 개발 실행이며 완료 검증 근거가 아니다.

## 4. 도구·환경 때문에 미검증 또는 제한

- 연결된 언리얼 MCP는 `AgentSkillToolset`만 제공했다. 초기화·도구 조회는 실제 MCP로 수행했으나 맵 생성·C++ 실행 도구는 노출되지 않아 허용된 파일·빌드 도구와 commandlet으로 보완했다.
- GPU 시간과 개별 게임/렌더 스레드 시간을 분리 계측하지 않았다. 전체 프레임 간격은 GPU 시간으로 해석할 수 없다.
- 실제 마우스 좌표로 HUD 버튼을 클릭하는 자동 시험, 패키징한 Shipping 빌드는 미검증이다. 검증 대상은 Development Editor 바이너리의 Standalone 실행과 조작 핸들러이다.
- 거리별 다중 LOD는 구현하지 않았다. 두 메시 해상도와 표시 주기의 물리 독립성을 검증했다.
- 벽의 중심 투영 범위 밖 끝단·상단 둥근 모서리 접촉을 생략했다. 유한 높이 위에서 무한 벽이 작용하지 않는 시험은 통과했다. 모서리 지배 흐름에 적용하면 안 된다.
- 구름·비틀림 저항과 입자 sleep을 사용하지 않는다. 5초 동안 버퍼 누적 증가가 없었지만 다시간 내구 시험은 아니다.
- 설치된 MSVC14.43은 UE가 차단해 기존 설치된 14.51을 사용했다. UBT가 허용하되 권장 최신 버전보다 새롭다는 경고가 있다. 외부 도구 설치는 없었다.
- 기존 엔진 `ToolsetRegistry` Python 시작 스크립트가 Standalone에서 `unreal.PythonTestRunner` 미존재 오류를 기록한다. DEM 실행은 종료 코드 0으로 완료했고 수치·렌더 결과가 저장됐다. 이 기존 엔진 플러그인은 수정하지 않았다.

## 5. 측정 성능과 병목

환경: Intel Core i7-14650HX, 16 physical / 24 logical cores, RTX 4060 Laptop GPU 8 GB, RAM 약 31.73 GiB, Windows 11, UE 5.8.2. [hardware.json](Results/hardware.json). DEM은 단일 스레드 double. 원래 사용자 에디터를 닫지 않았으며 노트북 전력·온도·백그라운드 부하를 통제하지 않아 전용 실험실 벤치마크가 아니다.

렌더링 없는 native C++ `/O2 /fp:precise`: 비겹침 바닥 근처 배치, 0.1초 워밍업 후 동일 상태에서 1000 step을 3회 반복. 초기화·워밍업·파일 저장 제외. 용기 X/Y를 sqrt(N/200)만큼 확장했으며 반지름·물성·dt는 유지했다.

| 입자 | 용기 X=Y (m) | 접촉 / 후보 쌍 | 평균 step (ms) | p95 step (ms) | 해석시간/계산시간 |
|---:|---:|---:|---:|---:|---:|
| 200 | 0.3000 | 200 / 727 | 0.0654 | 0.1476 | 0.1532 |
| 1,000 | 0.6708 | 1000 / 3811 | 1.0386 | 1.4931 | 0.00963 |
| 5,000 | 1.5000 | 5000 / 19159 | 5.3252 | 6.7759 | 0.001878 |

p95는 각 반복 p95의 평균이다. 세 규모 모두 완료했으나 **실시간을 보장하지 않는다**. [원본 성능 CSV](Results/bench_performance.csv).

Standalone 비교는 동일 바닥 근처 fixture에서 10,000 step 워밍업 후 130 frame × 10 step, 첫 30프레임 제외, 나머지 100프레임 측정이다. 세 모드의 해석 step 수가 같다. 엔진의 “해석만” 모드에도 용기·HUD 렌더링은 남아 있으며 완전 무렌더 비교는 위 native 실행이다. 아래 값은 3회 평균, 괄호 안은 p95 평균이다.

| 입자 | 해석만 frame ms | 저해상도 frame ms | 고해상도 frame ms | 저해상도 변환 준비 / ISM 갱신 ms |
|---:|---:|---:|---:|---:|
| 200 | 9.601 (11.868) | 10.027 (12.329) | 9.933 (12.155) | 0.00248 / 0.01719 |
| 1,000 | 11.103 (13.683) | 11.096 (13.746) | 11.619 (13.181) | 0.00837 / 0.03362 |
| 5,000 | 30.794 (35.748) | 34.923 (40.353) | 36.816 (41.646) | 0.06204 / 0.19189 |

이 수치는 최종 카메라와 면 방향 수정 후 다시 측정한 결과이다. 전체 프레임 차이에는 DEM/CPU 부하·엔진 작업·대기가 함께 포함된다. 모드별 DEM step 시간도 달라 차이를 전부 삼각형 수에 따른 GPU 비용으로 귀속시키거나 항상 저해상도가 빠르다고 주장할 수 없다. [렌더 비교 CSV](Results/render_performance_summary.csv).

native 5,000개 step 구간 평균은 격자 0.330, 후보 탐색 3.108, 접촉 1.418, 적분 0.298, 통계 0.171 ms이다. 가장 큰 병목은 후보 탐색이다. 프레임의 마지막 DEM step만 샘플링한 Unreal 통계와 모든 step을 측정한 native 평균은 동일한 계측기가 아니므로 직접 등치하지 않는다.

## 6. 적용한 최적화와 물리 결과 유지

- 정렬 셀 배열의 27회 이진 탐색을 셀 동등성을 검사하는 공간 해시로 교체. 연속 버퍼·generation marker·링크 인덱스 재사용으로 입자별 heap 할당 제거.
- 제곱 거리로 비접촉 후보 제거, 실제 접촉에만 sqrt 사용. 질량·관성 및 역수 캐시, 접촉 이력 용량 재사용.
- 쌍 순서와 합산 순서를 유지했고 정렬 격자 기준과 충돌을 포함한 상태 비교가 정확히 일치했다.
- 같은 200개 profile fixture에서 탐색 시간은 약 0.2572→0.03594 ms로 감소했다. 다만 이전 profile은 다른 작업이 함께 실행되던 개발 측정이므로 약 7.2배라는 비율을 통제된 속도 향상 보장으로 사용하지 않는다. [전](Results/profile_before.csv) / [후](Results/profile_after.csv).
- 저해상도 ISM 공유, 인스턴스 유지, 화면 갱신과 DEM substep 분리, 한 번의 배치 업로드. 렌더 모드·주파수 변경 후 수치·이력 동일성을 확인했다.
- 접촉 생략, 시간 건너뛰기, float 전환, 가시성 기반 물리 제거, sleep, 병렬화는 사용하지 않았다.

## 7. 다음 단계 및 실행

프로젝트 루트 PowerShell에서:

```powershell
.\Plugins\DEMPrototype\Tools\Run.ps1 -Task Run
```

에디터에서는 Plugin Content를 표시하고 `/DEMPrototype/DEM_Sandbox`를 연 뒤 Play한다. 기본 맵 변경은 없다. Space 시작/정지, N 한 step, R 초기화, S 저장. 물성·입자 수 등은 DEM 액터 Details에서 지정 후 Reset한다. 재현 명령과 좌표·토크 수식은 [README](README.md)에 있다.

후속 작업은 후보 셀 조회의 캐시 효율 개선, GPU·게임/렌더 스레드 계측, 더 깊은 다층 퇴적·모서리 접촉 시험, 장시간 내구 시험 순서가 적절하다. 병렬화는 결정성·힘/이력 race 방지 설계를 마련한 뒤 단일 스레드 기준과 비교해야 한다.

[낙하 중 화면](Results/falling200_40.png)은 실제 동적 실행이다. [5초 퇴적 형상 화면](Results/settled200_40.png)은 수치 검증 실행에서 저장한 위치·자세를 표시한 스냅샷이며 힘·속도 재생은 아니다. 물리 검증 근거는 스크린샷이 아니라 CSV/JSON이다.
