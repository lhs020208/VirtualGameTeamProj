## CUDA C++ 후보와 채택 경로를 구분한 이유

CUDA C++ 커널도 작성하고 실행했다. 단순 장면에서는 일치했으나 밀집 구간에서 FP32의 미세한 위치 차이가 속도 차이로 확대되어 사전에 정한 단일 단계 속도 허용치를 초과했다. 해당 후보는 기본 경로에서 제외하며 `short_contact/`에 실패 증거를 보존한다. 벽면 비교의 초기 실패도 `validation_no_fma_rejected.json`에 남긴다.

채택 검증 대상은 기존 OpenCL 소스의 NVIDIA 컴파일 결과(PTX)를 보존하여 CUDA Driver API로 실행하는 경로다. 실행 중 OpenCL API에 계산을 위임하는 래퍼가 아니다. CUDA가 메모리·스트림·커널·동기화를 직접 관리한다. 다만 **커널 소스까지 CUDA C++로 완전히 옮겨 검증한 상태는 아니다.** PTX 재생성에는 현재 NVIDIA OpenCL 컴파일러를 사용하며, 원본 소스·생성 과정·아티팩트는 `ptx_provenance.json`과 스크립트에 기록한다. 이 선택은 컴파일러의 산술 변경과 실행 API의 변경을 분리하기 위한 것이다.

추가 최적화 경로는 동일 커널 연쇄를 CUDA Graph로 제출하고, 격자의 `-1` 초기화를 같은 비트값의 CUDA 메모리 초기화 명령으로 처리한다. 회전각은 기존과 동일하게 호스트의 FP32 누산으로 계산하고, 각 단계가 해당 각도를 읽는다. 각 커널 사이의 전체 장치 순서, 매 반복 공간 격자 재구축, 매 배치 오류 검사를 유지한다.

## 현실성을 더 높이기 위한 후속 물리 개발 조건

실재료 자료가 없는 상태에서 임의의 탄성계수·마찰·응집력을 실제 값으로 지정하지 않는다. 다음은 CUDA 실행 전환과 별도의 물리 모델 개발·보정 항목이며, 이번 동일 알고리즘 이식으로 완료됐다고 주장하지 않는다.

- 실제 원료의 입도 분포, 고체/벌크 밀도, 형상, 수분, 벽 재질을 결정하고 입력 자료의 출처와 불확실성을 저장한다.
- 기존 CPU 힘 기반 기준판을 공정 형상에 연결한 후, 구–구/구–벽 충돌, 경사면 미끄럼, 회전·구름, 적층 및 안식각, 배출 시험을 통과시킨다. 시간 간격과 접촉 이력을 먼저 검증한다.
- 실제 분말이 점착성·비구형이면 응집·비구형 모델을 독립 검증한다. 측정 없이 파라미터를 추가했다고 현실성이 입증되지는 않는다.
- 압력·유량 및 배출량 자료로 관로 모델을 확인한다. 밀집 영역에서 단방향 모델의 오차가 지배적이면 보존적인 양방향 유동 모델과 격자 수렴 검증이 필요하다.
- 최소 측정 권장 항목은 입도/밀도, 입자–벽 마찰 또는 경사면 시험, 정적·동적 안식각, 시간별 배출 질량, 주요 지점 압력·유량, 혼합도 시간 변화다. 보정용과 검증용 조건은 분리한다.

재료·공기 모델의 교체나 보정값 확정은 이번 성능 표의 개선율에 포함하지 않는다.
