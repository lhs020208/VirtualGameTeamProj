# 최적화 29~36 구현 및 검증 결과

2026-10-22 · PowderSimulationOptimization · 커밋/푸시하지 않음.

## 판정

29~36의 축약 공정 구현과 가상 시나리오 시험을 수행했다. **10/30/50 kg 원료의 순차 계량→진공 이송→수취·배출→혼합을 화면과 정기 기록을 포함해 약 2배속으로 계산했다.** 현재 PC의 해당 가상 시나리오는 목표 0.1배속을 통과한다. 녹화 재생이 아니라 실행 중 보존 질량·압력·전달량·공간 조성을 계산한다.

**실제 분말·실제 장비의 정확도 인증은 완료되지 않았다.** 34의 보정 도구와 독립 데이터 분리 절차는 합성 해석해로 시험했으며 실험 데이터가 아니다. 36도 실제 생산 설비 인수 완료가 아니다. 상세 DEM으로 미세입자 전량을 계산한 성능과 비교해서는 안 된다.

## 성능 증거

PC: Intel Core i7-14700KF, RTX 4060 Ti, RAM 32 GB, Windows 11, UE 5.8 D3D12 SM6. 공정 해석은 CPU, 시각화는 Unreal 렌더러다. 표시 예산 1500개 + 소수 연결 흐름 표식, 창 1280×720. 시험 TargetRate=2, 일반 기본값=0.1. 질량 3조건×각 3회, 혼합 단계는 각각 물리시간 30초 포함. 프로그램 시작/종료 시간은 배속에서 제외하고 별도 launch_to_result_s로 기록했다.

| 총량 | 사이클 물리시간 | 실행 중 실제 시간(3회 범위) | 최저 평균 배속 |
|---|---|---|---|
| 10 kg | 52.385초 | 26.193~26.196초 | 1.999749 |
| 30 kg | 79.295초 | 39.648~39.649초 | 1.999924 |
| 50 kg | 106.010초 | 53.005~53.008초 | 1.999877 |

전체 평균 배속 최저 1.999749, 중앙값 1.999924. 실행 중 1초 창 최저 1.995213. 원료별 질량 최대 절대오차 1.85e-12 kg. 1초 창은 완료 직전 1초 미만 꼬리 구간을 제외한다. 짧은 단계 단독 성능을 이 값으로 주장하지 않는다.

코어 27회(10/30/50 kg×15/30/60 RPM×3)의 최저 배속은 5003.1이나 렌더·표시·저장을 제외하므로 사용자 체감 성능으로 쓰지 않는다. 최종 렌더 결과는 같은 RPM의 코어 종료 시각과 0.02초 이내 일치했다. 모든 기록의 원료 질량, 압력 범위, 완료 상태 및 상태 파일을 다시 검사했다.

검증: 기존 회귀 포함 CTest 47/47, Unreal 자동화 18/18, 보정 Python 2/2. 마지막 누적 유량 시각화 변경 후 신규 코어 시험과 27회 코어 벤치마크, 최종 렌더 9회를 수행했다. 최종 Unreal 결과는 evidence/unreal_summary.json 참조.

## 실행 및 조작

1. Content Browser에서 **L_ProcessTwin**을 열고 Play. 기존 기본 맵과 상세 DEM 레벨은 유지했다.
2. RMB+WASD 등 기존 카메라 조작을 사용한다. 실행 중 F8로 Eject한 뒤 PowderProcessTwin 액터 Details에서 값을 조절한다.
3. Running, TargetRate, RPM, SupplyEnabled, TransferValveOpen, PumpEnabled, DumpValveOpen은 실행 중 반영된다. 멈췄다 재개해도 정지 중 벽시계 시간을 따라잡지 않는다.
4. TotalKg, BulkDensity, DragRelaxationSeconds, MixingExchange, DeadZoneFactor, VacuumTargetPa, SupplyKgPerSecond, RawReserveFactor, DisplayBudget 변경은 **Reset Simulation**으로 재시작한다. 영속 설정은 Play 종료 후 편집하고 저장한다.
5. HUD의 t는 물리 초, x는 실제 경과시간 대비 배속, P는 Pa, I는 이 모델의 조성 균일도이다. Complete는 정해진 공정 시간이 끝났다는 뜻이며 의약품 품질 합격 판정이 아니다.

실행 기록은 Saved/ProcessTwin_날짜시간/trace.csv, state.json 및 완료 시 result.json이다. state.json은 진단용이며 **파일에서 이어 계산하는 기능은 없다**. 원료는 기본 각 1/3 비율, 총량 1~50 kg. 잔량은 사라지지 않고 질량 장부에 남는다.

## 모델 범위 및 후속 검증

기본 가상값: 벌크 밀도 800 kg/m³, 공급 2 kg/s, 공기-분말 완화시간 0.15초, 진공 목표 90 kPa, 공간 혼합 교환계수 0.08, 정체영역 배율 0.15. 실제 물성이 아니다. 공급·배출은 유량 모델이며 개별 자유낙하 충돌을 계산하지 않는다. 수취부+관로의 유효 기체 용적 0.02 m³는 고정값으로, 충전 중 기체 용적 변화는 해석하지 않는다. 약진공 범위의 단방향 수송이며 임의 배관/강진공/역류 일반화 모델이 아니다.

지원 통로의 내부에 표식을 배치하고 실제 전달량이 있을 때만 연결 흐름을 표시한다. 관 표식은 누적 실제 유량, 혼합 표식은 누적 회전량에 연결했다. 표시 수를 바꿔도 물리 질량은 변하지 않는다. 표식은 재배치될 수 있으며 입자 추적 ID가 없다. 임의로 추가한 메시를 자동 물리 경계로 인식하지 않는다. 자연 발생 막힘·응집·입도 분급·파쇄·입자 접촉력 예측은 지원하지 않는다.

다음 실측 자료가 있어야 실제 디지털 트윈으로 보정할 수 있다: 공급 명령별 실제 유량/계량 오차, 압력·공기 유량·도착량의 시간 이력, 배관·용기 실제 치수, RPM/충전율별 위치별 혼합 조성, 벌크 밀도 및 입도·마찰·응집의 영향. 일부 조건으로 보정하고 별도 조건을 검증해야 한다. 27의 정확도 기준안(도착량 5%, 이송시간 10%, 혼합 지표 0.05 등)은 아직 실물 증거로 통과시키지 않았다.
