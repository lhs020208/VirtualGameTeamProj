# 추가 최적화 04 — 이웃 후보 목록 안전 재사용

## 구현과 안전 조건

기존 입자 접촉 식, 중력, 마찰, 반지름, 시간 간격, 접촉 반복 수, 벽·날개 투영을 유지한다. 작업 03의 후보 목록에 거리 여유(skin)를 추가하고, 매 접촉 계산 직전에 GPU에서 유효성을 검사한다.

- 목록 구축 반경은 `2r + s`, 기본 `s = 0.5r`이다. 실제 접촉 판정은 계속 `거리 < 2r`이다.
- 격자 셀 폭도 `2r + s`로 맞춰 27개 인접 셀에서 여유 범위의 이웃을 찾는다.
- 마지막 목록 구축 시 모든 입자의 위치를 저장한다.
- 현재 위치와 저장 위치의 거리 중 하나라도 `0.49s` 이상이면, **이번 접촉 계산 전에** 전체 격자와 후보 목록을 다시 만든다.
- 이 검사는 위치 예측 이후, 매 Jacobi 보정 반복 직전에 수행한다. 이전 반복의 입자 접촉 보정과 벽·회전 날개 투영으로 생긴 위치 변화가 모두 들어간다. 마지막 반복 이후의 변화도 다음 시간 단계의 첫 접촉 전에 검사한다.
- 용량 초과 입자가 하나라도 있으면 다음 반복은 강제로 재구축한다. 따라서 해당 입자의 기존 전체 탐색 fallback이 오래된 격자를 사용하는 일이 없다.
- Reset은 참조 위치의 유효성을 해제한다. 정상적인 CPU 배치 경계에서는 캐시를 유지한다. 생성기/설정 변경 시 Reset이 필요한 기존 규칙도 유지한다.

안전 논리: 목록에 없던 쌍의 구축 당시 거리는 적어도 `2r+s`다. 두 입자가 각각 참조 위치에서 `0.49s` 미만 움직였다면 현재 거리는 `2r+0.02s`보다 크므로 접촉할 수 없다. 기준을 넘으면 사용 전에 다시 만든다. 구축 거리 판정에는 작업 03과 같은 작은 바깥 수치 여유도 적용한다.
이 논리는 각 접촉 평가 시점에서의 누락 방지다. 기존 시간 적분 자체를 연속 충돌 검출(CCD)로 바꾸거나 실제 분말 정확도를 인증하는 것은 아니다.

## GPU 동작과 계측

유효성 판단을 위해 매 반복 GPU→CPU 동기 읽기를 추가하지 않는다. GPU의 재구축 플래그를 후속 격자/목록 커널이 확인한다. 재사용 가능한 반복에는 해당 커널이 데이터 처리를 건너뛴다. **커널 호출 자체가 사라지는 것은 아니다.**
변위 검사는 128스레드 그룹에서 OR 축약 후 그룹별로 재구축 플래그를 올려, 모든 입자가 같은 플래그에 atomic 읽기를 수행하지 않게 했다. 기존 in-order OpenCL 큐가 검사→구축→접촉 사이의 동기화를 제공한다.

`timing.json` schema 4에 추가:

| 항목 | 의미 |
|---|---|
| candidate_reuse_enabled | 안전 재사용 활성화 |
| candidate_skin_m | 실제 목록 여유 거리(m) |
| reuse_checks | 접촉 직전 검사 횟수 |
| candidate_builds | 실제 목록 구축 횟수 |
| candidate_reuses | 목록 재사용 횟수 |
| reuse_begin / reuse_check GPU 시간·calls | 플래그 준비 및 변위 검사 이벤트 |
| candidate_audit_enabled / candidate_audit GPU 시간·calls | 소규모 모든 쌍 검사 진단 |

일반 실행에서는 `candidate_builds + candidate_reuses = reuse_checks = 시간 단계 수 × 반복 수`다. 진단용 `inspect_candidates()`는 별도 강제 구축을 추가하므로 이 등식에서 제외한다.
`candidate_build_calls`, `grid_*_calls`는 GPU 계측 ON일 때의 **호출 횟수**이며, 플래그 때문에 내용이 생략된 호출도 포함한다. 실제 구축 횟수는 `candidate_builds`를 사용한다.

## 사용법

- `-GrainCandidateReuse`: 후보 목록과 안전 재사용을 함께 활성화.
- `-GrainCandidateSkinRatio=0.5`: 반지름 대비 skin 비율. 허용 0.01–2, 기본 0.5.
- `-GrainCandidateCapacity=64`: 기존 목록 용량 설정. 초과 시 전체 탐색 fallback 유지.
- 옵션을 주지 않으면 기존 전체 격자 탐색을 사용한다. 기본값 확정은 계획의 작업 08에서 통합 검증 후 결정한다.
- CLI `granular_run`은 기존 `candidates candidate_capacity` 다음에 `candidate_reuse skin_ratio`를 받는다. API/CLI에서는 reuse에 candidates가 필요하다.

에디터 종료 후 비교:

```powershell
python -B Scripts/run_additional_optimization04.py --run
python -B Scripts/run_additional_optimization04.py --run --modes reuse --seconds 30 --repeats 1 --label extended30
```

첫 명령은 기본 경로/재사용 경로 각 12초 2회(두 번째는 역순), 두 번째는 재사용 경로 30초를 검사한다. 중력·마찰·dt·반복 수를 성능 때문에 바꾸지 않는다.

## 검증

`optimization_granular_safe_reuse`는 다음을 검사한다.

- 처음 skin 밖에 있던 두 입자의 접근·새 접촉, 재사용/재구축 모두 발생.
- 위치 보정으로 새 접촉이 생기는 사례와 독립 CPU 모든 쌍 Jacobi 기준 비교.
- 큰 회전축/날개 투영, 벽 접촉 궤적, 용량 초과 fallback.
- 배치 경계 캐시 유지, Reset 무효화, 서로 다른 skin/격자 모드.
- 영역 이탈 및 잘못된 설정 거부.
- 소규모 시험에서는 **모든 접촉 반복 직전** 별도 GPU O(N²) 검사로 실제 접촉 쌍이 유효 후보/전체 탐색에 들어 있는지 확인한다. 누락은 안전 오류 비트 8로 거부한다.

O(N²) 검사는 후보가 활성화된 4,096개 이하 진단에서만 허용하고, 5만 개 성능 측정에는 사용하지 않는다. 기존 `optimization_granular_gpu`, `optimization_granular_candidates` 시험도 함께 실행한다.
대규모 비교는 초기 SHA/입자 수/그룹/질량/유한값과 마지막 스냅샷의 겹침·벽·날개 침투를 검사한다. 모든 중간 시각의 대규모 접촉을 전수 검사한 것은 아니다.
## 12초 비교 결과 (2026-10-27)

RTX 4060 Ti 16GB, 동일 50,000개/64.8kg MX301 테스트 장면, dt=0.000375s, 접촉 16회, 배치 32. GPU 이벤트 계측 OFF, 1280×720, 최대 30fps, 요청 속도 2배속. 각 경로 2회 측정.

| 경로 | 실측 배속 범위 | 중앙값 |
|---|---:|---:|
| 기존 전체 격자 탐색 | 0.19457–0.19619 | 0.19538 |
| 안전 재사용 | 0.30555–0.30617 | 0.30586 |

중앙값 기준 처리속도 약 **1.57배**, 소요시간 약 **36.1% 감소**다. 짧은 각 2회 측정이므로 다른 입도/충전량/형상에서도 같은 개선률을 보장하지 않는다.

- 재사용 실행의 실제 구축 횟수: 7,353 / 7,541회.
- 검사 횟수: 514,032 / 513,504회. 약 98.5–98.6% 재사용.
- 용량 초과 fallback 0회. 소규모 강제 초과 시험에서는 fallback을 별도로 검증했다.
- 네 실행 모두 초기 상태 SHA/그룹/입자 수/질량/유한값 검사 통과.
- 최종 겹침/반지름 최대 0.05995(기준 ≤0.1), 벽·날개 침투는 각각 0.0001m 이하.
- 마지막 위치 기록 시각이 약 11.87–12.00초로 다르므로 최종 입자별 좌표나 혼합 지표가 같은 시각에 정확히 일치한다고 주장하지 않는다.

원본과 실행 명령: [comparison/measurement.json](comparison/measurement.json). 최종 위치·trace·타이밍 JSON도 각 실행 폴더에 보존했다.
## 30초 연장 실행

재사용 경로 1회에서 **30.00075초 시뮬레이션 / 평균 0.29101배속**을 기록했다. 현재 5만 개 테스트 장면에 대한 결과이며 수십 kg의 실제 미세입자 전부 또는 전체 공정에 대한 성능 인증은 아니다.

- 검사 1,281,056회, 실제 구축 19,268회, 재사용 1,261,788회(약 98.5%).
- 용량 초과 fallback 0회.
- 초기 SHA, 입자 수/그룹/질량/유한값 검사 통과.
- 마지막 저장 위치는 시뮬레이션 29.79675초에 해당한다. 이 위치의 최대 겹침/반지름 0.08776(기준 ≤0.1), 벽 침투 약 4.92e-8m, 날개 침투 약 4.37e-8m(각 기준 ≤0.0001m).
- 모든 중간 시점과 30.00075초 종료 순간의 입자 간 겹침을 전수 검사한 결과는 아니다.

자료: [extended30/measurement.json](extended30/measurement.json).

기본 실행 경로는 유지했다. 새 경로는 `-GrainCandidateReuse`로 사용할 수 있으며, 계획대로 작업 08에서 조합 검증 후 기본값을 확정한다. 현재 저장된 레벨의 목표 배속 제한도 변경하지 않았다.
