# 최적화 25~26 구현 및 검증 결과

2026-10-22 · PowderSimulationOptimization

25~26 구현과 회귀 검증 완료. 24의 미커밋 변경을 보존한 상태에서 이어서 작업했다. 기존 문서에 25~26 상세 정의가 없어, 24에서 확인한 정렬 비용 개선을 이번 범위로 명시했다. dt·입자 수·물성·q는 변경하지 않았다. 0.1배속 및 전체 공정 인수는 여전히 미달이다.

## 최적화 25: 변경 없는 정렬 제출 생략

셀 이동 검사 후 4바이트 재생성 플래그를 읽고 변화가 없으면 키 생성·bitonic 정렬·해시 재생성 커널을 제출하지 않는다. 플래그 읽기의 호스트 동기화 비용까지 전체 계산 시간에 포함했다. 오류 발생 시 기존 승인 단계 복구와 다음 탐색 재생성 동작을 유지한다.

## 최적화 26: 로컬 메모리 정렬 병합

128개 키의 초기 bitonic 정렬을 workgroup 내부에서 묶고, 큰 정렬 단계에서도 stride 64 이하의 마지막 병합을 로컬 메모리로 묶었다. 큰 stride의 전역 교환은 유지했다. 정렬 기준은 기존과 같은 (공간 키, 입자 인덱스) 순서이며, 힘 합산 순서를 바꾸지 않았다. 128개 미만의 패딩은 기존 경로를 쓴다. 추가 전역 버퍼 없이 workgroup당 로컬 키 공간 2 KiB를 사용한다.

`GpuSpheres::set_sort_optimizations(skip_unchanged, local_merge)`로 두 최적화를 독립 비교할 수 있다. 기본은 둘 다 true이며 clone에서도 보존한다. false,false는 24의 정렬 제출/전역 정렬 경로다. `set_spatial_reuse(false)`는 기존의 강제 재정렬/이진 탐색 기준 경로를 유지한다.

## 동일 전체 총량 측정

에디터 종료 후 보존한 24 실행 파일과 개선판을 순서대로 측정했다. RTX 4060 Ti 16 GB, 1,591,550개, 반지름 1 mm, 밀도 1,500 kg/m³, 약 10 kg, q=1, dt=20 ns. 동일 접촉계수와 가동 상자를 사용했다. 각 3회, 매회 단일 단계 6개 및 64단계 배치 5개.

| 측정값 | 24 기준판 | 26 개선판 |
|---|---:|---:|
| warm 단일 단계 배속 중앙값 | 1.41916e-7 | 1.48725e-7 |
| 64단계 배속 중앙값 | 1.37670e-7 | 1.59623e-7 |
| warm 정렬 GPU 시간 중앙값 | 7.125 ms | 0.788 ms |

단일 단계 배속 **4.80%**, 64단계 배속 **15.95%** 개선. 정렬 GPU 시간 약 **88.95% 감소**. 24 이전 결과와 서로 다른 측정 구간을 섞어 속도 향상을 계산하지 않았다. 접촉 수는 4,733,669쌍으로 유지됐으며 33개 모든 대응 구간의 질량·겹침·토크·벽 일·혼합 지표 차이는 0이었다.

129개와 32,769개 장면도 기존/25/26 경로를 순서를 바꾸며 3회 측정했다. 26 대 기존 속도는 재사용 조건에서 각각 약 4.16배/2.04배, 강제 재정렬 조건에서 3.78배/1.47배였다. 32,769개 재사용 조건에서 26은 25 단독보다 약 1.2% 느렸다. 따라서 두 최적화의 효과가 모든 장면에서 단순히 더해진다고 보지 않는다. 작은 시험에서 얻은 배율을 전체 10 kg 성능으로 사용하지 않는다.

프로파일링 양쪽 활성화. 계산+통계 집계는 포함하고 초기화·최종 전체 스냅샷 감사·렌더링은 제외했다. 매회 물리시간은 326단계=6.52 µs로, 장기 혼합/전체 공정 통과 시험이 아니다. 단일 단계 warm 비교에서는 첫 cold 단계를 제외했다. GPU 전역 버퍼 예약량은 24와 동일하다.

## 검증

- Release 빌드 및 코어 **45/45 통과**.
- UnrealEditor Win64 Development 빌드 성공, Powder.DEM **16/16 통과**.
- 1/127/128/129/255/256/257/1,025/32,769개에서 기존·25·26의 위치/속도/각속도와 접촉 집합 정확 일치.
- 역순 초기 인덱스, 음수 셀, 패딩 경계, 다중 workgroup, 강제 재생성, 접촉 및 셀 이동 검증.
- 다중 workgroup에서 1/2단계 승인 후 오류 발생 시 상태 복구 및 재시도 일치. 기존 마찰·가동벽·clone·입자 교체·GPU 관측·worker 검증 포함.
- 전체 총량의 33개 대응 구간 수치 비교 통과. 0.1배속 인수는 실패로 유지.

## 재현

1. CMake Release 전체 빌드 후 CTest 실행.
2. `gpu_sort_tests.exe <CSV 경로>`로 경로별 소규모 교대 측정.
3. `Saved/Optimization25_26_baseline/reference24.exe <새 기준 결과 폴더>` 및 현재 `Intermediate/PowderCore/Release/powder_gpu24.exe <새 개선 결과 폴더>` 실행. 실행 중 다른 GPU 작업을 종료한다.
4. 결과 하위 디렉터리를 baseline24/final26으로 두고 `Scripts/compare_optimization25_26.py <결과 상위 폴더>` 실행한다. 같은 위치에 sort_benchmark.csv 필요.
5. Unreal 테스트는 별도 RHI 활성화 상태에서 Powder.DEM. 실행.

실측: Docs/DEM/optimization25_26/{baseline24,final26,sort_benchmark.csv,comparison.json,validation.json,evidence}.
보존 실행 파일은 Saved 생성 산출물로 Git에 넣지 않는다. 소스/실행 파일 SHA256은 validation.json에 기록했다. 커밋/푸시는 수행하지 않았다.

## 남은 병목

전체 총량 개선판의 64단계 배속은 약 1.60e-7로 0.1 목표까지 약 63만 배 차이가 있다. 접촉력 계산과 사후 안전검사, 20 ns 시간 간격이 남아 있다. 추가 정렬 최적화만으로 목표 달성을 예상하지 않는다. 다음 작업은 두 계산의 중복 탐색 감소를 검증하거나, 이미 기록한 시간 간격·강성·대표입자 모델의 허용오차 검증을 진행해야 한다. 안전검사를 없애거나 dt/q를 임의 변경한 결과를 같은 정확도 성능으로 취급하지 않는다.
