# 추가 최적화 07 — 커널 인수 캐시·이웃 목록 메모리 배치

## 선정 근거

작업 06의 기존 경로 첫 실행에서 `advance_wall_s=42.8763`, `submit_wall_s=29.5775`, `guard_wait_wall_s=13.2558`이었다. 제출 시간은 API 호출/드라이버 대기를 포함하므로 순수 CPU 시간 또는 GPU 커널 시간으로 해석하지 않는다. 매 접촉 반복에서 수십 개의 동일 인수를 재설정하는 코드와, 인접 스레드의 후보 ID 읽기가 capacity 간격으로 떨어지는 저장 배치를 개선 대상으로 선택했다.

## 구현

`-GrainKernelOptimize`로 두 변경을 함께 활성화한다.

1. 커널별 인수의 바이트 값을 기억하고 값이 바뀐 경우에만 `clSetKernelArg`를 호출한다. 위치 버퍼 교대, 회전각, 게이트, 속도 등 동적 인수는 기존 호출 위치에서 비교하며 변경 시 전달한다. Reset에서 실제 커널 인수는 유지되므로 캐시도 유효하다. 임시 버퍼를 생성하는 경계 진단은 핸들 주소 재사용에 대비해 매 호출 인수 캐시를 비운다.
2. 후보 ID의 저장 주소를 `입자*capacity+후보순번`에서 `후보순번*입자수+입자`로 전치한다. 같은 순번을 읽는 인접 GPU 스레드가 연속 주소에 접근할 수 있다. 목록 작성·접촉 계산·모든 쌍 감사·CPU 진단 읽기를 함께 수정했다. 각 입자의 후보 순서와 접촉 누적 순서는 유지한다.

후보 개수/용량/overflow fallback, skin 재사용 판정, 접촉식, 경계 계산, 시간 간격, 반복 수, 입자 수와 물성을 변경하지 않는다. GPU 커널 개수·실행 순서도 유지한다. 버퍼 크기는 동일하다. 고속 수학 옵션이나 물리 근사는 추가하지 않는다.

`timing.json`의 `kernel_optimize_enabled`, `argument_calls`, `argument_cache_hits`로 적용 여부와 실제 인수 API 호출/생략 수를 확인한다. 계측 카운터는 Reset에서 초기화되지만 유효한 인수 캐시는 유지된다.

## 재현과 검증

에디터 종료 후:

```powershell
python -B Scripts/run_additional_optimization07.py --run
python -B Scripts/run_additional_optimization07.py --run --modes kernel --seconds 30 --repeats 1 --label extended30
```

양쪽 이웃 안전 재사용 ON, 경계 후보 축소/비동기 전송 OFF, GPU 이벤트 계측 OFF. 12초 × 각 2회, 두 번째는 역순. 두 변경의 결합 효과를 비교하며 개별 기여도는 분리 측정하지 않는다.

소규모 시험은 독립 CPU 기준, 매 반복 모든 쌍 감사, 접촉 생성, overflow fallback, 재사용/재구축/Reset, 회전/게이트/속도 변경과 홀수 반복 수의 위치 버퍼 교대를 확인한다. 대규모 실행은 초기 SHA/수량/그룹/질량 및 마지막 기록의 겹침/벽·날개 침투를 검사한다. 모든 중간 시점이나 실제 분체 정확도 인증은 아니다.

## 12초 비교 결과 (2026-10-27)

RTX 4060 Ti, 5만 입자, 각 경로 2회 중앙값:

| 경로 | 배속 중앙값 |
|---|---:|
| 이웃 안전 재사용만 | 0.280364 |
| 인수 캐시·전치 목록 추가 | 0.333302 |

처리속도 약 **1.189배**, 소요시간 **15.88% 감소**. 기존 경로 두 측정은 0.28922/0.27150으로 편차가 있으므로 모든 조건에서 이 개선률을 보장하지 않는다. 최적화 경로는 0.33338/0.33322였다.

첫 실행의 인수 설정 API 호출은 기존 28,888,200회, 최적화 2,627,287회였다. 최적화에서는 26,267,213회를 캐시로 생략했다(약 90.9%). GPU dispatch 횟수 감소를 의미하지 않는다. 제출/guard 대기 시간이 함께 감소했지만 각 변경의 개별 기여는 이 비교만으로 구분하지 않는다.

네 실행 모두 초기 불변량과 최종 기록의 기하 검사를 통과했다. 기본값은 작업 08의 조합 검증 전까지 OFF이며 `-GrainKernelOptimize`로 선택할 수 있다. [원본 측정](comparison/measurement.json).
