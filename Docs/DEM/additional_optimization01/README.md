## 재현 절차 (프로젝트 루트)
먼저 에디터 변경을 저장한 경우 기준 자산 해시가 바뀌었는지 검사한다. 기준 파일을 새 결과로 덮어쓰지 않는다.

```powershell
python Scripts/run_additional_optimization_baseline.py
python Scripts/verify_additional_optimization01.py
```

위 명령은 새 성능 시험을 실행하지 않는다. verify는 저장소에 포함된 과거 기록으로 검사 로직을 확인한다. check.json과 verification.json에 이번 검사 결과가 있다.
새 기준 측정은 다른 Unreal 실행을 종료한 상태에서 아래 명령을 수행한다. 기존 프로세스를 도구가 임의 종료하지 않는다.

```powershell
python Scripts/run_additional_optimization_baseline.py --run --seconds 12 --repeats 3
python Scripts/run_additional_optimization_baseline.py --run --seconds 30 --repeats 3
```

후속 코드 변경 후보는 Editor Development 빌드를 먼저 완료하고 `--candidate`를 추가한다. 코드/바이너리 변경은 기록되지만 고정된 자산/설정 변경은 계속 거부한다. 후보별 설정 옵션은 후속 작업에서 명시적으로 추가하며 물리 조건을 바꾸지 않는다. 다른 엔진 경로는 --engine으로 지정한다.
출력은 Saved/AdditionalOpt_<UTC시각>/run_N에 저장하며 기존 결과를 덮어쓰지 않는다. 초기화/로딩은 운전 배속에서 제외하되 실행 로그를 보존한다. 서로 다른 실행은 동시에 수행하지 않는다.

## 판정 규칙
1. 초기 위치/그룹은 바이트 일치, 개수 50,000, 그룹 유지, 모든 상태/통계 유한값, 질량 오차 1e-6kg 이내, 시간이 단조 증가해야 한다.
2. 충돌 검사에서는 기존 잠정 기준(겹침/반지름 0.1 이하, 벽/회전부 침범 0.1mm 이하)을 사용하되 중간 표본을 추가한다. 이번 runner는 1번만 자동 판정하며 충돌 검증까지 통과한 것으로 취급하지 않는다.
3. 이웃 목록은 소규모 모든 쌍 기준 및 접촉 보정 이동을 포함한 시험에서 누락 0. 형상 최적화는 전체 형상 검사와 비교한다. 후보 용량 초과를 숨기지 않는다.
4. 반복 측정의 평균/범위와 중간 표본 시간대를 함께 비교한다. 최종 스냅샷 시간이 다르면 개별 궤적을 직접 등치하지 않는다. 속도 목표는 현재 조건에서 최소 0.1배속 유지 및 기존 처리량 개선이다.
5. 통계적 흐름 지표의 허용 오차는 반복 기준 실행에서 변동성을 먼저 확인한 뒤 작업 02/08에서 확정한다. 속도에 맞춰 사후 완화하지 않는다.

## 한계
이 기준은 비최종 시험 혼합기와 대표 입자 5만 개에 한정된다. 실제 분말/공정 전체의 물리 정확도를 보장하지 않는다. 실행 중인 에디터의 저장하지 않은 상태는 포함하지 않는다. 기록된 바이너리와 소스의 해시는 비교 기준이며 다른 PC에서는 다시 빌드하고 후보 환경을 명시해야 한다.
