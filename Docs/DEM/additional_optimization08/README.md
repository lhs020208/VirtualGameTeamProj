# 추가 최적화 08 — 현재 입자 상태 통합 검증

## 범위

사용자 지시에 따라 현재 저장된 L_MX301_Test의 생성기 초기 상태만 사용한다. 5만 대표 입자, 반지름 약 6.3647mm, 질량 약 64.8kg, dt=0.000375s, 16회 접촉 반복, 배치32, 첫1초 정착 후30RPM, 닫힌 테스트 혼합기. 초기 좌표/그룹 SHA와 보호 자산 해시를 확인한다. 다른 입도·수량·물성·기계 또는 합성 시험 장면은 이번에 실행하지 않는다.

## 비교와 기준

이웃 안전 재사용+인수 캐시/전치 목록을 바탕으로, 비동기 표시와 경계 후보 축소의 4개 조합을 12초씩 각2회 비교한다. 두 번째는 역순이다. 요청 배속2로 처리 여유를 측정하며 물리 dt를 늘리지 않는다.

긴 실행은 같은 초기 상태로 60초를 진행한다. 약2초 간격의 위치와 같은 시점의 회전각을 저장해 수량/그룹/유한값, 입자 최대 겹침/반지름≤0.1, 벽·날개 침투≤0.0001m를 검사한다. 이 간격 사이의 모든 시간 단계를 전수 기하 검사한 것은 아니다. 매 물리 배치의 기존 GPU 오류 검사도 유지한다.

속도는 전체 평균과 trace에서 구한 실제 벽시계 5초 이상 구간 처리속도로 구분한다. 샘플 구간 최소는 장래의 하한 보장이 아니다. OS/GPU 부하, 온도, 장시간 상태 변화에 따라 달라질 수 있다. 현재 근사 분체 모델의 수치 검사이며 실제 분말 물성 정확도 인증은 아니다.

## 개발 내용 점검

- 후보 용량 초과 시 전체 격자로 fallback하며 다음 반복 재구축을 강제하는지 확인.
- 예측·접촉 보정 뒤 매 반복 skin 유효성 검사와 위치 버퍼 교대 확인.
- 전치 목록의 작성/읽기/감사/진단 인덱스와 후보 처리 순서 확인.
- 커널 인수 캐시가 각도·버퍼·게이트 변경을 전달하고 임시 핸들 재사용 시 초기화되는지 확인.
- 비동기 읽기의 완료 전 버퍼 수명, Reset/종료 대기, 동일 시점 메타데이터 게시 확인.
- 시간 간격/접촉식/입자수 변경이나 렌더링 위치의 물리 피드백은 추가되지 않았음.

실행 예:

```powershell
python -B Scripts/run_additional_optimization08.py --run
python -B Scripts/run_additional_optimization08.py --run --modes default --seconds 60 --repeats 2 --label default60
```

원시 중간 위치는 Saved/AdditionalOpt08_* 아래 보존하고, 문서에는 검증 요약과 마지막 위치를 보관한다.

## 기본값 결정 및 수정

현재 생성기 기반 MX301 설정(50,000개, 반지름 약6.3647mm, dt0.000375, 반복16, 마찰0.4)에 한해 **이웃 안전 재사용 + 커널 인수 캐시/전치 목록을 자동 활성화**한다. 다른 입자 설정에는 이번 검증 결과를 확장해 자동 적용하지 않는다. 비동기 표시와 경계 후보 축소는 기본 OFF다. 명시적 기존 옵션은 계속 사용할 수 있고, `-GrainLegacy`는 이 자동 활성화를 끈다.

저장된 레벨의 목표 배속 제한(0.18)은 바꾸지 않았다. 최대 처리능력 시험은 별도 벤치마크가 목표2를 요청하는 방식이며, 실제 dt/반복 수를 변경하지 않는다. 벤치마크 결과가 평소 화면의 목표 배속 제한을 자동으로 올리는 것은 아니다.

발견한 제어 문제: 처리능력보다 높은 배속 요청이 계속되면 미처 처리하지 못한 시간(Debt)이 무한히 쌓여, 나중에 목표 배속을 낮춰도 과거 요청을 따라잡느라 빠르게 계산할 수 있었다. 이를 최대2배치 분량으로 제한하고 Pause 시 비운다. 실제로 실행하는 물리 단계의 dt를 늘리거나 상태를 건너뛰는 처리는 하지 않는다. 목표 wall-time을 무조건 따라잡는 대신 가능한 만큼 계산한다.

12초 비교 중앙값:

| 조합 | 초당 시뮬레이션 시간 |
|---|---:|
| 재사용+작업07 | 0.333399s |
| 위 조합+비동기 표시 | 0.334117s |
| 위 조합+경계 후보 축소 | 0.327494s |
| 모두 활성화 | 0.328588s |

비동기 표시의 추가 이득이 명확하지 않아 복잡성을 더하는 기본값으로 채택하지 않았다. 경계 후보 축소도 이 장면에서 더 느려 채택하지 않았다. 비교 결과는 [comparison/measurement.json](comparison/measurement.json)에 기록했다. 기본값/누적시간 제어 수정을 포함한 최종 빌드는 별도의60초 시험으로 검증한다.

## 최종 기본값 빌드의 60초 검증

현재 동일 초기 상태로 60초씩2회 실행: 평균 **0.303313 / 0.304836 s/s**. 시작5초를 제외하고 trace에서 구한 벽시계5초 이상 구간(각214개)의 최저 관측값은 **0.284111 / 0.287018 s/s**였다. 시작/맵 로딩 시간은 이 처리속도에 포함하지 않는다.

- 초기 SHA, 5만 입자 및 고정 그룹 ID, 질량, 유한값 검사 통과.
- 중간 위치58개 및 마지막 기록2개 검사 통과. 각 실행의 마지막 위치 시각은 약59.9284s / 59.9078s로, 종료 순간과 정확히 같지는 않다.
- 모든 검사 위치의 최대 겹침/반지름 **0.08567217**, 벽 침투 **5.842e-08m**, 날개 침투 **4.991e-08m**.
- 두 실행 모두 GPU 안전 오류/후보 용량 초과 fallback 0. 정상 경로가 실제 기본 활성화됐음을 timing.json으로 확인했다.
- 시험 중 모든 시간 단계의 기하 전수 검사나 무제한 장기 안정성/실제 물성 검증을 의미하지 않는다.

**운용 목표로는 초당 시뮬레이션0.2초를 권장**한다. 최저 관측 구간0.284보다 약30% 여유를 둔 제안이며, 별도로0.2배속에 제한한 장기 시험 또는 모든 OS/GPU 부하에서의 하한 보장은 아니다. 저장된 목표0.18은 그대로이므로 평소 화면은 이 제한을 따른다. 속도를 높이려면 Target Rate를0.2로 조정할 수 있다. 물리 dt를 늘리는 설정이 아니다.

현재 시험으로 무조건 안전하게 보장할 수 있는 s/s 값은 없다. 보고 가능한 것은 **현재 상태에서60초씩2회, 평균 약0.304s/s와 관측 최저 약0.284s/s, 검사 기준 통과**다.
