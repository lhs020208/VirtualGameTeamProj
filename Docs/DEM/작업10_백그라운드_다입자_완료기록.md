# 작업 10 — 백그라운드 계산과 다입자 표시

완료일: 2026-10-21. PowderCore 0.10.0. 브랜치: PowderSimulation. 커밋·푸시는 하지 않았다.

## 구현

- `worker.hpp/.cpp`: 전용 계산 스레드 하나가 Session과 물리 상태·접촉 이력을 독점한다. 계산 자체의 병렬 최적화는 하지 않았다.
- 화면에는 `shared_ptr<const Snapshot>`을 전달한다. 스냅샷에는 실행 번호, 완료 단계 수·물리 시간, 입자 상태, 접촉·질량 보고, 이력 수, 연산 소요 시간·오류가 들어간다. 소비자는 내용을 수정하지 않는다.
- 명령과 스냅샷 포인터만 짧은 mutex 구간에서 교환한다. 물리 계산 중 mutex를 잡지 않으며 계산 스레드에서 Unreal 객체를 읽거나 수정하지 않는다.
- 정상 실행은 8개 물리 단계마다 최신 스냅샷을 게시한다. 일시정지·한 단계 진행·초기화·오류 시에는 상태를 즉시 게시한다. 최신 표시 상태만 유지하므로 화면용 중간 스냅샷은 건너뛸 수 있지만 물리 단계는 생략하지 않는다.
- R은 실행 번호를 증가시키고 이전 화면 상태를 비운다. 새 초기 상태 검증은 계산 스레드에서 수행한다. 뒤늦게 완료된 이전 실행의 결과는 게시하지 않는다.
- 일시정지·종료는 현재 계산 중인 한 단계가 끝나는 경계에서 처리한다. EndPlay/소멸 시 중단을 알리고 스레드를 join한다. 분리된 스레드나 Unreal 객체를 참조하는 콜백을 남기지 않는다.
- `APowderDEMTest`는 300개 구를 하나의 InstancedStaticMeshComponent로 표시한다. Chaos 시뮬레이션·중력·충돌은 비활성이다. 인스턴스 추가·갱신과 현재 레벨 형상 읽기는 게임 스레드에서만 한다.
- 프레임당 계산량 설정은 제거했다. 렌더 프레임은 스냅샷을 소비할 뿐 계산 스레드의 진행 횟수를 결정하지 않는다.

## 기본 시험 조건

| 항목 | 값 |
|---|---|
| 입자 수 | 300, 편집 범위 1~300 |
| 지름 / 밀도 | 0.04m / 2500kg/m³ |
| 입자 1개 질량 / 전체 질량 | 약 0.0837758kg / 25.1327kg |
| 초기 배치 | 5×5×12, 중심 간격 지름의 1.25배=0.05m |
| 초기 층 위치 | 중심 XY ±0.10m, 최하단 z=4.50m, 최상단 z=5.05m |
| 고정 dt | 2e-7초 |
| 선형 접촉 | kn=4e6N/m, cn=40Ns/m, kt=1e6N/m, ct=10Ns/m, 마찰계수 0.3 |

지름 4cm의 가상 검증 입자이며 실제 미세 분말 물성을 보정한 결과가 아니다. 작업 09의 20cm 단일 구를 300개 그대로 배치하면 공급부에 맞지 않으므로 크기·밀도·감쇠와 dt를 함께 바꿨다. 입자 1개 모드도 유지한다.

기존 Space 시작/일시정지, N 한 단계, R 초기화, F 입자 초점, Home/T 시점 이동과 카메라 이동을 유지한다. 명령 반영은 비동기다. 실행 중 N을 누르면 이미 계산 중인 한 단계는 끝내고 요청한 한 단계를 더 수행한 뒤 멈춘다. 정지 상태에서 N은 정확히 한 단계다. 시작/일시정지 요청은 아직 실행하지 않은 N 대기 요청을 취소한다.

HUD는 초기화 중/실행/정지/오류, 입자 수, 실행 번호, 단계 수, 물리 시간·실제 시간·연산 시간을 구분한다. 기본 한 단계 0.000000200초가 보이도록 물리 시간은 소수점 9자리로 표시한다.

## 검증 결과

- Release 빌드와 전체 CTest 9개 통과(약 42.81초). 기존 session_controls 포함, 새 background_worker 추가.
- Python CLI·운동·평면 회귀 검사 3개 통과.
- UnrealEditor Development 빌드 성공.
- `Powder.DEM.BackgroundBridge` 엔진 자동 검사 성공.

### 코어 백그라운드 검사

실제 L_Main의 53개 상자와 300개 입자로 100개의 고정 단계를 백그라운드와 순차 기준에서 각각 계산했다. 입자 ID, 위치 전 성분, 수직 속도가 정확히 일치했고 입자 수 300·총질량 약 25.1327kg을 확인했다. 물리 시간은 **20마이크로초**로, 전체 낙하·퇴적 실험을 완료한 것은 아니다.

한 번의 측정에서 100단계 연산은 약 0.731초, 계산 중 스냅샷 1000회 읽기는 약 0.0000255초였다. 별도 합성 접촉 시험에서 한 단계 진행과 이력 생성, 일시정지 응답 후 단계 수 고정, 보관 중인 스냅샷 불변성을 확인했다. 실행 중 초기화 20회에서 실행 번호·단계 0·이력 0을 확인했고, 초기화/실행 상태의 Worker 생성·종료 10회도 통과했다. 오류 입력은 새 실행을 정지시킨다.

### Unreal 검사

엔진 액터의 비동기 초기화, N, Space에 해당하는 시작/정지, R, 실행 번호 증가, 접촉 이력 삭제, 300개 인스턴스 수, Chaos 비활성을 확인했다. 새 스냅샷 93개를 받아 인스턴스를 갱신하는 검사에서 최대 Tick 실행 시간은 약 **4.50ms**, 기준 100ms 미만이었다. 전체 렌더러 FPS 측정이나 모든 하드웨어에 대한 지연 보장은 아니다.

ISM 표시 행렬은 렌더 정밀도를 사용하므로 표시 좌표는 1e-4cm 이내로 검사한다. 코어는 double을 유지하며 순차 계산 비교에서는 좌표가 정확히 일치했다. 기존 단일 메시의 double 변환 검사와 ISM 렌더 정밀도를 혼동하지 않는다.

실제 에디터에서 300개 표시, 백그라운드 실행 중 F 카메라 초점, 실행 중 R로 Run 1→2 및 Steps 0 복원, N으로 Steps 1을 확인했다. 계산 실행 중 Play를 종료해 스레드를 정리하는 과정에서도 충돌이 없었다.

## 수명·성능 제한

R은 이전 계산을 강제로 끊지 않는다. 진행 중인 단계가 끝날 때까지 기존 계산 스레드에서 정리하며, UI는 그 결과를 받아들이지 않는다. 종료 시 join은 진행 중인 한 단계 또는 초기 검증이 끝날 때까지 기다릴 수 있다. 모든 임의 형상·매개변수에서 종료 시간이 일정하다는 보장은 없다.

이 작업은 **화면 응답성을 계산 속도에서 분리**한 것이다. 계산 코어를 빠르게 만든 것은 아니다. 보수적인 작은 dt와 현재의 공간/상자 검사 비용 때문에 눈에 띄는 낙하까지 오래 걸릴 수 있다. 실제 시간을 따라잡기 위한 dt 확대·단계 생략·녹화 재생은 하지 않는다.

형상은 R 시점의 정적 스냅샷이다. 임의 이동 벽·대규모 벽 가속·물리 계산 병렬화·입자 추적/통과율 분류·실제 분말 보정은 후속 범위다. 이번 검증으로 300개 입자의 장시간 관 통과나 막힘을 검증했다고 주장하지 않는다.

## 재실행

기존 CMake 빌드 후 CTest를 실행한다. 새 검사만 실행하려면:

```powershell
ctest --test-dir Intermediate/PowderCore -C Release -R background_worker --output-on-failure
```

엔진 빌드 후:

```powershell
& 'C:/Program Files/Epic Games/UE_5.8/Engine/Binaries/Win64/UnrealEditor-Cmd.exe' "$PWD/VirtualGameTeamProj.uproject" -unattended -nullrhi -nosound '-ExecCmds=Automation RunTests Powder.DEM.BackgroundBridge' '-TestExit=Automation Test Queue Empty' "-ReportExportPath=$PWD/Saved/DEM_task10_automation"
```
