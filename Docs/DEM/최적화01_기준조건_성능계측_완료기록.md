# 최적화 01 — 목표 조건·기준 시험·성능 계측 완료 기록

작성일: 2026-10-22
브랜치: `PowderSimulationOptimization`
상태: 최적화 01 완료, 최종 성능 목표 미달/미지원

## 목적과 범위

대량 분말 0.1배속 최적화에 앞서 비교할 조건과 측정 경로를 마련했다. 현재 물리식·적분 순서·접촉 처리·안정성 검사·입자 수 상한은 유지했다. 이번 작업 완료는 대량 계산이나 0.1배속 달성을 뜻하지 않는다.

가상 원료 A/B 각 5kg, 반지름 1mm(직경 2mm), 재질 밀도 1500kg/m³, 단일 구형을 기본 목표로 정했다. 입자 수를 올림하면 원료별 795,775개, 총 1,591,550개와 약 10.0000035756kg이다. 벌크 밀도가 아닌 재질 밀도이며 실제 원료 보정값은 아니다. 0.5/1/2mm 반지름 민감도와 1천/1만/10만 계산 입자 단계도 목표 계약에 기록했다.

최종 인수 조건은 최소 60초 물리 시간, 1초 물리 시간 단위의 완전한 측정 창 모두에서 0.1배속 이상, 반복 3회다. 필수 측정·전달·출력·Unreal 표시 비용을 포함한다. 초기화/빌드는 분리 보고한다. 이번 짧은 소규모 창은 이 최종 조건을 판정하지 않는다.

## 구현

- `powder/profile.hpp`: 선택적으로 켜는 9개 배타적 단계 타이머와 시도/수락 단계, 실제 전수 거리 검사, 후처리 쌍 검사, 재료 쌍 검증 횟수.
- 기존 `ClumpWorld::step(dt)`는 계측을 끈 경로를 유지한다. `step_profiled(dt, profile)`로 계측한다. 실패 시 시간/시도 횟수는 기록하고 물리 상태는 기존 원자적 수락 정책을 유지한다.
- 단계: 검증·준비 / 입자 탐색·힘 / 기본형상 벽 / 정적 메시 조회·힘 / 가동 메시 조회·힘 / 시간 간격 제한 / 적분 / 계산 후 안전 검사 / 상태 반영.
- 입자 탐색과 힘 계산 내부, 메시 조회와 힘 계산 내부는 각각 묶었다. 접촉 하나마다 타이머를 읽는 오버헤드를 피하며, 세부 비용을 별도로 측정했다고 주장하지 않는다.
- `powder_opt01`: 고정 입력 시험 실행기. 물리 지표, 초기/최종 상태, 배출 사건, 단계별 시간, 고정 물리 구간의 속도를 CSV로 기록한다.
- `run_optimization01_validation.py`: 빌드·기존/신규 회귀 검사·계측 켜기/끄기 반복·물리 결과 동일성·소스/실행 파일 해시·하드웨어·프로세스 최고 작업집합 메모리 보고.
- Unreal `Clump > Profiling > Profile Performance`: 기본 꺼짐. 켜고 Reset하면 계산 단계 및 `Sync()` CPU 시간을 수집한다. 정지 후 O로 내보내면 `performance.csv`를 추가 저장한다.
- Unreal 화면 전달 시간은 혼합 지표 산출·인스턴스 준비·변환 적용을 포함하는 CPU 시간이다. GPU 그리기/표시 지연을 측정한 값이 아니다. NullRHI 자동 검증을 최종 화면 포함 성능으로 취급하지 않는다.

입력 계약은 `Physics/PowderCore/fixtures/optimization01_contract.json`, 장면 목록은 `optimization01.bench`다. 장면 생성 규칙과 정확한 초기 좌표는 버전 고정 소스 및 `*_initial.csv`로 보존된다. 난수는 사용하지 않는다.

## 기준 장면과 제한

| 장면 | 크기·개수 | 용도 |
|---|---|---|
| freefall_32 | 반지름 20mm, 32개 | 기존 크기의 무접촉 적분 기준 |
| packing_32/128/256 | 반지름 20mm | 접촉이 있는 초기 조밀 격자, 규모별 비용 |
| discharge_32 | 반지름 20mm, 32개 | 초기 하향 속도에서 가상 z=0 수집면 통과와 원료별 질량 수지 |
| mixing_32 | 반지름 20mm, 32개, 30RPM | 패들 근처에 배치한 접촉 도전 조건; 겹침 기준 부적합 진단 |
| mixing_gentle_32 | 동일 배치, 5RPM | 기준을 통과하는 저속 접촉·토크·혼합 지표 시험 |
| mm_packing_32/128/256 | 반지름 1mm | 목표 크기의 짧은 접촉 비용 탐색 |
| capacity_1000/10000/100000, target_10kg | 요청 개수만 기록 | 현재 지원 불가를 명시, 거대한 배열을 할당하지 않음 |

20mm 시험은 기존 물성(k_n=10000N/m, c_n=8N·s/m 등)과 2e-6초 간격을 사용한다. mm 시험은 새 가상 입력으로 k_n=10000N/m, c_n=0.01N·s/m, k_t=2500N/m, c_t=0.0025N·s/m, μ=0.4, 2e-8초 간격을 사용한다. 서로 다른 크기·물성·시간 간격의 속도를 단순한 구현 가속비로 비교하지 않는다. 기존 프로젝트 물성이나 시간 간격을 변경한 것은 아니다.

조밀 격자는 평형 상태를 만든 완성된 분말층이 아니다. 배출은 초기 속도를 가진 한 층의 가상 수집 시험이며 호퍼 막힘/중력 배출률 검증이 아니다. 패들 시험은 짧은 접촉 구간으로 완전 혼합 과정이나 실제 제품 품질을 검증하지 않는다. UI의 기존 L_MixingTest와 배치·메시 구성도 다르므로 속도를 직접 같은 장면의 개선 전후 값으로 비교하지 않는다.

첫 30RPM 근접 배치 시험에서 최대 겹침/반지름이 약 0.0783으로 사전 기준 0.05를 넘었다. 이 입력과 실패 결과를 유지하고 `reference_rejected`로 표시했다. 기준을 완화하지 않고 별도 5RPM 입력을 추가했다. 이는 모든 30RPM 장비나 기존 UI 장면이 부적합하다는 뜻이 아니다. 이 30RPM 결과는 향후 정확도 기준 정답으로 사용하지 않는다.

## 정확도 기준과 검증 의미

- 계측 켜기/끄기와 반복 실행의 물리 CSV·초기/최종 상태·배출 사건은 같은 빌드에서 정확히 같아야 한다.
- 원료별 질량 잔차는 1e-18kg + 초기 원료 질량 × 1e-12 이하.
- 자유낙하는 현재 적분기의 독립 이산 해석식과 위치 오차 1e-11m 미만으로 비교한다. 물리 시간 간격 수렴 등 기존 19개 회귀 검증도 유지한다.
- 기준 적합 장면은 최대 겹침/반지름 <0.05, 조밀 장면은 입자·벽 접촉 발생, 혼합 장면은 벽 접촉 및 유효한 지표, 배출 장면은 32개 전량 수집을 요구한다.
- 향후 모델 간략화 기준도 계약에 고정했다: 누적 배출/평균 배출률·체류 평균/중앙값/p95 5%, 혼합지수 절대 0.05, 평균 토크 10%. 0 근처 절대 허용값은 계약 참조. 이 넓은 기준은 구현 오류·접촉 누락에 적용하지 않는다.
- 막힘·누출·분리의 정성 기준은 별도 도전 장면이 마련된 뒤 간략화 인수에 사용한다. 이번 소규모 장면만으로 그 현상을 검증했다고 보지 않는다.

## 재현 명령

프로젝트 루트에서 새 출력 폴더 이름으로 실행한다.

```powershell
python -B Scripts/run_optimization01_validation.py --output Saved/Optimization01_new_check
& ./Intermediate/PowderCore/Release/powder_opt01.exe Physics/PowderCore/fixtures/optimization01.bench Saved/Opt01_profiled 1
& ./Intermediate/PowderCore/Release/powder_opt01.exe Physics/PowderCore/fixtures/optimization01.bench Saved/Opt01_plain 0
```

`powder_opt01` 종료 코드: 0=시험 기대 판정 충족(지원 불가/명시된 기준 부적합 포함), 2=입력/출력 거부, 3=예상 밖 계산/검증 실패. `result.json`의 `large_scale_target_supported`는 false다. 상태 구분을 읽지 않고 종료 코드만으로 대량 성능 목표를 통과했다고 해석하지 않는다.

실행 결과 파일:
- `physics.csv`: 성공/기준 부적합/미지원 상태, 원료 질량, 접촉, 겹침, 에너지, 벽의 일·토크, 수집·체류, 혼합지표.
- `timings.csv`: 초기화·해석기 호출·관측/수집·전체 루프·출력 시간. 구간의 일부가 중첩되므로 열을 모두 합하지 않는다.
- `profile.csv`: 해석기 내부 9개 배타적 구간과 계수기.
- `windows.csv`: 입력에 지정한 단계 수 단위의 짧은 물리 창. 물리 계산만 진행하며 창 길이도 물리 시간으로 기록한다.
- `*_initial/final/events.csv`: 입자 기준 상태와 보간 배출·단계 끝 제거 시각.
- `report.json`: 반복 동일성, 소스 해시, 최소 짧은 창 배속, 중앙값 배속, 계측 오버헤드 비교, 프로세스 최고 작업집합. 메모리는 입자 배열만의 크기나 GPU 메모리가 아니다.

계측 자체의 비용은 켜기/끄기 두 실행을 비교해 공개한다. 보고된 시간에서 임의로 빼지 않는다. 성능은 시점·캐시·운영체제 부하에 따라 변할 수 있다.

## 검증 결과

- CMake Release 빌드 성공, 기존 19개+신규 2개 = 21개 CTest 묶음 × 2회 통과.
- 14개 요청 조건 중 9개 기준 적합, 1개 사전 겹침 기준 부적합, 4개 규모 미지원. 계측 on/off 각각 2회 실행.
- 물리 지표·입자 상태·수집 사건이 4개 실행 모두 바이트 단위로 일치.
- Unreal Development Editor 빌드 성공, 기존 기능 포함 자동 검증 13/13 통과.
- 실패 입력/기존 출력 덮어쓰기 거부, 실패 단계 상태 보존, 실제 301몸체 상한 거부도 검증.

측정 장비: Intel Core i7-14700KF, RAM 32GB, RTX 4060 Ti(보고된 VRAM 16380MiB). GPU 가속은 사용하지 않았다. 다음 배속은 계측을 끈 standalone 루프의 두 반복 중앙값이며, UI 실행 배속이 아니다.

계측/비계측 해석기 호출 시간 비율은 0.990~1.048. 1 미만 값은 실행 변동이며 계측으로 빨라졌다는 의미가 아니다. 기준 실행 프로세스의 최고 작업집합은 약 7.05~7.81MiB다. 작은 데이터만 실행했으므로 이를 대량 입자 메모리 추정으로 외삽하지 않는다.

Unreal CPU 전달 검증 원문:

```text
OPT01_UNREAL_CPU: 500 fixed steps, physics 0.0572013 s, display_sync 0.00859332457 s, paired_loop 0.132284898 s; display_sync excludes GPU drawing
```

이 검증은 계측 on/off 액터를 각각 한 단계씩 진행하고 매번 Sync하는 비교다. 실제 프레임당 여러 물리 단계를 처리하는 화면 실행이나 GPU 렌더 성능과 다르다.

## 병목과 다음 작업

256개 mm 시험에서 검증·준비가 약 56%, 입자 탐색·힘 약 20%, 계산 후 안전 검사 약 12%였다. 실제 계수기는 다음과 같다.

```json
{
  "attempted_steps": 500,
  "accepted_steps": 500,
  "pair_distance_checks": 16320000,
  "post_pair_checks": 16320000,
  "material_pair_validations": 32768000
}
```

먼저 최적화 02의 구형 전용 경로와 불변 질량·관성·재료 캐시를 구현한다. 캐시 무효화 및 기존 안전 검사의 동등성을 유지해야 한다. 이어 최적화 03에서 입자 쌍·후처리 쌍·재료 검사와 ID 탐색의 확장 비용을 해결한다. 이번 결과만으로 단순 캐시 최적화가 159만 입자의 0.1배속을 보장한다고 볼 수 없다.

기존 작은/큰 구형 시험 간 속도 차이는 개수 외에 시간 간격·물성 차이도 포함한다. 현재 mm 간격을 최종 운영 간격으로 확정하지 않았으며 시간 간격/강성 검증은 최적화 07~08에서 별도 진행한다.
