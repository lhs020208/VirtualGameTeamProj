# 작업 14 — 실험 결과 저장과 비교

상태: 완료. 작성일: 2026-10-21. 프로젝트 `D:/GitHub/VirtualGameTeamProj`, 브랜치 `PowderSimulation`, 코어 버전 0.14.0.

## 구현

계산 스레드가 매 수락된 물리 단계에서 측정 상태를 갱신하고, 지정한 물리 시간 간격에 결과를 기록한다. 렌더 프레임이나 화면에 표시된 스냅샷만으로 결과를 추정하지 않는다. 기록은 입자 운동·접촉 계산을 변경하지 않는다.

일시정지한 실행의 단일 불변 스냅샷에서 CSV/JSON 묶음을 내보낸다. 현재 Details에서 편집 중인 값이 아니라 실행 시작 때 적용된 분말 설정·측정 기준·형상을 저장한다. 실행 중 저장 요청은 거부하며, 먼저 Space로 일시정지해야 한다. R은 실행과 측정 기록을 함께 초기화한다. 기존 실행을 보존하려면 R이나 PIE 종료 전에 저장한다.

## 저장 파일

기본 출력 폴더: `Saved/DEM/Results/<UTC시각>_<GUID>/`

| 파일 | 내용 |
|---|---|
| metadata.json | 결과 스키마·측정 정의·코드 버전·빌드 시각 문자열, 실행 세대, 단계 수, 물리 시간, dt, 시드, 계산 소요 시간, 실제 설정, 측정 임계값, 관 측정 영역, 고정 상자/평면 형상 |
| settings.dem | 해당 실행에서 사용한 가상 분말·공급 설정 원문 |
| summary.json | 누적 배출·통과 질량, 잔류 질량, 공급량·대기량, 정체 상태, 완료된 통과의 체류 시간 표본과 평균·중앙값 |
| timeseries.csv | 물리 시간별 배출량·구간 평균 배출률, 위치별 개수/질량, 공급량/대기량/향후량, 수지 오차, 저속·무배출 상태 |
| particles.csv | 실제 투입된 입자별 최종 위치·속도·질량·생성 시각·나이·위치 변경 시각·저속 지속 시간·통과 여부 |
| events.csv | 입자별 관 경계 통과 이벤트와 보간된 물리 시각, 완료 통과 여부·해당 체류 시간 |
| run.json | 고유 내보내기 ID와 UTC 저장 시각 |
| complete.json | 모든 파일 작성 후 마지막에 쓰는 완료 표식 |

반복 저장은 새 폴더를 생성하며 기존 파일을 덮어쓰지 않는다. 쓰기 실패 시 불완전한 폴더를 남기고 실패를 표시한다. 비교 도구는 완료 표식이 없거나 필수 파일이 빠진 묶음을 거부한다. 운영체제 장애나 디스크 고장까지 원자적 디렉터리 저장을 보장하지 않는다. 결과에는 체크섬/서명이 없으므로 파일 변조 검증 기능은 아니다.

코드 버전은 `0.14.0`으로 기록한다. 빌드 시각 문자열은 컴파일러의 `__DATE__ / __TIME__`이며 UTC를 의미하지 않는다. Git 커밋 해시나 소스 지문은 자동 추출하지 않으므로 `source_revision`은 null이다. 버전이 같다는 것만으로 바이너리까지 동일하다고 주장하지 않는다. 저장 결과와 소스 버전을 함께 보관하는 것이 필요하다.

## 지표의 정의

- **gross_exit_kg:** 관 아래 측정면을 아래 방향으로 통과한 질량 누계. 재진입 후 재배출하면 다시 센다. 관 내부에서 생성된 입자의 출구 통과도 포함한다.
- **net_exit_kg:** 같은 면의 아래 방향 질량에서 위 방향 질량을 뺀 순통과 질량. 단순한 수집함 잔류 질량과 같다고 가정하지 않는다.
- **unique_pass_kg:** 위쪽 입구부터 아래쪽 출구까지 유효한 통과를 완료한 입자를 ID당 한 번만 세는 질량.
- **interval_exit_kg / interval_exit_kg_s:** 직전 기록 이후 gross 질량 증가량과 이를 실제 기록 시간 차로 나눈 구간 평균 유량. 시작 시각의 0초 구간은 유량을 빈 값으로 기록한다.
- **체류 시간:** 각 유효한 완료 통과의 마지막 입구 진입부터 출구 통과까지의 시간. 같은 입자의 반복 완료 통과는 별도 표본이다. 아직 통과하지 못한 입자는 0초 표본으로 넣지 않는다. 완료 표본이 없으면 평균·중앙값은 JSON null이다.
- **체류 시간 분포:** 완료 통과별 원자료를 events.csv에 저장하고, summary.json에 정렬된 표본 배열을 제공한다. 임의의 히스토그램 구간은 강제하지 않는다. 이 분포는 완료한 입자에 조건부인 분포이며 미완료 입자의 검열을 보정한 통계가 아니다.
- **잔류 위치:** 마지막 스냅샷의 입자 중심 좌표와 Feed/Tube/Collector/Outside 분류. Outside는 삭제·손실이 아니라 현재 측정 영역 외부다. 대기·미요청 입자는 아직 위치가 없으므로 particles.csv에 넣지 않고 공급 통계에 남긴다.

events.csv의 kind: 0=입구 아래 방향, 1=출구 아래 방향, 2=출구 위 방향, 3=입구 위 방향이다. 시각은 기존 추적기의 한 단계 내 직선 경로 보간을 사용한다. 입자가 생성되었다는 이유만으로 가짜 경계 통과를 만들지 않는다.

## 정체와 공급 완료의 분리

기본 측정 기준은 Details의 **DEM / Results**에서 변경하고 R로 적용한다.

| 기준 | 기본값 | 의미 |
|---|---|---|
| ResultSampleSeconds | 0.01s | 기록 간격, 물리 시간 |
| SlowSpeedMps | 0.001m/s | 이 값 이하이면 저속 |
| LongStallSeconds | 1s | 지속 시간이 이 값 이상이면 장시간 상태 |
| MaxResultSamples | 10,000 | 정규 기록 행 수 한도, 허용 범위 2~100,000 |

입자 저속 지속 시간은 연속된 단계 끝 속도로 계산한다. 처음 저속으로 관측된 시점은 0초부터 시작하고, 기준보다 빠르면 0으로 초기화한다. 정확한 단계 내부 속도 임계값 통과 시각은 풀지 않으므로 분해능은 dt 수준이다. `moving`, `temporary_slow`, `long_slow`를 구분한다. 수집함에서 정상적으로 가라앉은 입자도 저속일 수 있으므로 이를 곧바로 관 막힘으로 판정하지 않는다.

출구 무배출은 Feed/Tube의 입자 또는 공급 대기량이 있을 때만 센다. 마지막 아래 방향 출구 통과 이후의 시간이며, 기록 간격 사이의 이벤트도 반영한다. 짧은 `temporary_no_outflow`와 임계값 이상의 `prolonged_no_outflow`, 배출 관측 `outflow_observed`, 상류 물질 없음 `no_upstream_material`을 구분한다. 추적 영역이 없으면 `tracking_disabled`다. 자유낙하 이동 시간도 무배출에 포함될 수 있으므로 장시간 무배출을 물리적 아칭의 확정 진단으로 해석하지 않는다.

공급 상태는 별도로 `scheduled / feeding / backlogged / complete / unconfigured`를 기록한다. complete는 전량이 계산 공간에 들어갔다는 뜻이며 관 통과 완료·장치 비움·실험 종료를 뜻하지 않는다. 따라서 공급 complete와 장시간 무배출이 동시에 나올 수 있다.

## 기록 간격·용량·제한

지정 간격 이상이 된 첫 물리 단계에서 실제 시각을 기록한다. dt가 기록 간격보다 크면 존재하지 않는 중간 상태를 보간해 행을 만들지 않는다. 이벤트 원자료에는 그 사이의 관 통과가 남는다. 내보낼 때 마지막 정규 기록 이후의 현재 시각을 한 행 추가하므로 끝 구간을 누락하지 않는다.

정규 기록 한도에 도달해 다음 행을 기록하려는 시점에는 계산을 일시정지하고 `LIMIT: export then reset`을 표시한다. 기존 자료와 현재 최종 상태는 저장 가능하며, 메타데이터에 `sample_limit_reached=true`를 기록한다. 최종 행 때문에 출력 행 수가 정규 한도보다 1개 많을 수 있다. 한도에 도달한 실행을 그대로 계속하지 않고 저장 후 간격/한도를 조정해 R로 다시 시작한다.

기록 배열은 새 정규 표본 때 불변 사본으로 갱신하고, 일반 화면 스냅샷끼리는 공유한다. 보관 자료가 커지면 복사·메모리 비용이 증가한다. 성능 기준 측정은 작업 15 범위다. 오류가 발생한 실행의 내보내기는 현재 거부하며, 정상 상태에서 일시정지한 기록을 대상으로 한다. 자동 종료 저장이나 실행 재개 체크포인트는 없다.

측정 임계값은 결과 metadata.json에 저장한다. 기존 K/L 분말 프리셋(settings.dem)은 결과 기록 기준까지 복원하지 않는다. 두 조건 비교 시 결과 기준을 동일하게 설정해야 한다.

## Unreal 사용법

1. Play 후 PowderDEMTest의 **DEM / Results**에서 기록 간격·저속 기준·장시간 기준을 설정하고 R로 적용한다.
2. Space로 계산한다. 원하는 **물리 시간**에 일시정지한다. N은 한 물리 단계 진행이다.
3. **O**를 눌러 결과 묶음을 저장한다. Blueprint의 ExportResults도 같은 기능이다.
4. HUD에 저장 결과가 표시되고, Details의 LastResultsDirectory에서 전체 경로를 확인할 수 있다.
5. 다른 조건을 실행해 같은 물리 시각에 저장하고 아래 비교 도구를 사용한다.

## 두 조건 비교

프로젝트 루트에서:

```powershell
python Scripts/compare_dem_results.py "Saved/DEM/Results/<A폴더>" "Saved/DEM/Results/<B폴더>" --output "Saved/DEM/comparison.json"
```

출력은 A, B 및 B−A 차이, 상태, 변경된 설정·형상·dt·시드 여부를 담는다. --output을 생략하면 터미널에 JSON을 출력한다. 지정 출력 파일이 이미 있으면 덮어쓰지 않고 실패한다.

결과 스키마·지표 정의·코드 버전·측정 영역·기록 간격·저속/장시간 기준·관측 종료 물리 시간이 같아야 한다. 관측 시각은 정확히 같은 수치여야 하며 자동 보간·시간 정규화는 하지 않는다. dt와 시드는 달라도 차이를 명시한다. 형상은 관 측정 영역이 유지되는 범위에서 달라도 비교할 수 있다. 측정이 꺼진 결과, 누락된 최종 행, 일부 JSON/CSV 불일치, 질량 수지 오차 1e-10kg 초과는 거부한다. 단위는 SI다.

- 지름 0.1m·밀도 1000kg/m³의 입자가 t=1s 진입, t=2s 배출하는 독립 경로에서 질량 약 0.5235987756kg, 체류 1s, 0~3s 구간 평균 유량 약 0.1745329252kg/s 확인.
- 역방향 출입과 반복 완료 통과에서 gross/net/unique 질량 차이를 검증했다.
- 밀도만 2000kg/m³로 바꾼 두 번째 결과는 배출 질량이 2배이고 체류 시간은 동일함을 비교 도구로 확인했다.
- 일시/장시간 무배출, 저속 재시작, 공급 완료와 무배출의 독립성, 생성 시각, 기록 한도 자동 일시정지·저장, 리셋, 마지막 비정규 행을 검사했다.
- Python 표준 JSON/CSV 파서로 실제 출력 파일을 읽어 숫자·이벤트·잔류 위치를 독립 검증했다. 기준/시각/측정 영역 불일치, 불완전 파일 묶음은 비교를 거부했다.
