# 최적화 09 — CPU 접촉·적분 병렬화 완료 기록

완료일: 2026-10-22  
브랜치: `PowderSimulationOptimization`  
범위: 프롬프트 1회 + 문제 수정. 기존 최적화 07·08 작업을 보존했다. 커밋/푸시는 수행하지 않았다.

## 결과와 적용 정책

입자 간 접촉 평가와 강체 적분을 병렬화했다. 물성, 시간 간격, 안정성/겹침 검사는 그대로다. **기본값은 CPU 1스레드**이며, 병렬 설정에서도 작업 수가 기준 미만이면 단일 경로를 사용한다. 32개 기존 혼합 장면에 스레드를 강제하는 것은 일반적인 가속 방법이 아니다.

Core 31/31, Unreal 15/15 통과. 기존 물리 CSV 31개가 변경 전 실행 파일과 byte 단위로 일치했다. 기존 10개 지원 시나리오를 1·2·4·8스레드로 각 3회 실행한 372개 CSV 비교도 동일했다. 기존의 의도된 오류/용량 제한 결과도 유지했다.

mm·kg 규모에서 0.1 물리 초/실제 초 목표는 **미달·미검증**이다. 강체 300개/pebble 1024개 제한은 유지했다. 최적화 10에서 대량 CPU 기준판과 다음 경로를 결정한다.

## 구현과 소유권

- `parallel.hpp`: 매 스텝 생성하지 않는 지연 생성 스레드 풀. N스레드는 호출 중인 계산 스레드 1개 + 보조 N-1개를 뜻한다. 허용 설정 1~32, 검증한 설정 1·2·4·8.
- 접촉 후보를 연속 인덱스 구간으로 나눈다. 각 후보의 힘·토크·새 이력은 전용 슬롯 1개에만 기록한다. 이전 이력과 입자·물성은 읽기 전용이다.
- 모든 작업이 끝나면 후보 순서대로 힘·토크를 합산하고 새 이력을 구성한다. 공유 힘 배열에 대한 동시 쓰기나 atomic floating-point 덧셈을 사용하지 않는다. 이 직렬 합산은 기존 계산 순서를 보존하기 위한 선택이며 남아 있는 병목이다.
- 강체 적분은 각 `next_[i]`의 전용 소유자가 수행한다. 프로파일 카운터는 barrier 후 호출 스레드에서 합산한다.
- 예외는 작업 구간마다 저장한 뒤 모든 작업 종료를 기다려 다시 던진다. 가장 작은 실패 인덱스의 오류를 우선 보고한다. 실패한 스텝은 입자·접촉 이력·시간·벽 일에 반영하지 않는다.
- World 복사/체크포인트는 실행 중인 풀을 공유하지 않는다. 복사본은 자기 풀을 필요할 때 생성하며, 소멸/교체 시 보조 스레드를 join한다. 동일 World를 여러 호출자가 동시에 수정/step하는 것은 지원하지 않는다.
- 벽의 기하 조회·벽 접촉, 공간 탐색, 사후 관통 검사, 힘 합산은 이번 단계에서 직렬이다. 모든 CPU 구간을 병렬화했다고 해석하면 안 된다.

## 언리얼 사용

`APowderClumpTest`의 Details → **Clump / Simulation**:

1. `CPU Threads`: 기본 1. 계산을 분할할 때 사용할 총 스레드 수.
2. `Parallel Min Jobs`: 기본 128. 접촉 단계에는 후보 쌍 수, 적분 단계에는 강체 수를 적용한다. 검증 시 1로 두면 작은 장면에서도 병렬 경로를 강제할 수 있으나 느려질 수 있다.
3. 설정 후 **Reset Simulation / R**로 적용한다. 실행 중 값만 수정하면 현재 실행에는 적용되지 않는다.
4. **Clump / Profiling**의 `Last Pair Threads`, `Last Integration Threads`로 마지막 스텝의 실제 분할 수를 확인한다.

설정은 `configuration.txt` 내보내기에 기록된다. 렌더링용 UObject는 보조 계산 스레드에서 접근하지 않는다. 강성 완화 후보는 자동 적용하지 않았다.

## 검증

| 항목 | 결과 |
|---|---|
| Core 전체 회귀 | 31/31, 최종 진단 CLI 수정 후 해당 테스트 재실행 통과 |
| Unreal 전체 자동화 | 15/15, CPU 설정·리셋·실제 분할 수·내보내기·잘못된 설정 포함 |
| 병렬 특화 | 선형/Hertz × 구형/복합 × 벽 없음/정적·이동 벽 × 2/4/8 = 24조건 |
| 이력·보존 | 힘/토크에 따른 전체 궤적 동일, 접촉 이력 복사 후 연속 계산 동일, 운동량 잔차 <1e-12 kg m/s |
| 수명·오류 | 동시 독립 복사본, 30회 반복 예외 barrier, 강제 적분/접촉 실패 원자성, 실패 후 복구, 체크포인트 |

전용 데이터 경쟁 검출기(TSan)는 이 Windows/MSVC 실행에서 사용하지 않았다. 위 결과는 출력 슬롯 소유권 검토와 동시 실행·복구 회귀 검증 근거이며, 경쟁 검출기로 모든 실행을 증명했다는 의미는 아니다.

## 성능과 메모리

측정 CPU: Intel Core i7-14700KF, 물리 20코어 / 논리 28개. Release, `/fp:strict`. 스레드 순서를 번갈아 각 3회 실행한 중앙값이다. 1스레드 대비 1 미만은 느려짐을 뜻한다. 벤치마크 중 빌드·자동화 테스트를 함께 돌리지 않았다.

첫 표는 100스텝 워밍업 후 2,000스텝, dt=1e-8초의 짧은 연산 비용 시험이다. 복합 입자 256강체는 pebble 512개다. 강제로 `Parallel Min Jobs=1`을 적용했다. 이 짧은 접촉망 시험의 가속률을 전체 공정 속도로 환산하지 않는다.

## 재현과 다음 작업

```powershell
cmake --build Intermediate/PowderCore --config Release --parallel 8
ctest --test-dir Intermediate/PowderCore -C Release --output-on-failure
python -B Scripts/run_optimization09_validation.py --output Saved/Optimization09_new --reference-exe Saved/Optimization09_before/powder_opt01.exe
```

새 출력 디렉터리를 사용한다. 이전 실행 파일은 로컬 `Saved/Optimization09_before`에 보관했으며 SHA256은 보고서에 기록했다. 핵심 산출물은 `Docs/DEM/optimization09/report.json`, `contract.json`, `samples.json`, `tested_manifest.json`, Core/Unreal 로그와 시나리오별 CSV다.

진단 CLI는 `powder_opt01 INPUT.bench NEW_DIRECTORY 1 walls 4 128`처럼 스레드 수와 최소 작업 수를 추가 지정할 수 있다. 생략 시 기존 호출과 동일하게 1스레드다.

다음은 **최적화 10**이다. 현재 용량 제한을 명시한 상태에서 대량 시험을 가능하게 하는 저장·인덱스·메모리 제한을 점검하고 1천/1만/10만 조건의 인수 결과를 작성한다. 이번 작은 시험에서 나타난 이득으로 kg 규모 성공을 추정하지 않는다.
