## 유지 조건
시간 간격, 반복 횟수, 입자 수, 중력, 마찰을 속도 때문에 변경하지 않는다.
화면 밖 입자도 계속 계산한다. 후보 목록 용량 초과 시 잘라내지 않고 확장/기존 경로 전환/명시적 실패를 사용한다.
CPU 접촉 기준 비교와 GPU 수치 검사를 거쳐야 한다. 이 작업은 기존 근사 모델의 훼손 방지이며 실제 분말 정확도 인증은 아니다.

## 작업 01 결과
현재 저장된 레벨을 별도 Unreal 명령 프로세스에서 읽어 설정과 두 생성기를 확인했다. 실행 중인 사용자 에디터/PIE 상태가 아니라 **디스크에 저장된 상태**를 기준으로 삼는다.
105개 소스, 14개 설정/자산, 빌드된 모듈 2개와 초기 입자 5만 개의 SHA-256을 고정했다. 생성기 좌표와 이전 실행의 초기 상태 일치를 확인했다.
검사 도구는 변경된 조건/코드/바이너리를 감지한다. 기본 실행은 검사만 하고 --run에서만 새 벤치마크를 실행한다. 반복 실행은 순차적이고 기존 Unreal 프로세스가 있으면 자동 종료하지 않고 측정을 거부한다.
이전 12초/30초 기록을 이용한 기본 불변량 검사와 손상 입력 거부 시험을 통과했다. 이번에는 신규 속도 측정을 하지 않았다.

세부 기준/실행 명령: [추가 최적화 기준](additional_optimization01/README.md).

## 작업 02 결과
GPU 이벤트 계측과 선택적 경계 분리 진단을 구현했다. 기본 물리 경로와 설정을 유지하며 GPU 계측 기본값은 OFF이다.
5만 개·12초·모드별 2회 비교에서 기본 배속 중앙값 0.190, 계측 ON 0.169, 분리 진단 0.141을 기록했다.
분리 진단 GPU 시간은 입자 접촉 약 71.75%, 경계 약 14.03%, 격자 약 12.94%였다. 추가 커널·메모리 비용을 포함하므로 기본 커널 내부의 정확한 비중과 동일시하지 않는다.
6회 모두 초기 상태/질량/입자 수/최종 충돌 기준을 통과했고, 확장 GPU 코어 시험 및 언리얼 19개 시험을 통과했다.
다음은 작업 03 이웃 후보 목록 구축이다. 상세 결과·한계·재현: [GPU 계측 결과](additional_optimization02/README.md).

## 작업 03 결과
GPU 이웃 후보 목록과 용량 초과 시 입자별 기존 전체 탐색 fallback을 구현했다. 현재는 매 위치 보정 반복마다 다시 구축하며 재사용하지 않는다.
CPU 모든 쌍 대조에서 8,690개 접촉 쌍 누락이 없었고, 독립 CPU 접촉 계산/기존 GPU 결과 비교, 새 접촉 생성, 강제 용량 초과, Reset 및 경계 시험을 통과했다.
5만 개·12초·각 2회에서 기존 중앙값 0.20173배속, 후보 경로 0.16938배속으로 후보 경로 소요시간이 약 19.1% 늘었다. 재사용 전의 구축 기반이며, 기본 OFF로 유지한다.
4회 모두 초기 상태/질량/입자 수/최종 충돌 검사를 통과했다. 관련 GPU 코어 시험 2개와 언리얼 자동화 19개도 통과했다.
다음 작업 04에서 이동·위치 보정을 감시하는 안전 재사용을 구현한다. 상세: [후보 목록 결과](additional_optimization03/README.md).

## 작업 04 결과
skin을 포함한 목록과 GPU 변위 감시를 구현했다. 매 접촉 직전에 참조 위치 대비 변위를 검사하므로 예측 이동과 입자/경계 투영을 모두 반영한다. 임계값 초과 및 용량 초과 시 사용 전에 재구축한다.
소규모 모든 반복의 모든 쌍 검증, 독립 CPU 접촉 기준, 새 접촉/회전축/벽/fallback/배치/Reset 시험을 통과했다. 관련 코어 시험 3개 및 언리얼 자동화 19개 통과.
5만 개 12초 비교 각 2회에서 중앙값은 기존 0.19538배속, 재사용 0.30586배속(약 1.57배, 소요시간 36.1% 감소)이었다. 30초 연장 실행은 0.29101배속으로 초기 상태/질량/수량/최종 기록 충돌 검사를 통과했다.
기본 경로와 물리 설정은 유지하며 새 경로는 -GrainCandidateReuse로 활성화한다. 기본값 확정은 작업 08에서 진행한다.
작업 04 이후 벽·날개 충돌 후보 축소를 진행했다. 자세한 안전 조건과 검증 한계: [안전 재사용 결과](additional_optimization04/README.md).

## 작업 05 결과

벽 평면 그룹의 보수적 상한과 회전체 그룹 AABB로 후보를 줄였다. 회전과 이전 접촉의 위치 보정을 매 그룹 검사에 반영한다. 전체 경계 계산과 위치·법선·벽 속도를 비교한 571,860개 표본 및 회전 연속 실행, 관련 코어 4개 시험을 통과했다.

5만 입자 12초 각 2회 중앙값은 재사용만 0.28052배속, 경계 후보 축소 추가 0.27685배속이다. 이번 장면에서 소요시간이 1.33% 증가해 기본 활성화하지 않는다. 30초 연장 실행은 0.25589배속으로 초기 불변량/최종 기록 기하 검사를 통과했다. [구현·검증 결과](additional_optimization05/README.md).

작업 05 이후 전송·표시 최적화를 진행했다.

## 작업 06 결과

비차단 읽기 요청/완료 확인과 전송·게시·표시 버퍼 재사용을 구현했다. 위치와 요청 시점의 시각·회전각을 함께 게시하며, Reset·종료에서 진행 중 DMA를 정리한다. 초기 중복 읽기를 제거하고 기존 표시 주기와 물리 계산 조건을 유지했다.

관련 코어 5개 시험과 5만 입자 12초 각 2회/30초 연장 기하 검사를 통과했다. 12초 중앙값은 기존 0.279849배속, 새 경로 0.280071배속으로 전체 속도 이득은 확인하지 못했다. 읽기 CPU 시간/요청은 약 28% 줄었다. 30초 연장은 0.251664배속이다. `-GrainStream` 선택 옵션이며 작업 08까지 기본 OFF를 유지한다. [구현·검증 결과](additional_optimization06/README.md).

작업 06 이후 메모리 접근·커널 인수 제출 개선을 진행했다.

## 작업 07 결과

변경되지 않은 커널 인수의 재설정을 생략하고, 이웃 후보 ID를 후보 순번 중심의 연속 메모리로 전치했다. 후보 순서·접촉 누적 순서·커널 순서와 물리 조건을 유지한다. 인수 API 호출은 약 91% 감소했다.

5만 입자 12초 각 2회 중앙값은 기존 안전 재사용 0.28036배속, 최적화 추가 0.33330배속으로 처리속도 약 1.19배/소요시간 약 15.9% 감소했다. 30초 연장은 0.31236배속으로 초기 불변량/최종 기록 기하 검사를 통과했다. 관련 코어 6개 시험 통과. `-GrainKernelOptimize` 선택 옵션이며 기본 활성화는 작업 08에서 결정한다. [구현·검증 결과](additional_optimization07/README.md).

작업 07 이후 통합 검증 및 기본값 확정을 진행했다.

## 작업 08 결과

사용자 요청대로 현재 5만 입자 초기 상태만 시험했다. 4조합×12초×2회 및 최종 기본값 빌드60초×2회 통과. 이웃 안전 재사용+작업07 최적화를 검증한 현재 설정에서 자동 적용하고, 경계 후보 축소/비동기 표시는 기본OFF로 유지한다. 처리 지연 시간이 무한히 누적되는 배속 제어 문제도 수정했다.

60초 평균0.30331/0.30484s/s, 5초 이상 구간 최저관측0.28411/0.28702s/s. 중간58개+최종기록2개 충돌 기준 통과. 운용 목표0.2s/s를 권장하나 보장 하한은 아니다. 저장된 목표0.18은 유지했다. 모든 단계/실제 물성/다른 입자 상태의 안전을 인증하지 않는다. [최종 결과](additional_optimization08/README.md), [개발 점검](additional_optimization08/review.md).
