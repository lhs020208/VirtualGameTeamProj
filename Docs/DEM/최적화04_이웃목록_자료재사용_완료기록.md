# 최적화 04 — 이웃 목록 재사용·연속 작업 배열 완료 기록

- 완료일: 2026-10-22
- 브랜치: `PowderSimulationOptimization`
- 결과: 같은 물리 결과를 유지하며 이웃 목록·작업 배열·접촉 이력 저장소 재사용 적용. 대량 분말 0.1배속 목표는 아직 미달성.

## 구현

1. 이동 여유 `skin = 최소 구성 구 직경 × 0.2`를 둔 이웃 목록을 생성한다. 생성 시 두 구의 반지름 합에 skin을 더한 거리 안의 후보만 보관한다. 후보 순서는 기존과 같은 노드 인덱스 순서다.
2. 힘 계산 전과 적분 후 안전 검사 직전에 각각 목록 유효성을 확인한다. 모든 구성 구의 ID·소유 몸체·직경이 같고, 목록 생성 위치로부터 구성 구 하나의 이동이 `skin/4` 이하인 동안 재사용한다.
3. 두 입자 사이 거리는 최대 `skin/2`까지만 줄어들 수 있어 생성 여유 skin보다 작다. 따라서 목록 밖에 있던 쌍이 접촉하기 전에 재생성 조건에 걸린다. 단계 수를 고정해 검사를 생략하지 않는다.
4. COM 이동량만 사용하지 않고 회전된 구성 구의 실제 월드 위치를 검사한다. 추가·삭제·ID 변경·소유 관계·직경 변경은 즉시 재생성하며, 형상/회전 변경으로 구성 구가 이동하면 같은 변위 기준을 적용한다. 밀도·타입 변화는 최적화 02 물성 캐시에서 검증한다.
5. 현재/다음 구성 구, 소유 인덱스, 관성, 힘·토크 누적기, 접촉 차수, 정렬된/적분 후/커밋용 몸체 배열의 용량을 재사용한다. 입자 정보는 연속 AoS 배열이며 힘·토크 배열을 분리했다. 전면적인 필드별 SoA 변환이나 GPU 자료 배치는 아니다.
6. 몸체별 임시 구성 구 벡터를 만드는 대신 재사용 배열에 직접 추가한다. 접촉 이력은 정렬된 연속 배열로 저장하고 현재/다음 상태의 두 버퍼를 교환한다. 실패한 스텝은 활성 이력·물리 상태·시간을 커밋하지 않는다.
7. `reuse_neighbor_list=true`가 Unreal 포함 기본값이다. false는 매번 후보를 재생성하는 검증 경로다. `invalidate_caches()`는 목록도 무효화한다. 목록·버퍼는 월드별 값 소유이므로 월드 복사끼리 공유하지 않는다.

## 검증

- 코어 전체 24개 테스트 통과. Unreal Editor Development 재빌드 및 DEM 자동화 13개 통과. NullRHI 검증이며 GPU 렌더 성능은 측정하지 않았다.
- 새 테스트: 고정 시드 이동 장면, 직경/ID/소유 관계/입자 수 변경, 명시 무효화, 정지 재사용, 고정 COM 회전, 목록 밖에서 빠르게 접근하는 쌍을 검증했다.
- 구형/비구형 혼합 월드에서 3,000스텝 동안 재사용과 매번 재생성의 상태·접촉 보고·이력 수 정확 일치. 실패한 스텝 뒤 재시도 및 이력 Reset 후에도 일치.
- 최적화 03 실제 보관 실행 파일과 최적화 04를 각각 3회 비계측 교대 실행하고 각각 1회 계측 실행했다. 최종 실행 파일의 강제 재생성 경로도 별도 실행했다. 모든 실행의 31개 물리/상태/이벤트 CSV가 바이트 단위로 정확 일치했다. 허용 오차를 확대하지 않았다.
- 시간 간격·물성 계수·힘·마찰·구름·회전·벽/겹침 안전 검사는 유지했다. 목록 유지 여부는 계측값에 의존하지 않는다.

목록 조회는 힘 계산 및 적분 후 검사에서 각각 발생한다. 생성 횟수에는 배출 완료 후 빈 월드 조회도 포함한다. 30RPM `mixing_32`는 기존부터 겹침 5% 기준 부적합인 진단 사례다. 정확도 검증을 통과한 공정 기준으로 취급하지 않는다.

1mm·256입자 충전은 500스텝의 1,000회 조회 중 1회 생성·999회 재사용했다. 구간당 실제 거리 검사도 최적화 03의 1,146,000회에서 320,000회로 줄었다. 이동 여유 범위로 후보를 선별하기 때문이다. 접촉 수·힘 결과에는 차이가 없다.

## 할당·메모리

실제 전역 C++ `new/new[]` 호출을 계수하는 별도 테스트에서 6몸체 장면을 5스텝 예열한 뒤 200스텝 동안 측정했다. 출력·월드 복사는 측정에서 제외했다. 두 경로 모두 새 연속 버퍼를 사용하므로 아래 수치는 이웃 목록 재사용 효과 비교이며, 최적화 03 대비 전체 할당 절감률은 아니다.

| 경로 | 할당 호출 수 | 누적 요청 바이트 | 작업 버퍼 유지 용량 |
|---|---:|---:|---:|
| 매번 재생성 | 20,200 | 1,188,800 | 8,760 |
| 목록 재사용 | 19,000 | 945,600 | 8,760 |

이는 C++ 할당 호출 계수이며 모든 OS/엔진 메모리 할당의 계수는 아니다. 기존 ID 자료구조, 강체 복사, 메시 질의 등에는 할당이 남아 있으므로 무할당 해석기로 표현하지 않는다.

1mm·256입자 시험의 유지 용량: 이웃 목록 관련 78,960바이트 + 작업 배열/접촉 이력 488,160바이트. 이 값은 vector capacity 기준이며 재료 맵·메시·렌더러·할당기 관리 비용 등을 제외한다. 프로파일 CSV에 조건별 최대치를 보관했다.

- 별도 실행 프로세스 최고 작업 집합: optimization03 = 7,888,896바이트 (7.52MiB).
- 별도 실행 프로세스 최고 작업 집합: optimization04 = 7,024,640바이트 (6.70MiB).

프로세스 메모리는 별도 소규모 벤치마크 실행의 관측치이며 장시간/대량 메모리 예측이 아니다. 누적 할당 바이트, 유지 용량, 프로세스 작업 집합은 서로 다른 지표다.

## 남은 제한과 다음 작업

- 300몸체/1024구 상한은 유지했다. 이번 작업에서 상한을 확대하지 않았으며 1천·1만·10만·약 159만 입자 요청은 미지원이다.
- 32입자 낙하/배출의 짧은 시험에서 0.1배속을 넘었어도 kg 규모 mm 분말 목표 달성이 아니다. 1mm·256입자 충전은 약 0.000030배속 수준이다.
- 작은 구에 맞춘 skin은 큰 구/작은 구가 심하게 섞인 조건이나 빠른 회전에서 재생성을 자주 유발할 수 있다. 안전을 위해 재사용률보다 보수적 조건을 우선한다.
- 밀집 시 후보 수가 제곱으로 증가할 수 있고 정렬 이력 배열의 중간 삽입에도 비용이 남는다.
- 다음 작업은 최적화 05 — 장비 표면·가동부 계산 재사용.
- 커밋·푸시는 수행하지 않았다.
