# 작업 24 — 공기에서 입자로의 힘 전달

완료: 2026-10-22. 단방향 연성 모듈 `0.3.0-one-way`, 공기 계산기 `0.2.0`, 재사용한 DEM 이동 적분 `PowderCore 0.21.0`.

**계산된 공기 속도가 입자에 Stokes 항력을 전달하는 단방향 계산을 구현했다.** 공기 격자에 입자의 반작용·체적 분율을 넣지 않으므로 양방향 CFD–DEM이 아니다. Unreal 화면·기존 혼합 레벨·다입자 접촉 World 연결은 이번 범위에 포함하지 않았다.

## 1. 구현과 연결 방식

- `Physics/FlowCore/include/flow/one_way.hpp`, `src/one_way.cpp`: 유동장 보간, Stokes 항력, 모델 범위 검사, 공기/입자 시계 연결, 실패 시 전체 단계 취소.
- `app/particle_run.cpp`: 실제 계산을 수행하고 입력·입자 조건·궤적·성공/실패 기록을 저장하는 실행 프로그램.
- `tests/one_way_tests.cpp`, `tests/particle_cli_tests.py`: 해석해·수렴·단방향성·저장 인터페이스 검사.
- `Scripts/run_one_way_validation.py`: 기존 공기 검사와 DEM 이동 적분 회귀를 함께 반복하고 소스 해시·정확 재현을 확인.

새 입자 운동을 별도로 흉내 내지 않고 `powder::Particle`, `ForceAccumulator`, `integrate_translation`을 사용한다. CMake의 `flow_particle_motion`은 기존 `Physics/PowderCore/src/core.cpp`를 그대로 빌드한다. PowderCore 소스는 수정하지 않았다. 이 재사용 범위는 구형 입자의 병진 운동이며 기존 마찰·회전·응집·접촉 시스템 전체의 공기 연동을 뜻하지 않는다.

한 번의 `advance_one_way`는 다음을 수행한다.

1. 입력과 현재 공기·입자 상태를 검증하고 임시 복사본을 만든다.
2. 작업 23의 `advance`로 다음 공기 상태를 실제 계산한다.
3. 공기 시간 간격을 정수 N개의 입자 하위 단계로 나눈다. 각 입자 위치에서 이전/다음 공기장을 각각 보간하고, 하위 단계 시각으로 선형 시간 보간한다.
4. 기존 DEM 힘 누산기에 항력과 중력을 더하고 symplectic Euler로 입자의 속도·위치를 갱신한다.
5. 모든 하위 단계에서 위치·입자 Reynolds 수·이동량·격리 조건을 검사한다. 모두 성공하면 공기와 입자 상태를 함께 확정한다.

공기는 입자 상태를 읽지 않는다. 입자 유무와 항력 활성 여부에 따라 공기 결과가 바뀌지 않는 것을 시험했다. 입자 단계에서 오류가 나면 이미 임시로 계산했던 공기 단계도 취소된다. 물리 시계는 수락한 공기 단계 수×dt이며 실시간 프레임이나 영상 재생을 사용하지 않는다.

## 2. 힘 모델과 명시적인 제외

선택 모델:

```text
slip = u_air − v_particle
F_drag = 3 π μ d slip
Re_p = ρ_air d |slip| / μ
τ_p = ρ_particle d² / (18 μ)
m dv/dt = F_drag + m g
```

Stokes 항력의 원문 근거: [MIT OCW, Flow Past a Sphere II, Chapter 3](https://ocw.mit.edu/courses/12-090-introduction-to-fluid-motions-sediment-transport-and-current-generated-sedimentary-structures-fall-2006/7841d9b1681d6748fa2f5cbc6d6f1cb2_ch3.pdf). 이번 구현은 무거운 입자의 **중력+항력** 기준판이다. 부력을 포함한 일반적인 침강식은 `(ρ_particle−ρ_air)g d²/(18μ)`지만, 현재 코드의 종단속도 기준은 `g τ_p`다. 두 식을 혼용하지 않는다. 밀도비≥100에서는 중력 대비 부력 크기는 1% 이하이며, 기본 밀도 1000 kg/m³에서 약 0.12%다. 부력을 구현했다고 표시하지 않는다.

제외한 힘·효과: 부력, 비정상 이력력(Basset), 부가질량, 배경 압력 기울기 힘, 양력, 회전 항력 토크, Brownian 운동, Cunningham 미끄럼 보정, 벽·다른 입자에 의한 항력 보정. 높은 밀도비와 낮은 Re 검사만으로 모든 제외 효과가 실제로 무시 가능하다고 입증되지는 않는다. 검증한 것은 선택한 방정식의 수치 해이며 실제 원료의 예측 정확도는 별도 검증이 필요하다.

미세 입자나 낮은 압력에서는 미끄럼 보정이 중요해질 수 있다. [NIST의 미끄럼 보정 연구](https://www.nist.gov/publications/slip-correction-measurements-certified-psl-nanoparticles-using-nanometer-differential)를 적용 범위를 구분하는 근거로 참고했다. 해당 연구의 고 Kn 측정 결과를 이번 30 μm 가상 입자의 보정값으로 사용하지 않았다. 여기서는 `Kn=λ/d`를 쓰므로 다른 자료의 반지름 기준 Kn과 수치를 직접 혼용하지 않는다.

## 3. 이번 기준판의 적용 조건

모든 수치는 프로젝트 초기 검증 범위이며 보편적인 정확도 보증 기준이 아니다.

| 항목 | 검사 |
|---|---|
| 공기 | 작업 22–23의 근대기압·등온·비압축성 2D 평행판 계약 유지 |
| 입자 | 비회전 구형, ρ_particle/ρ_air≥100 |
| 항력 | 상대 Re_p≤0.1, 실행 중에도 검사 |
| 기체 미끄럼 | 추정 Kn(d)≤0.01, 보정은 아직 없음 |
| λ 추정 | 70 nm×101325/min(출구 절대압, 추정 입구 절대압); 명목 공학적 추정 |
| 크기 | d≤0.1 min(dx,dy) |
| 벽 거리 | 입자 중심과 상하 벽 사이 ≥50d |
| 입출구 | 보간 스텐실이 내부에 있어야 함: x∈[dx/2,L−dx/2], y∈[dy/2,H−dy/2] |
| 차원 | 입자 위치·속도 z=0, 공기 x/y와 DEM x/y 동일. Unreal 축 변환은 미연결 |
| 입자 수·격리 | API 최대 32개 시험 입자, 입자 중심 간 거리 ≥50×큰 입자 지름 |
| 전역 질량 부하 | Σm_particle/(ρ_air L H reporting_depth)≤0.001 |
| 입자 시간 간격 | 항력 활성 시 dt_particle≤0.05τ_p, N=1–100000 정수 |
| 하위 단계 이동 | 한 번에 ≤0.1 min(dx,dy) |
| 중력 | xy 평면, 크기≤9.81 m/s². 기본 (0,−9.81,0) |

보고용 깊이는 전역 시험 슬래브 질량 부하를 계산할 때 명시적으로 사용한다. 이 값은 국소 고체 체적 분율이나 유동 반작용 계산이 아니다. 깊이와 전역 질량 부하만으로 단방향 근사의 타당성을 보장하지 않으며, 이번에는 소수의 멀리 떨어진 시험 입자로 제한한다. 국소 밀집·차폐·입자 접촉은 지원하지 않는다.

영역 밖의 입자를 가장자리로 붙이거나 유동 속도를 0으로 바꾸지 않는다. 벽 근처 보정이 필요한 위치, 높은 Re, 큰 입자, 접촉 가능한 배치에서는 이유를 남기고 실패한다. 기존 40 mm 혼합 시험 입자는 이 미세 입자 모델에 들어갈 수 없다. 항력을 끈 비교 실행도 동일한 기하·입자 모델 범위 검사를 유지한다.

## 4. 공간·시간 보간

u와 v를 동일 위치에 저장된 벡터로 간주하지 않는다. 각 MAC 성분의 실제 위치를 기준으로 네 이웃 값을 이중선형 보간한다. 영역 밖 외삽과 경계값 잘라내기는 없다. 마지막 유효 격자점에 정확히 놓인 경우에는 마지막 보간 구간을 사용한다.

공기 상태 n, n+1 사이에서 하위 단계 k의 시작 시각 `α=k/N`을 사용한다. 입자 위치는 매 하위 단계 갱신하므로 이동하는 입자가 같은 셀 속도를 계속 받는 방식이 아니다. 끝 위치·끝 시각에서도 항력 적용 범위를 확인한다. 추가로 다음 공기 상태에서의 범위 검사도 적용하므로 급격한 변화에서는 보수적으로 실패할 수 있다.

하위 단계에 해석해 궤적을 대입하지 않는다. 해석해는 검증에서만 사용한다. 전체 구현은 입자 이동 적분과 공기 시간 적분 모두 1차이며, 이중선형 보간의 매끄러운 공간장 수렴과 구분한다.

## 6. 실행 방법과 파일

프로젝트 루트에서 PowerShell:

```powershell
python Scripts/run_one_way_validation.py --output Saved/Flow_task24_new_check
& ./Intermediate/FlowCore/Release/flow_particle_run.exe Physics/FlowCore/fixtures/one_way_channel.flow Saved/MyParticleRun
```

입자 지름·밀도·하위 단계 수를 바꾸려면 세 값을 함께 지정한다. 단위는 각각 **m, kg/m³, 정수**다.

```powershell
& ./Intermediate/FlowCore/Release/flow_particle_run.exe Physics/FlowCore/fixtures/one_way_channel.flow Saved/MyParticleRun2 0.00003 1000 40
```

출력 폴더는 새 경로여야 하며 부모 폴더는 존재해야 한다. CLI는 한 입자를 채널 중앙에 놓고 기본 중력을 사용한다. 여러 입자·다른 중력·항력 비활성 비교는 C++ `OneWaySettings`/`OneWayState` API로 지정한다. 가상 분말 설정 파일 전체를 읽는 UI는 아직 연결하지 않았다.

- `input.flow`: 실제 공기 조건.
- `particle.json`: 입자 조건·중력·초기 상태·항력 활성·반작용 비활성 표시.
- `particles.csv`: 시각 0과 수락한 공기 단계마다 입자 ID·위치·속도·구간 최대 Re·구간 항력 충격량. 입자 하위 단계마다 출력하는 파일은 아니다.
- `result.json`: 단방향 모드, 수락한 공기 단계 수와 물리 시간, 하위 단계 수, 최대 Re·dt/τ, 성공/실패·이유.

종료 코드 0은 요청 시간 완료, 2는 입력/파일 오류, 3은 계산 실패다. 실패한 물리 단계는 출력 이력에 추가되지 않는다. 파일 시스템 오류는 파일 기록 자체가 실패할 수 있어 종료 코드도 확인해야 한다.
