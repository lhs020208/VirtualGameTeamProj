# 작업 13 — 배치 방출과 공급 조건

상태: 완료. 작성일: 2026-10-21. 프로젝트 `D:/GitHub/VirtualGameTeamProj`, 브랜치 `PowderSimulation`, 코어 버전 0.13.0.

## 구현과 의미

작업 12의 가상 분말 총량·입도·밀도·접촉 물성을 유지하면서, 유한한 공급 재고와 실제 계산 중인 입자를 분리했다. 재고의 ID·지름·질량은 초기화 시 시드로 결정되며 공급이 막혀도 다시 추첨하거나 변경하지 않는다. 총량 한도는 기존과 같은 300개다. 질량 모드는 목표 질량과 허용 오차로 완전한 입자 개수를 선택하는 작업 12의 정책을 유지한다.

| 설정 | 의미 |
|---|---|
| SupplyMode: Batch | 준비한 전량을 시작 시각에 한 번에 방출 |
| SupplyMode: Timed | 시작 시각부터 일정 간격마다 ParticlesPerEvent개를 요청 |
| SupplyStartSeconds | 첫 요청 시각. 물리 시간 s, 0 이상 |
| SupplyIntervalSeconds | 요청 간격. 물리 시간 s, 양수 |
| ParticlesPerEvent | 한 요청의 입자 수, 1~300 |
| SupplyRetrySeconds | 막힌 입자의 재시도 간격. 물리 시간 s, 양수 |
| Spawn Centre / SpawnHalfExtentsCm | 공급 영역 중심·반크기, cm |
| InitialVelocityMps | 투입 순간의 속도, m/s |

총량은 기존 ParticleCount 또는 TargetMassKg/MassToleranceKg로 지정한다. 간격과 회당 개수는 **명목 요청률**이며 실제 공급률을 보장하지 않는다. kg/s 일정 유량 제어나 임의의 시간표는 이번 범위가 아니다. 다분산 입자는 회당 질량이 다를 수 있다.

Batch 기본값은 시작 시각 0이며 이전처럼 300입자를 즉시 배치한다. 지연 Batch는 전량을 미리 겹침 없이 배치할 수 있는지 검사하고, 지정 시각 전까지 계산 공간에 입자를 넣지 않는다. 일괄 배치 자체가 불가능하면 작업 12와 동일하게 초기화 오류를 낸다. 실제 밸브가 입자를 받쳐 두었다가 열리는 모델은 아니다.

Timed는 공급 영역이 전체 재고를 동시에 담을 필요가 없다. 한 입자만 들어가는 입구에서 여러 입자를 순차 공급할 수 있다. 가장 큰 실제 재고 입자가 생성 영역에 들어갈 수 있는지는 초기화 때 검사한다. 벽에 가려지거나 현재 입자가 입구를 차지하면 요청된 입자는 대기한다.

## 시간과 혼잡 처리

- 물리 시간만 사용한다. 렌더 FPS·벽시계 시간·계산 지연에 맞춰 입자를 추가하지 않는다.
- 이벤트 i의 시각은 `start + i * interval`이다. 마지막 이벤트는 남은 재고만 요청한다.
- 고정 dt의 경계에서 해당 시각 이상이 된 첫 시점에 처리한다. 시각이 dt와 맞지 않으면 최대 약 한 단계 늦어지며 일찍 공급하지 않는다. 부동소수점 표현에 따른 경계 차이도 한 단계로 처리한다.
- 먼저 요청된 입자가 먼저 들어가는 FIFO 정책이다. 앞 입자가 배치되지 않으면 뒤 입자를 건너뛰어 넣지 않는다.
- 새 요청이 도착하거나 재시도 시간이 되면, 시드로 정해진 격자 후보를 다시 검사한다. 기존 입자와 벽에 대해 실제 반지름의 겹침을 검사한다.
- 후보 한도에 걸려도 입자를 버리거나 겹침을 허용하지 않는다. 대기 상태를 유지한다. HUD는 `Waiting: occupied/candidate limit`로 안내한다.
- 후보 순서는 매 시도 동일하므로 후보 한도가 너무 작으면 다른 빈 공간이 있어도 계속 대기할 수 있다. 생성 영역·입도·MaxPlacementCandidates를 조정해야 한다. 대기는 수학적 배치 불가능 판정이 아니다.
- 한 번의 재시도에서 밀린 요청 여러 개가 들어갈 수 있다. 실제 투입은 요청 간격보다 몰릴 수 있으며 이는 대기열 해소 정책이다.
- 일시정지하면 공급 시간도 멈춘다. N은 한 물리 단계와 그 시각의 공급을 처리한다. R은 재고·대기열·추적·시간을 모두 새로 만든다.

## 수량·질량 수지와 추적

`SupplyReport`에 다음 값을 각각 개수와 kg로 저장한다.

- planned: 실행의 전체 재고.
- requested: 현재 물리 시각까지 요청된 누적 재고.
- inserted: 실제 계산 공간에 들어간 누적 재고.
- pending: 요청되었으나 아직 들어가지 못한 재고.
- future: 아직 요청 시각이 오지 않은 재고.

항상 `planned = inserted + pending + future`, `requested = inserted + pending`을 만족해야 한다. 사용자 목표 질량과 정수 입자로 구성한 실제 planned 질량의 차이는 기존 InitialReport의 target/delta로 별도 표시한다. 대기 입자는 힘 계산·렌더링·공간별 잔류량에 포함되지 않는다.

Tracker는 새 입자의 실제 생성 시점과 위치에서 기록을 시작한다. 생성 전의 가상 이동 경로나 관 진입을 만들어 내지 않는다. 관 내부에서 생성된 입자는 출구만 지났다고 완전 통과로 집계하지 않는다. 기존 입자의 접촉 이력과 통과 이력은 공급 때 초기화하지 않는다. 추적 질량 기준에는 새로 들어온 입자의 질량을 더한다.

후보 생성·공급·추적 변경은 계산 스레드에서 수행한다. 새 세대 초기화와 종료를 후보 탐색 중 확인한다. 취소되거나 실패한 공급 후보의 부분 상태는 게시하지 않는다. 기존 월드와 공급 재고의 복사본을 사용해 갱신하며, 오류가 나면 실행을 중단한다.

## Unreal 사용법

1. Play 후 `PowderDEMTest` 액터를 선택한다. 필요하면 Shift+F1로 마우스를 해제한다.
2. Details의 **DEM / Supply**에서 Batch 또는 Timed를 선택하고 시작 시각·간격·회당 개수·재시도 간격을 지정한다.
3. **DEM / Settings**의 총량, 공급 중심·반크기, 초기 속도를 지정한다.
4. 뷰포트로 돌아와 **R**로 적용하고 **Space**로 실행한다. **N**은 한 단계다.
5. HUD의 `plan/request/in/wait/future`와 질량 수지를 확인한다.
6. **K**는 저장, **L**은 불러오기 후 초기화다. 기본 파일은 `Saved/DEM/PowderSettings.dem`이다.

예: 총량 30개, Timed, 시작 0s, 간격 0.01s, 회당 1개, 재시도 0.001s. 기본 dt=2e-7s에서는 0.01 물리 초에 50,000단계가 필요하므로 실제 화면에서 오래 기다릴 수 있다. 공급을 빨리 보기 위해 dt를 임의로 키우지 않는다. 설정 편집은 R을 눌러야 현재 실행에 반영된다.

새 설정 저장 형식은 `POWDER_SETTINGS 2`이며 공급 조건을 포함한다. 버전 1도 읽을 수 있고 즉시 Batch로 해석한다. 잘못된 공급 모드·시간·개수나 잘린 파일은 거부하며 기존 설정과 실행을 유지한다. 저장 파일은 진행 상태나 대기열 체크포인트가 아니다.

## 검증

검사 전 기준: 개수 수지는 정수로 정확 일치, 독립 구 질량 합계와 공급량 차이 및 질량 분할 오차는 1e-10kg 이하, 자유 운동 위치는 해석값 `v*(현재 시각-생성 시각)`과 1e-12m 이하, 입자 사이 초기 거리는 반지름 합 이상이다.

- 코어 CTest 전체 12개 검사 통과. 최초 실행에서 기존 설정 테스트의 버전 문자열과 새 시험의 불완전한 추적 영역을 수정했다. 기존 10개가 통과했고, 수정한 설정·공급 검사 및 관련 worker 검사를 다시 통과했다.
- 일괄 즉시/지연 방출, 요청 전 미투입, 마지막 이벤트의 잔량, 설정 왕복과 버전 1 호환.
- 한 셀 입구에서 3개 요청·1개 투입·2개 대기, 빈 공간 확보 후 FIFO 재투입, 벽으로 완전히 가려진 입구의 지속 대기.
- 1kg ±0.1kg의 다분산 재고에 대한 공급 질량 분할, 취소 시 원래 상태 보존, 잘못된 입력 거부.
- 실제 코어 자유 운동으로 입구가 비워지는 3입자 순차 공급을 1,100단계 실행하고 생성 시각별 해석 위치와 비교.
- 생성 시각의 추적 시작, 가짜 관 통과 없음, 중복 ID 거부, 일시정지·단계 실행·리셋·이전 스냅샷 보존.
- Unreal Development Editor 빌드 성공. `BackgroundBridge`, `TrackingBridge`, `SettingsBridge`, `SupplyBridge` 4개 자동 검사 통과. 실제 액터의 렌더 개수, 대기량, 공급 설정 저장·복원, 지연 일괄 방출을 확인했다.
- Unreal 결과: `Saved/DEM_task13_automation/index.json`, 로그: `Saved/Logs/DEM_task13_automation.log`.
