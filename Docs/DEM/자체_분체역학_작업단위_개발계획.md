# 자체 분체역학 해석기 — 작업 단위 개발 계획

작성일: 2026-10-21

## 1. 확정한 개발 방향

- 최우선 목표는 물리적으로 타당한 계산이다. 실시간 속도는 일부 포기할 수 있다.
- 입력 조건에 따라 실제로 재계산한다. 녹화 영상 재생으로 시뮬레이션을 대체하지 않는다.
- 상용 해석기는 사용하지 않는다. 입자 해석기와 이후 공기 유동 해석기를 직접 개발한다.
- 장비 에셋이 준비되는 동안 기본도형 시험장을 사용한다.
- 대상 원료는 아직 미정이다. 가상 입자의 물성을 수치로 정의하고 변경할 수 있게 한다.
- 기존 조사 자료는 모델 선정과 공정 이해의 참고 자료다. 특정 분말의 보정된 실측 물성으로 간주하지 않는다.
- 입자 계산은 DEM, 공기 이송은 이후 CFD–DEM, 혼합기는 움직이는 벽과 입자의 접촉으로 확장한다.
- 실제 분말과 일치한다고 주장하기 전에 해당 분말의 실험 자료로 보정하고 별도 조건으로 검증한다.

## 2. 작업 1회의 정의와 운영 규칙

**작업 1회 = 하나의 프롬프트로 지시한 작업의 구현 + 해당 범위 검증 + 발견된 문제 수정 + 결과 보고.**

- 아래 각 작업 번호가 프롬프트 한 번으로 요청할 범위다. 고정 시간이나 성공을 보장하는 일정 단위는 아니다.
- 작업 중 발견된 해당 범위의 결함은 같은 작업에서 수정하고 재검증한다. 이를 별도 기능 작업으로 세지 않는다.
- 선행 작업의 결함 때문에 완료 기준을 충족하지 못하면 원인과 수정 범위를 기록한다. 미완료 상태에서 다음 단계 완료를 선언하지 않는다.
- 예상보다 큰 기능이 필요하면 현재 작업을 완료한 것으로 처리하지 않고, 남은 범위를 분할하여 계획을 갱신한다.
- 각 작업은 구현 전 모델·가정·검증 기준을 명시하고, 완료 후 변경 파일·시험 결과·오차·제한을 기록한다.
- 수치 검증은 구현식을 그대로 복사한 시험보다 해석해, 보존 법칙, 독립적인 기준 계산과 비교한다.
- 오차 허용값은 시험 실행 전에 단위와 근거를 정한다. 결과를 맞추기 위해 사후에 완화하지 않는다.
- 커밋·푸시는 별도 요청 시 수행한다. 계획 작성은 구현 시작이나 자동 연속 실행을 뜻하지 않는다.

## 4. 구조 원칙

1. **계산 코어:** Unreal 의존성을 최소화한 C++ 라이브러리. 입자 상태·물성·접촉·시간 적분을 담당하며 엔진 없이 시험할 수 있게 한다.
2. **Unreal 연결부:** 형상과 설정을 계산 코어에 전달하고 완료된 계산 상태를 표시한다. 같은 입자에 Chaos와 자체 힘 계산을 동시에 적용하지 않는다.
3. **실험 관리:** 초기 조건, 난수 시드, 단위, 모델 버전, 계산 간격과 결과를 저장한다.
4. **시간:** 계산 코어는 SI 단위(m·kg·s), Unreal 위치는 cm로 명시적으로 변환한다. 작은 물리 시간 간격과 화면 갱신 간격을 분리한다.
5. **정확도:** 초기에는 CPU의 순차 계산과 배정밀도를 기준 구현으로 삼는다. 병렬화는 기준 결과와 비교하면서 도입한다.
6. **입자 의미:** 첫 DEM은 각 구를 실제 계산 입자로 취급한다. 대표 입자 확대나 강성 축소는 자동 적용하지 않으며 추후 별도 검증 대상으로 둔다.
7. **물성 일관성:** 구의 질량·관성은 지름과 밀도에서 계산한다. 총질량·입자 수·입도 분포를 동시에 모순되게 지정하지 못하게 한다.
8. **계산 속도:** 늦어져도 물리 단계를 건너뛰지 않는다. 표시할 결과가 없으면 기다리고 현실 시간과 시뮬레이션 시간을 구분한다.

- 난류·압축성 확대, 복잡한 관로 격자, 필터 저항·누설·밸브 상세 모델.
- 대표 입자 단순화: 보정 법칙과 적용 범위를 검증한 후 사용.
- CPU 병렬화·GPU 계산: 기준판과의 오차 비교 및 성능 측정 후 채택.
- 실측 보정: 한 시험으로 물성을 보정하고 다른 조건으로 예측력을 검증.
- 체크포인트 재개: 입자 상태뿐 아니라 접촉 이력·난수 상태·유동장까지 일관되게 저장.
