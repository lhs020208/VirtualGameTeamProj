# 작업 22 — 유동 모델·격자·경계조건 계약

완료: 2026-10-21. FlowCore `0.1.0-contract`. **입력 계약과 자료구조만 구현했다. 유동 시간 적분·압력 해법·Unreal 표시·CFD–DEM 연성은 아직 없다.** 다음은 작업 23이다.

## 1. 조사 자료와 첫 모델의 구분

`구현_설계_및_가정.md`의 수취부 −35 kPa(g), 내경 50 mm, 길이 약 5 m, 굽힘 2개는 기존 시제품의 가정이며 실측값이 아니다. `원료_투입_공정_디지털_트윈_기획정리.md`, `중간평가_발표가이드/참고문서/물리해석_시각화_최종목표.md`도 함께 참조했다. 분말 공급 질량 유량을 공기 유량으로 사용하지 않는다.

대기압 101325 Pa에서 −35000 Pa(g)는 66325 Pa(abs)다. 같은 온도의 이상기체라면 밀도는 대기 상태의 약 65.46%다. 이 조건 전체를 일정 밀도로 처리하지 않는다. 낮은 Mach 수만으로 큰 압력차의 비압축성을 보장하지 않는다. 이상기체 상태식과 음속의 근거: [NASA, Role of the Mach Number](https://www1.grc.nasa.gov/beginners-guide-to-aeronautics/role-of-the-mach-number/).

첫 모델은 **입자 없는 2차원 평행판, 등온 건조 공기, 비압축성 층류, 정지 벽**이다. 원형 관·굽은 관·강한 진공·난류·열전달·중력은 제외한다. 아래 제한은 이 프로젝트의 초기 검증 범위이며 보편적인 층류 전이 기준이 아니다. 기존 DEM 혼합 시험과 독립된 `Physics/FlowCore`에 구현했다.

## 2. 단위·물성·입력 범위

입력은 SI 선언 필수다. 길이 m, 시간 s, 속도 m/s, 압력 Pa(abs), 점도 Pa·s, 밀도 kg/m³를 쓴다. 내부 압력장은 `π = p_abs − p_reference`인 게이지압이다. 압력 변환 함수는 대기 절대압을 명시적으로 받는다. 단위 선언과 수치 범위를 검사하지만 잘못 붙인 모든 단위를 자동 추론하지는 못한다.

| 항목 | 계약 |
|---|---|
| 온도·공기 물성 | T=293.15 K 고정, R=287.05 J/(kg·K), γ=1.4, μ=1.81e−5 Pa·s; ρ=p_reference/(RT), ν=μ/ρ |
| 길이 L / 판 간격 H | 0.002–1 m / 0.001–0.02 m, L/H=2–50 |
| 격자 | Nx=4–1024, Ny=4–512, NxNy≤262144, dx/dy=1/8–8 |
| 보고용 깊이 | 0.001–1 m; 질량 유량 환산용이며 z 방향 벽은 없음 |
| 절대압 | 기준·경계·추정 입구압 95000–105000 Pa |
| 압력 변화 | Δp/p_out≤0.01, 입출구의 기준압 대비 변화≤1%; 역압력차 불허 |
| 속도 상한 B | 각 성분 1e−8–1 m/s, 해석해 최대 속도≤B |
| 보수적인 유동 범위 | Dh=2H, Re_bound=√2 B Dh/ν≤100, Mach_bound=√2 B/a≤0.1 |
| 연속체 점검 | Kn_estimate≤0.001; λ≈70 nm×101325/min(p_in,p_out), Kn=λ/H |
| 시간 | dt=1e−9–1 s, duration=dt–100 s, duration/dt는 정수, 최대 1천만 단계 |
| 명시적 계산 예산 | dt B(1/dx+1/dy)+2νdt(1/dx²+1/dy²)≤0.5 |

70 nm는 근대기압 공기의 명목 평균자유행로를 사용한 공학적 추정이다. 실측 물성이나 희박 기체 해석기를 뜻하지 않는다. 시간 간격 제한도 압력 수렴과 모든 비선형 안정성을 입증하는 정리가 아니다. 실제 해석 단계에서 잔차·보존·속도 상한을 추가 검사해야 한다.

## 3. 격자·경계조건·이산화 계약

구현한 MAC 자료구조는 p=NxNy개, u=(Nx+1)Ny개, v=Nx(Ny+1)개다. x 우선 행 순서이며 압력은 셀 중심, u/v는 각각 x/y 법선 면에 놓인다. 저장 배열에 유령 셀은 없다. 좌표·배열 크기·인덱스 범위와 필드의 유한성을 검사한다.

입구는 절대압 또는 포물선 평균 속도 중 하나다. 출구는 절대압으로 압력 기준을 고정한다. 위·아래는 정지 no-slip 벽이다. 입구에 압력과 유량을 동시에 지정하지 않는다. 속도 입구는 면 중앙값 대신 포물선의 **면 평균**을 저장하여 면 유량 합이 지정 평균과 일치한다.

다음 이산화는 **작업 23에서 구현할 설계**다.

- 방정식: ∇·u=0, ∂u/∂t+∇·(uu)=−∇π/ρ+ν∇²u.
- 균일 MAC 유한체적법. 대류는 보존형 1차 donor-cell, 점성은 2차 중앙 차분, 예측 속도는 명시적 Euler.
- 비증분 투영: u*=uⁿ+dt[−∇·(uu)+ν∇²u], ∇²πⁿ⁺¹=(ρ/dt)∇·u*, uⁿ⁺¹=u*−(dt/ρ)∇πⁿ⁺¹.
- 호환되는 이산 발산·기울기를 사용한다. 압력 A=−∇²는 행렬 비저장 Jacobi 전처리 CG를 첫 구현으로 선택한다. 압력 Dirichlet 기준이 영공간을 제거해야 한다.
- 압력 입출구: 면에 압력 지정, 속도는 발달 유동의 ∂u/∂x=0 및 v=0 조건. 고정 유량을 추가하지 않는다. 압력 유령 값은 면까지의 반 셀 거리를 반영한 π_ghost=2π_boundary−π_adjacent다.
- 속도 입구: u 면 평균을 고정하고 v=0. 예측 속도부터 입구값을 유지하는 이 투영법에서 압력 법선 기울기를 0으로 둔다. 일반적인 모든 속도 경계에 적용되는 압력 법칙이라는 뜻은 아니다.
- 벽: 법선 v=0, 접선 u는 반대 부호 유령값으로 벽면 0을 구성한다. 예측 법선 속도가 0인 벽은 압력 투영 Neumann 0. 모서리에서 벽 법선 속도 0을 우선한다.

압력과 속도를 질량 보존에 맞게 함께 푸는 일반 원리 참고: [CFD Direct, Pressure–velocity coupling](https://doc.cfd.direct/notes/cfd-general-principles/pressure-velocity-coupling). 외부 해석기를 호출하거나 상용 해석기를 사용하지 않는다.

## 4. 초기 상태와 계산 실패 계약

`rest`는 내부 속도 0, 압력은 출구압으로 초기화한다. 속도 입구가 있으면 경계면만 지정값이므로 초기 발산이 0이라는 보장은 없다. `steady_analytic_reference`는 해석해로 초기화할 뿐 계산 완료 상태가 아니다. 둘 다 physical_time=0, accepted_steps=0이다.

`validate_fields`는 배열 크기, NaN/Inf, 압력 범위·전체 압력차, 성분 속도 상한, 벽 법선 속도, 속도 입구 유지, 열린 면 역류, 단계 수와 물리 시계 일치를 검사한다. **잔차나 발산 수렴 검사를 대신하지 않는다.** 잘못된 값을 잘라서 정상 결과로 바꾸지 않는다.

작업 23의 단계 수락 기준:

- ||Aπ−b||∞≤max(absolute_tolerance, relative_tolerance×||b||∞). 기본값 1e−7 Pa/m² 및 1e−8, 최대 20000회.
- 투영 후 ||∇·u||∞≤1e−7 s⁻¹.
- |ṁ_out−ṁ_in|/max(|ṁ_in|,|ṁ_out|,1e−12 kg/s)≤1e−8. 무구동 시험은 절대 수지 오차≤1e−12 kg/s도 확인한다.
- 실패한 단계는 시간·필드를 확정하지 않는다. 실패 원인과 마지막 수락 상태를 보존한다. 시간 간격 축소로 모델 적용 범위 위반을 숨기지 않는다.

## 5. 작업 23의 독립 검증 문제

현재는 다음 **검증 문제를 정의한 상태**이며 유동 정확도 시험을 통과했다는 뜻이 아니다.

1. 무구동 정지: 동일 입출구 압력에서 속도·질량 수지·압력 기울기 0 유지.
2. 압력 구동 평행판: u(y)=Δp·y(H−y)/(2μL), U_mean=Δp H²/(12μL), U_peak=1.5 U_mean, 선형 압력, ṁ=ρ U_mean H×보고용 깊이와 비교한다. [NETL MFiX 검증 문서의 평행판 해석해](https://mfix.netl.doe.gov/doc/vvuq-manual/main/html/fluid/fld-01.html)를 독립 기준으로 참고한다. 그 문서의 주기 경계 구현과 우리 열린 경계는 동일하지 않다.
3. 속도 구동: 입구 면 유량 적분과 계산된 압력 강하를 독립 비교한다.
4. 2차원 제조해 Poisson: π=P₀[sin(πx/L)cos(2πy/H)+x/L], 해석적인 소스항, x Dirichlet/y Neumann으로 단순 1차원 문제 이외의 공간 연산자를 검사한다. 혼합 압력 경계는 cos(πx/(2L))cos(2πy/H) 제조해로 별도 검사한다.
5. 압력 구동 시작 과도: G=Δp/L일 때 u(y,t)=G y(H−y)/(2μ)−[4GH²/(μπ³)]Σ(홀수 n) sin(nπy/H)exp(−νn²π²t/H²)/n³과 비교한다. 급수 항 수 증가로 기준값 자체의 수렴도 확인한다.
6. 공간 격자 32×8, 64×16, 128×32에서 충분히 작은 동일 시간 간격으로 비교한다. 최세격자 속도 상대 L2 오차 1% 이내, 압력 기울기 상대 오차 1% 이내를 초기 목표로 둔다. 점성·Poisson은 점근 구간 오차비 3–5를 확인하고 반올림 오차 구간은 분리한다. 대류 donor-cell까지 2차 정확도라고 주장하지 않는다.
7. 시간 수렴은 고정 격자에서 dt=0.0005, 0.00025, 0.000125 s, 정상상태 이전의 동일 물리 시각에서 검사한다. 공간 오차를 충분히 낮춘 구간의 Euler 오차비 목표는 1.8–2.2다. 모든 조건은 입력 계약의 안정성 예산도 통과해야 한다.

## 6. 구현 파일과 사용법

- `Physics/FlowCore/include/flow/contract.hpp`, `src/contract.cpp`: 계약·단위 변환·범위 검사·MAC 필드·해석해·직렬화.
- `app/main.cpp`: 입력 검증 CLI. 출력 JSON에 `solver_implemented: false`와 해석해 추정값임을 기록한다.
- `fixtures/*.flow`: 압력/속도/무구동 유효 입력과 적용 범위 밖 진공 입력.
- `tests/contract_tests.cpp`, `tests/cli_tests.py`: 수치 계약과 파일 인터페이스 회귀 시험.
- `Scripts/run_flow_contract_validation.py`: 빌드, CTest 반복, 보고서 재현성·소스 해시 검사.

저장 형식은 `FLOW_CONTRACT 1`, SI, 고정 순서 키를 사용한다. 주석·알 수 없는 키·후행 내용·잘못된 정수·NaN/Inf·64 KiB 초과 입력을 거부한다. 표본 전체 형식은 `fixtures/pressure_channel.flow`를 참조한다. JSON 파일은 새 경로에만 저장하며 기존 결과를 덮어쓰지 않는다. 부적합 입력은 종료 코드 2와 `CONTRACT_REJECTED`를 반환한다.

프로젝트 루트에서 PowerShell 실행:

```powershell
python Scripts/run_flow_contract_validation.py --output Saved/Flow_task22_new_run
& ./Intermediate/FlowCore/Release/flow_contract.exe Physics/FlowCore/fixtures/pressure_channel.flow
```

첫 명령의 출력 폴더는 존재하지 않는 경로여야 한다. 검증 스크립트는 현재 설치된 Visual Studio 2022 Community의 CMake 위치를 사용한다.

## 8. 실제 설비 범위로 확장하기 위한 별도 작업

작업 23–26은 위 검증 범위에서 진행한다. 기존 혼합 시험의 40 mm 입자를 10 mm 간격 채널에 그대로 연성하지 않는다. 작업 24에서 입도·격자·항력 적용 조건을 정해야 한다.

- **22-E1 운영 조건 계약:** 실제 절대압 범위, 공기 유량·온도, 펌프 특성, 필터 손실, 관경·길이·굽힘을 확보하고 압축성·열·유동 상태를 판단한다. 기존 가정을 실측값으로 바꾸어 표기하지 않는다.
- **22-E2 가변 밀도/압축성 자체 해석기:** 연속·운동량·상태방정식과 에너지식 또는 정당화된 등온 조건을 별도 구현·검증한다. 압력파·유량·과도 기준 문제를 포함하고 열 모델은 필요하면 다시 분할한다.
- **22-E3 실제 관로:** 3차원 원형·굽은 관 격자와 경계 처리, 형상 수렴을 검증한다. 유동 범위가 요구할 때 난류 모델을 별도 선정·검증한다.

위 항목은 조건부 후속 작업이며 현재 구현된 기능이 아니다. 작업 27에서 실제 진공 관로를 연결하려면 그 운전 범위를 지원하는 모델과 해당 확장 검증이 먼저 필요하다. 다음 작업 23은 현재 계약으로 착수할 수 있다.
