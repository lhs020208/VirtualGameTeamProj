# 최적화 10 — 대량 CPU 기준판 인수와 다음 경로 결정

완료일: 2026-10-22  
실행 브랜치: `PowderSimulationOptimization`  
상태: **작업 10의 구현·측정·경로 결정 완료. 전체 0.1배속 목표 미달.**  
커밋/푸시는 수행하지 않았다. 기존 최적화 07~09의 미커밋 작업을 보존했다.

## 핵심 결과

- 1천·1만·10만 실제 계산 입자의 자유낙하/밀집 접촉을 1·8스레드 각각 3회, 총 36회 측정했다.
- 추가로 반지름 1mm, 밀도 1500kg/m³, 두 그룹 각 약 5kg인 **1,591,550개 입자**를 실제 CPU 해석기로 실행했다. 총 질량 10.0000035756kg, 그룹별 5.0000017878kg이다. 개별 구의 질량 때문에 목표를 소량 초과한다.
- 목표 총량 밀집 시험은 **4,733,669개 접촉**을 처리했다. 관측 private memory 약 6.36GiB, 계산 배속 8.044e-09였다.
- 0.1배속과의 비율 차이는 이 짧은 시험에서 약 **12,431,499배**다. 장시간 외삽이나 GPU/대표 입자의 예상 가속률로 해석하지 않는다.
- Core **33/33**, Unreal **15/15**, 기존 기본 경로 물리 CSV **31개 byte 동일**. 1천/1만/10만 입자에서 dt/2 비교도 통과했다.
- 다음 작업은 **최적화 11: 대표 입자 모델 계약과 질량·조성 구조**다. 검증을 통과하면 12~13을 거친 뒤 14의 GPU 경로를 평가한다. 두 경로 모두 성능 성공을 보장하지 않는다.

## 구현 범위와 용량 계약

`ClumpWorld`의 고정 상한을 명시적 설정으로 바꿨다. **에디터 기본값은 300강체/1024 pebble**로 유지된다. `maximum_bodies`, `maximum_pebbles`는 각각 1~2,000,000, `maximum_candidates`는 1~64,000,000 범위에서 명시적으로 설정한다. 값이 허용 범위 안에 있다는 사실은 해당 크기의 성능·메모리 지원 보장이 아니다.

기본 후보 상한은 1,048,576이며, 본 행렬은 4,000,000, 목표 밀집 재시험은 64,000,000을 지정했다. 후보 목록은 skin을 포함한 광역 탐색 후보로 실제 접촉보다 크다. 격자·해시·전수 탐색 및 캐시 재사용 모두 상한을 검사하고, 초과하면 예외로 중단한다. 후보나 힘을 조용히 누락하지 않는다. 입자/pebble 상한은 준비 버퍼 생성 전에 검사한다.

한 스텝이 실패하면 기존 입자·시간·접촉 이력을 유지한다. 기본 모델, 물성, dt, 안정성 및 사후 관통 검사를 완화하지 않았다. 대표 입자·GPU 해석기는 이번에 구현하지 않았다.

대량 실행은 `powder_capacity10` CLI를 사용했다. `L_MixingTest`를 159만 개 렌더링 장면으로 바꾸지 않았으며, 대량 Unreal 표시/FPS를 검증했다고 볼 수 없다.

## 사전 시험 조건

| 항목 | 설정 |
|---|---|
| 입자 | 모두 단일 구, 반지름 0.001m, 밀도 1500kg/m³ |
| 그룹 | A/B 번갈아 배치, 물성 동일; 그룹별 질량 별도 기록 |
| 접촉 | 선형 kn=10000, cn=0.01, kt=2500, ct=0.0025, mu=0.4 |
| 시간 간격 | 2e-8s (20ns), 모든 시험에서 동일 |
| 자유낙하 | 간격 4mm, 중력 -9.81m/s², 벽 없음 |
| 밀집 접촉 | 간격 1.99999mm 격자, 초기 미소 겹침, 중력 동일, 벽 없음 |
| 반복 | 1천/1만/10만 × 2조건 × 1/8스레드 × 3회 |
| 측정 스텝 | 각각 200/40/10, 별도의 초기 스텝 1회 |
| 대량 자원 제한 | 행렬 4GiB private/프로세스 180초; 목표 총량 8GiB/180초 |
| 목표 총량 스모크 | 8스레드, 초기 1 + 측정 5스텝, 조건별 1회 |

단일 스텝 창의 최저 속도까지 기록한다. 초기 준비/탐색 스텝과 이후 스텝을 분리하며, 프로세스 전체 시간도 별도 저장한다. 결과 해시·에너지 집계·출력 비용은 평균 solver 배속에 포함하지 않는다. 프로파일링은 켜져 있다. GPU 전송, Unreal 렌더, 공정 측정 비용은 포함하지 않는다.

## 성능 행렬

단위는 **물리 초 / 실제 초**다. 1·8스레드 열은 3회 중앙값, 최저 스텝 배속은 세 반복 중 가장 느린 스텝의 값이다.

| 입자 수 / 질량 | 조건 | 1스레드 배속 | 8스레드 배속 | 8스레드 최저 스텝 배속 | 가속률 | private 최대 |
|---|---|---:|---:|---:|---:|---:|
| 1,000 / 0.00628319kg | 자유낙하 | 2.872e-05 | 2.114e-05 | 7.150e-06 | 0.74배 | 3.5MiB |
| 1,000 / 0.00628319kg | 밀집 접촉 | 9.336e-06 | 1.796e-05 | 7.429e-06 | 1.92배 | 5.3MiB |
| 10,000 / 0.0628319kg | 자유낙하 | 2.264e-06 | 2.483e-06 | 1.648e-06 | 1.10배 | 23.6MiB |
| 10,000 / 0.0628319kg | 밀집 접촉 | 7.829e-07 | 1.741e-06 | 1.501e-06 | 2.22배 | 43.4MiB |
| 100,000 / 0.628319kg | 자유낙하 | 1.812e-07 | 2.119e-07 | 9.291e-08 | 1.17배 | 240.5MiB |
| 100,000 / 0.628319kg | 밀집 접촉 | 7.507e-08 | 1.506e-07 | 1.399e-07 | 2.01배 | 401.4MiB |

목표 총량은 동일 재료에서 총 10kg이며, 두 조건 모두 6스텝 합계 **1.2e-7 물리 초**만 진행했다. 이는 진입·메모리·계산 비용을 확인한 스모크 시험이고, 지속 배속이나 공정 결과 인수 시험이 아니다.

| 목표 총량 조건 | 평균 배속 | 최저 스텝 배속 | 초기 스텝 포함 배속 | 관측 private 최대 | 결과 |
|---|---:|---:|---:|---:|---|
| 자유낙하 | 9.739e-09 | 5.449e-09 | 9.214e-09 | 4.08GiB | 6스텝 완료 |
| 밀집 접촉 | 8.044e-09 | 7.087e-09 | 6.341e-09 | 6.36GiB | 6스텝 완료 |

밀집 조건의 최초 3,200만 후보 상한 시도는 `spatial candidate capacity exceeded`로 중단됐다. 당시 관측 private는 약 3.22GiB였다. 8GiB 시험 예산 내에서 후보 상한을 6,400만으로 늘린 재시험이 통과했다. 초기 거부 기록도 보존했다.

RAM 약 31.85GiB, CPU i7-14700KF(20코어/28논리 스레드), MSVC Release `/fp:strict`에서 측정했다. 목표 시험 직전 가용 RAM 약 15.63GiB였다. `private bytes`는 프로세스 커밋 메모리 관측값이며 전체 시스템 RAM·가상 주소 예약량과 같지 않다. 모니터는 50ms 간격이므로 아주 짧은 peak를 놓칠 수 있다. 프로세스 자체 peak working set도 원자료에 저장했다.

현재 GPU는 RTX 4060 Ti, 보고된 VRAM 총 16380MiB/조회 시 가용 12947MiB다. **GPU 해석 성능은 측정하지 않았다.** CPU 자료의 메모리 크기를 GPU에 그대로 대입해 수용 가능하다고 판단하지 않는다.

## 정확도와 기존 기능 회귀

실행 전에 고정한 허용 기준: 자유낙하 위치 잔차 <1e-12m; 운동량 잔차 <1e-12 + 상대 1e-9; 질량 잔차 <1e-10kg + 상대 1e-10; 최대 겹침/반지름 <0.01. 원자료에 모든 측정값을 남겼다.

36회 행렬의 동일 조건에서 상태 FNV64 지문과 질량·운동에너지·접촉 수·이력 수·겹침·오차 지표가 스레드 수 및 반복 간 동일했다. 지문은 회귀 검사용이며 모든 상태를 수학적으로 증명하는 수단은 아니다. 별도로 128개 입자에서 전체 직렬/병렬/전수 탐색 상태 문자열의 일치를 검사했다.

밀집 1천/1만/10만 입자는 공통 시각 2e-7s에서 dt=20ns 10스텝과 dt=10ns 20스텝을 비교했다. 사전 기준은 위치 차이 ≤1e-12m, 속도 차이 ≤1e-9m/s + 최대 속도의 0.001, 운동에너지 상대 차이 ≤0.005, 질량·접촉/이력 수 동일이다.

| 입자 수 | 최대 위치 차이(m) | 최대 속도 차이(m/s) | 운동에너지 상대 차이 |
|---:|---:|---:|---:|
| 1,000 | 3.418e-14 | 4.405e-13 | 9.749e-08 |
| 10,000 | 3.418e-14 | 1.586e-11 | 9.670e-08 |
| 100,000 | 3.418e-14 | 1.586e-11 | 4.824e-08 |

Core 33개에는 기본 상한, 명시적 대량 상한, 후보 초과, 전수 탐색 fallback 상한, 캐시 상한 감소, 실패 원자성과 복구, 수렴 검사가 포함된다. Unreal 15개로 기존 리셋/워커/내보내기/병렬 설정을 회귀 검증했다.

이 시험은 가상 입자의 **짧은 수치 검증**이다. 실분말의 실제 물성, 비구형·응집·공기 영향, 장시간 배출·체류·혼합·가동 벽의 대량 정확도를 인수한 결과가 아니다. 짧은 구간에서 에너지가 작거나 보존 오차가 작다는 이유로 전체 물리 모델의 현실성을 주장하지 않는다.

## 병목과 다음 경로 결정

10만 밀집/8스레드의 단계별 중앙 시간 합 기준, 준비·검증이 약 35%, 쌍 탐색/힘 평가 약 30%, 상태 반영 약 15%, 적분 약 6%다. 적분만 GPU로 옮기거나 스레드 수만 늘리는 것으로 전체 병목이 사라지지 않는다. 벽/공정 비용이 없는 이 시험에서도 목표에 크게 미달했다.

1. 현재 CPU 경로는 **실입자 기준 해석·회귀 비교용**으로 유지한다. 이번에 큰 계산이 실행된 사실을 목표 성능 달성으로 취급하지 않는다.
2. **최적화 11을 다음으로 선택한다.** 실입경·계산 입경·대표 개수·질량·원료 그룹의 계약과 축약비 1 회복을 먼저 정의한다. 성능 차이만 보고 큰 축약비를 즉시 채택하지 않는다. 틈 통과/막힘/분리에는 별도의 적용 제한이 필요하다.
3. **12~13에서 정확도와 비용을 측정한 뒤 14~16의 GPU 경로를 평가한다.** 배열 저장, 이웃 후보/접촉 이력, 오류 검사, 준비·상태 반영까지 포함한 메모리/API 계약이 필요하다. VRAM 보유나 CUDA 사용 자체를 목표 달성으로 보지 않는다.
4. 어떤 축약/GPU 경로도 검증을 통과하지 못하면 목표 조건/물리 모델의 추가 분할을 계획에 기록한다. 현재 자료만으로 원료 조합의 혼합 품질을 예측하지 않는다.

## 재현

```powershell
cmake --build Intermediate/PowderCore --config Release --parallel 8
ctest --test-dir Intermediate/PowderCore -C Release --output-on-failure
python -B Scripts/run_optimization10_validation.py --output Saved/Optimization10_new
python -B Scripts/run_optimization10_target.py --output Saved/Optimization10_target_new
python -B Scripts/run_optimization10_target.py --output Saved/Optimization10_target_dense_new --dense-only --candidate-budget 64000000
```

새 출력 디렉터리가 필요하다. 대상 장비에 충분한 RAM이 있을 때 목표 스모크를 실행한다. 각 감독 스크립트는 자기 계산 프로세스에 자원 제한을 적용한다. 대량 메모리의 관측/종료는 Windows에서 검사했다.

원자료는 `Docs/DEM/optimization10/`의 `acceptance.json`, 행렬 `report.json`, `samples.json`, `contract.json`, `convergence_*.json`, 목표별 `report.json`, 하드웨어/테스트 로그다. 행렬의 `target_total`은 별도 목표 시험 이전의 4GiB/4M 후보 **초기 검토**이며, 최종 실제 실행 결과는 `acceptance.json`을 따른다.

행렬 실행 후 목표 시험용 선택 인자를 추가했으므로 행렬/목표 실행 파일 해시는 구분한다. 원 행렬 소스와 해시는 보존했다. 최종 소스 목록/해시는 `tested_manifest.json`, 소스 묶음은 `optimization10_sources.zip`에 기록한다. 기존 기준 실행 파일은 로컬 `Saved/Optimization10_before/powder_opt01.exe`에 보관했다.
