# 작업 23 — 입자 없는 공기 유동 계산

상태: 완료 (2026-10-22). FlowCore `0.2.0`, 작업 22의 제한된 입력 계약을 사용하는 자체 공기 해석기다. 상용 해석기나 녹화 재생을 사용하지 않으며, 각 물리 시간 단계의 속도·압력을 직접 계산한다. **입자 항력·양방향 연성·Unreal 표시·실제 진공 관로는 이번 범위가 아니다.**

## 1. 구현 범위

`Physics/FlowCore/include/flow/solver.hpp`, `src/solver.cpp`에 다음을 구현했다.

- 2차원 MAC 격자의 비압축성·등온·층류 Navier–Stokes 시간 적분.
- 보존형 1차 donor-cell 대류 플럭스, 2차 중앙 점성 차분, 명시적 Euler 예측 속도.
- 비증분 압력 투영: `u*=uⁿ+dt[−div(uu)+ν lap(u)]`, `−lap(π)=−ρ div(u*)/dt`, `uⁿ⁺¹=u*−dt grad(π)/ρ`.
- 행렬 비저장 Jacobi 전처리 CG 압력 계산. 재귀 잔차뿐 아니라 실제 `b−Aπ` 잔차를 확인하며, 100회마다 잔차를 재구성하고 방향을 재시작한다.
- 압력 입구/출구 또는 속도 입구/압력 출구, 정지 no-slip 상하 벽. 압력 Dirichlet은 면까지 반 셀 거리, 벽 속도는 반대 부호 유령값을 사용한다. 속도 입구는 작업 22의 면 평균 포물선 유량을 유지한다.
- 무구동·압력 구동·속도 구동 초기 과도와 정상상태 접근 계산. 공기는 중력 없이 계산하며 고체·에너지식·난류 모델은 없다.

압력은 수치 계산 중 출구압을 뺀 값으로 풀고, 속도 보정이 끝난 뒤 사용자의 압력 기준으로 복원한다. 큰 공통 압력 오프셋이 작은 압력 기울기 계산에 섞이는 것을 줄인다.

`advance(contract, fields)`는 임시 상태에서 계산한다. 압력 수렴, 필드 범위, 발산, 질량 수지를 모두 통과한 뒤에만 필드와 물리 시계를 갱신한다. 실패 시 마지막 수락 상태가 유지된다. 시간 단계 건너뛰기, 비물리적 값 자르기, 실패한 단계를 성공으로 처리하는 기능은 없다. 실행 요청 시간을 넘긴 추가 진행도 거부한다.

## 2. 적용 범위와 수락 기준

작업 22의 평행판·SI·절대압·속도 상한·격자·시간 간격 제한을 유지한다. 근대기압, 일정 온도 293.15 K, 보수적 Reynolds 상한 100이다. **입력 허용 범위 전체를 실측으로 검증한 것은 아니다.** 이번 검증은 아래에 명시한 기준 문제와 격자·시간 간격에 한정된다. 적합한 입력이어도 압력 반복 한도나 수치 수락 기준을 만족하지 못하면 실패할 수 있다.

기본 수락 기준:

- Poisson 실제 잔차 `||b−Aπ||∞ ≤ max(1e−7 Pa/m², 1e−8 ||b||∞)`.
- 투영 후 발산 L∞ ≤ `1e−7 s⁻¹`.
- `|ṁ_in−ṁ_out|/max(|ṁ_in|,|ṁ_out|,1e−12 kg/s) ≤ 1e−8`.
- 작업 22의 필드 유한성·압력 범위·속도 상한·벽 비투과·입구 유량·역류 금지·물리 시계 검사 통과.

구현은 연속식 수락 기준을 위해 Poisson 잔차를 더 엄격하게 제한한다. 예측 경계 유량과 압력 가속으로 추정한 유량 크기 `F`, 영역 부피 `V`를 사용하여 `cap=0.05 min(div_tol ρ/dt, mass_tol F/(dt V))`를 적용한다. 최종 유량·발산은 실제 투영 결과로 다시 검사한다. 고정된 매우 작은 잔차값만 요구하면 속도 입구를 갑자기 켜는 큰 우변에서 부동소수점 정밀도 때문에 반복이 끝나지 않는 문제가 있어, 물리 수락 기준에 연결해 수정했다.

전단 점성과 Poisson의 공간 수렴은 2차를 확인했지만, 일반 대류는 1차 donor-cell이다. 전체 유동 계산을 모든 조건에서 2차 정확도라고 부르지 않는다. 에너지 출력은 셀 중심 보간 속도로 계산한 진단용 운동에너지이며, 정확한 이산 에너지 보존을 입증하는 지표가 아니다. 속도 최대값은 벡터 크기가 아니라 **성분 절대값 최대**다.

## 3. 독립 검증과 측정 결과

기본 채널은 L=0.1 m, H=0.01 m, 보고용 깊이 1 m, Δp≈0.004344 Pa, 해석해 평균 속도 약 0.02 m/s다. 질량 유량은 보고용 깊이에 비례한다. 깊이를 3차원 벽으로 해석하지 않는다.

평행판 해석해 `u(y)=Δp y(H−y)/(2μL)`를 사용했다. 원문 기준: [NETL의 평행판 Poiseuille 검증 문제](https://mfix.netl.doe.gov/doc/vvuq-manual/main/html/fluid/fld-01.html). 해당 자료의 해석해만 참고했으며 외부 해석기를 실행하지 않았다. 우리 입출구 경계는 그 자료의 주기 경계와 다르다.

| 검증 | 측정 결과 | 기준 |
|---|---:|---|
| 정지·동일 입출구 압력 | 속도 0 유지 | 정확히 0 |
| 정상 속도 상대 L2, 32×8 | 2.13927% | 수렴 추적 |
| 정상 속도 상대 L2, 64×16 | 0.534848% | 수렴 추적 |
| 정상 속도 상대 L2, 128×32 | 0.133689% | 1% 이내 |
| 정상 속도 격자 오차비 | 3.99978, 4.00070 | 3–5 |
| 2D 제조해 Poisson, 양쪽 압력, 최세격자 | 0.210213% | 1% 이내 |
| 2D 제조해 Poisson, 혼합 경계, 최세격자 | 0.321696% | 1% 이내 |

| 속도 입구 조건의 출구 부근 압력 기울기 | 상대 오차 0.774690% | 1% 이내 |
| 비영 횡방향 속도 교란의 투영 | 발산 약 8.45e−11 s⁻¹ | 1e−7 이하 |
| 압력에 공통 100 Pa를 더한 시험 | 속도 차이 약 3.47e−18 m/s | 1e−10 이하 |

정상 속도는 휴지 상태에서 10초를 직접 적분하고 dt=0.0005 s, 격자 32×8·64×16·128×32를 비교했다. 압력은 선형 해석해와 비교했다. 유동장은 해석해를 복사하여 결과로 사용하는 방식이 아니다.

Poisson 제조해는 x/y에 동시에 변하는 삼각함수와 독립적으로 미분한 소스항을 사용했다. 양쪽 압력 Dirichlet과 입구 Neumann/출구 Dirichlet을 각각 검사한다.

과도 급수는 작업 22에 기록한 홀수 Fourier 급수를 200 미만 홀수 항으로 계산한다. t=0.1 s의 지수 감쇠에서는 마지막 항의 기여가 부동소수점 정밀도보다 훨씬 작다. 시간 수렴은 64×32 고정 격자에서 dt=0.0005·0.00025·0.000125 s를 비교했다. 연속 해석해 오차에는 공간 오차도 남으므로, Euler 차수는 연속 두 시간 간격 결과의 차이 비율로 구분했다. 공간 오차가 남은 총 오차가 두 배씩 감소한다고 주장하지 않는다.

속도 입구는 지정 평균 유량과 면 유량 적분이 일치하는지 확인하고, 1초 계산 후 출구 부근 압력 기울기를 비교했다. 입구에서는 면 평균 포물선을 사용하므로 유한 격자에서 점값 해석해와 완전히 같지 않다.

그 외 검증: 비영 v 교란에서 실제 2D 투영과 운동량 갱신, 같은 초기 상태의 정확 재현, 압력 반복 1회 제한 실패 시 상태·시각 보존, 잘못된 벽 속도 거부, 요청 시간 초과 거부, 결과 폴더 덮어쓰기 거부, 적용 밖 진공 입력 거부를 포함한다. 이것이 복잡한 2D 와류·실제 관로의 검증 완료를 뜻하지 않는다.

## 4. 실행과 저장 결과

프로젝트 루트에서:

```powershell
python Scripts/run_flow_solver_validation.py --output Saved/Flow_task23_new_check
& ./Intermediate/FlowCore/Release/flow_run.exe Physics/FlowCore/fixtures/pressure_channel.flow Saved/MyAirRun
```

출력 폴더는 새 경로여야 하며 부모 폴더는 존재해야 한다. 스크립트는 현재 설치된 Visual Studio 2022 Community의 CMake를 사용한다. Release 빌드, `/W4 /WX /fp:strict`로 검사했다.

`flow_run`의 출력:

- `input.flow`: 실제 사용한 입력의 정규 직렬화.
- `contract.json`: 입력 검증과 해석해 추정. `flow_evolved:false`로 실제 계산 결과와 구분한다.
- `history.csv`: 수락한 **매 단계**의 물리 시각, 압력 반복 수·잔차, 발산, 입출구 질량 유량·수지, 최대 속도 성분, 운동에너지.
- `last_accepted_fields.csv`: MAC 위치별 압력 게이지값(Pa), u/v(m/s)의 마지막 수락 필드. 초기 단계 실패라면 시각 0의 초기 상태다.
- `result.json`: 계산 성공 여부, 수락/요청 단계 수, 물리 시간, 실제 계산 시간, 최대 오차 지표, 실패 원인. `result_kind:computed_air_only_MAC_fields`로 구분한다.

종료 코드 0은 요청한 시간까지 수락 완료, 2는 입력·파일 처리 오류, 3은 계산 실패다. 계산 실패 시 마지막 상태와 실패 이유를 남긴다. 파일 시스템 오류에서는 결과 파일 작성 자체가 실패할 수 있으므로 종료 코드도 확인해야 한다. 부분 실행 파일을 성공 결과로 간주하지 않는다.

기존 `flow_contract`는 여전히 입력 검증 전용이다. 모듈에 해석기가 존재하므로 `solver_implemented:true`, 해당 출력은 계산하지 않았으므로 `flow_evolved:false`를 함께 기록한다. 기존 작업 22 보고서는 당시 버전의 기록으로 보존했다. `run_flow_contract_validation.py`는 계약 시험 두 묶음만 선택하도록 수정했다.

## 5. 최종 반복 검증 기록

실행 위치: `Saved/Flow_task23_validation`. 계약 C++·계약 CLI·해석기 수치·실행 CLI의 네 CTest 묶음을 각각 두 번 통과했다. 압력 구동·속도 구동·무구동 fixture는 각각 5초, 10000단계를 두 번 계산했다. 계산 소요 시간을 제외한 수치 지표 CSV·유동장·전체 단계 이력·입력·계약 출력이 바이트 단위로 일치했다. 실행 전후 소스 SHA-256도 같았다.

첫 5초 실행의 실제 계산 시간은 압력 구동 약 0.65초, 속도 구동 약 22.24초였다. 속도 구동은 초기 과도와 공간적인 압력 교정 때문에 반복 계산 비용이 더 컸다. 이 실행에서 최대 발산은 약 1.00e−10 s⁻¹, 최대 상대 질량 수지 오차는 약 1.49e−10으로 설정 기준을 통과했다. 향후 성능 개선은 이번 기준판과 비교해야 한다.

최종 PASS 여부와 정확한 소스 해시·실행 시간·수지는 `Docs/DEM/task23/report.json`과 `report.md`, `numerical_metrics_*.csv`에 보관한다. 전체 유동장과 매 단계 이력은 Saved 아래에 남긴다. 보고서의 계산 비용은 이 컴퓨터·이번 실행의 측정이며 고정 실시간 성능 목표가 아니다.

## 6. 남은 제한과 다음 작업

기존 DEM/Unreal 소스·레벨은 수정하지 않았고 에디터를 재빌드하거나 재실행하지 않았다. 따라서 현재 언리얼 화면에 공기 흐름이 나타나지 않는 것이 정상이다. 이번 검증을 DEM 회귀 시험이나 Unreal 통합 시험 통과로 확대하여 해석하지 않는다.

다음 **작업 24 — 공기에서 입자로의 힘 전달**을 시작할 수 있다. 유동장 보간, 항력 모델의 적용 범위, 입도와 격자 크기, 연성 시계부터 정한다. 기존 40 mm 혼합 시험 입자를 10 mm 간격 채널에 그대로 넣지 않는다. 실제 −35 kPa(g) 진공과 3차원 원형·굽은 관로는 작업 22-E1/E2/E3의 별도 확대가 필요하다.
