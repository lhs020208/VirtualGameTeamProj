# 작업 11 — 입자 추적·통과 판정·보존 검증

상태: 완료 (2026-10-21). 자체 DEM 작업 10에 이어 구현했다. 브랜치 `PowderSimulation`. 커밋·푸시는 하지 않았다.

## 구현 범위와 판정 계약

`Tracker`는 고유 입자 ID를 키로 현재 위치, 질량, 현재 영역에 들어온 단계 시간, 관 진입·배출 시간과 방향별 측정면 횡단 이력을 기록한다. 입자 배열 순서가 바뀌어도 ID를 따라간다. 실행 중 ID 집합·입자 수·질량이 변하거나 시간이 역행하면 오류로 중단한다. 공급으로 입자가 추가되는 경우는 작업 13에서 별도로 확장한다.

현재 위치는 중심 좌표 기준으로 **공급부(깔때기 포함) / 관 / 수집부 / 외부** 중 하나다. 관, 수집부, 공급부 순으로 판정하므로 영역이 겹쳐도 중복 집계하지 않는다. 관은 `bottom < 축 좌표 <= top`이며 입구 경계는 관에 속한다. 관과 수집부 사이 낙하 공간도 외부다. 외부는 입자 삭제나 장비 밖으로 영구 유출됐다는 뜻이 아니다.

각 영역의 수와 질량, 전체 수와 질량, 영역 질량 합계와 초기 질량의 차이를 제공한다. 과거 통과한 입자도 현재 위치 집계에 계속 포함된다. 현재 위치 합계를 누적 진입·통과 수에 더하지 않는다.

통과 기준은 **입자 중심이 실제 개구부 내부에서 측정면을 횡단하는 것**이다. 구 전체가 개구부에 맞는지 검사하는 여유 공간 판정과 구별한다. 입자–벽 충돌은 기존 DEM이 계산하며, 통과 집계가 충돌·관통 검증을 대체하지 않는다.

- 입구 하향, 출구 하향, 출구 상향, 입구 상향의 네 사건을 각각 기록한다.
- 입구 하향 진입으로 시작한 경로가 출구 하향을 통과해야 완료 통과로 집계한다.
- 관 측면으로 벗어나면 그 진입 자격을 취소한다. 측면에서 다시 들어온 입자가 바로 출구를 넘어도 완전 통과로 보정하지 않는다.
- 처음부터 관 안에 있는 입자는 입구 진입 이력이 없다. 배출 사건은 기록하지만 완전 통과로 세지 않는다.
- 고유 진입·통과·상류 복귀 입자 수와 반복 통과·복귀 사건 수를 분리한다. 재진입한 같은 ID는 고유 통과 수를 늘리지 않는다.
- `first_entry_s/last_entry_s`는 입구 하향, `first_exit_s/last_exit_s`는 출구 하향 시각이다. 출구 시각만 있다고 완전 통과한 것은 아니며 사건의 `completed_passage` 또는 `ever_passed`로 확인한다. 미발생 시각은 -1이다.
- 사건 시각은 **완료된 물리 단계의 전후 위치를 잇는 선분과 측정면의 교점**을 물리 시간으로 보간한다. 두 면을 한 단계에 넘어도 시간순으로 처리한다. 화면 프레임·현실 시간을 사용하지 않는다.
- 현재 영역의 `location_since_s`는 해당 상태를 처음 관측한 물리 단계 끝 시간이다. 영역 이동 시각 전체를 연속 해석한 값은 아니다.

## 시험장 형상 연결

초기화(R) 시 게임 스레드에서 읽은 동일한 상자 형상을 충돌과 추적 양쪽에 전달한다. 코어는 공급 벽·깔때기·관 벽·수집부 그룹의 내부 면과 끝 위치로 측정 영역을 구성한다. 현재 관 입구/출구는 벽에서 계산한 3.6m / 2.4m이며 고정 높이 상수가 아니다.

현재 53개 직선 시험장의 축, 이동·회전·크기를 반영한다. 시험장 전체의 강체 변환을 검사했다. 관 벽은 공통 축과 같은 끝면을 가져야 하며, 잘못된/불완전한 그룹, 닫히지 않은 방향 집합, 잘못된 수집부 형상은 오류로 거부한다. 임의로 비틀어진 관, 곡관, 임의 메시의 내부 영역 추정은 지원하지 않는다. 벽 이음부의 유한한 틈과 실제 충돌은 기존 기하 해석의 대상이다.

Unreal은 `PowderTube`, `PowderFeed`, `PowderFunnel`, `PowderCollector` 태그를 사용한다. 기존 레벨의 공급부·깔때기·수집부는 에디터 액터 이름(`Feed_Wall_`, `Feed_Funnel_`, `Collector_`)으로도 연결한다. 시험장 재생성 스크립트에는 태그를 추가했다. 이번 작업에서 레벨을 재생성하거나 저장하지 않았다. 현재 레벨을 패키징할 때에는 이름 대체 경로에 의존하지 않도록 태그를 저장하는 후속 준비가 필요하다.

어떤 그룹도 없는 단순 바닥 시험은 추적 OFF를 명시한다. 일부 그룹만 있는 잘못된 시험장은 조용히 고정 좌표로 대체하지 않는다. 형상 수정은 R 또는 Play 재시작 이후 반영되며, 한 실행 중 벽은 정적이다.

## 계산·화면 연결

계산 스레드가 성공한 **모든 물리 단계**에서 추적기를 갱신하고, 해당 물리 상태와 같은 불변 스냅샷에 결과를 넣는다. 8단계마다 화면에 전달하더라도 중간 통과 사건은 누락하지 않는다. 초기화는 세대 ID와 함께 모든 추적 이력을 지운다. 이미 전달된 과거 스냅샷은 변경되지 않는다.

HUD에 네 위치의 현재 수량, 전체 수량, 고유 진입/통과/복귀 수, 반복 통과 수, 총질량·보존 오차를 표시한다. `InspectParticleId`로 확인할 ID를 지정할 수 있으며 Blueprint의 `ParticleTracking(Id)`로 해당 ID의 상태·첫 진입/배출 시각·사건 수를 조회한다. 전체 사건 데이터는 코어 `TrackingSummary.records`에 보존한다.

기본 300개, 지름 0.04m, 밀도 2500kg/m³, dt=2e-7s 조건은 유지한다. 초기 총질량은 약 25.132741kg이다. 카메라와 Space/N/R 조작도 유지한다.

## 300개 / 298개 조사

보존된 `Saved/Logs/VirtualGameTeamProj-backup-2026.10.21-10.04.19.log`의 UTC 08:33:05.485 기록은 다음과 같다.

```text
PowderDrop CHECK: t=8.07 count=300 moving=0 escaped=0 ...
PowderTube CHECK: entered=298 passed=298 inside=0 returned=0 ... rate=100.0%
```

이는 입자 수 자체의 손실 증거가 아니다. 이전 통과율의 분모도 전체 300이 아니라 감지된 진입 298이다. 당시 ID별 경로가 저장되지 않아 두 입자가 실제로 우회했는지, 측정 조건에서 누락됐는지 확정할 수 없다.

기존 `PowderDropTest.cpp`는 고정 관 위치·높이를 사용하고, 진입면을 반지름만큼 내린 뒤 모든 벽 방향에 대해 `중심의 반경 투영 <= 12cm - 3cm + 0.15cm`를 요구한다. 새 중심 횡단 조건과 다른 정의다. 예를 들어 중심 x=9.5cm인 경로는 관 중심 영역 안에 있지만 기존 여유 조건 9.15cm 밖이다.

재현 가능한 **진단용 선분 경로 시험**에서 298개는 중심 경로, 2개는 위 경계 경로로 배치했다. 이전 반경 조건은 298, 새 중심 횡단 검사는 300을 기록한다. 이는 해당 조건이 누락을 만들 수 있다는 반례이며 당시 Chaos 실행을 재현한 결과가 아니다. 이 경계 경로에는 벽과 구의 겹침이 있을 수 있으므로 물리적으로 유효한 자유 낙하 결과로 해석하면 안 된다.

별도 시험에서 개구부 바깥 경로와 측면 우회는 완전 통과로 세지 않는다. 집계를 무조건 300으로 맞추는 보정은 없다. **역사적 두 입자의 정확한 원인은 미확정**으로 남긴다.

## 검증 기준과 결과

시험 작성 시 정한 허용 오차: 개수·고유 ID·사건 수는 정확히 일치, 질량 수지는 1e-10kg 이하, 선형 경로 시각은 1e-12s 이하, 내보낸/변환한 실제 형상과 시각은 1e-10 SI 이하다. 이 수치는 수치 비교 허용값이며 측정면을 임의로 넓히는 보정값이 아니다.

- Release CMake 빌드 및 CTest **10/10 통과**, 최종 전체 실행 41.40초.
- CLI 설정/JSON/오류 입력, 자유 운동 수렴, 평면 충돌·평형 Python 회귀 검사 통과.
- 추적: 4영역 분할과 서로 다른 질량, ID 순서 변경, ID·수량·질량 변경 거부, 시간 역행 거부, 양 측정면 빠른 횡단, 정확히 경계에서 끝나는 단계, 역류·재진입, 측면 이탈, 관 안 초기화, 개구부 바깥 우회, 초기화, 불변 스냅샷을 검사했다.
- 하나의 선형 경로를 1단계/30단계로 나눠도 횟수와 교점 시각이 일치한다.
- 실제 53개 형상과 300개 초기 입자는 전부 공급부로 분류되고 수량·질량 수지가 맞는다. 90도 회전·이동한 시험장에서도 교점 시각이 일치한다.
- 계산 스레드에서 두 면을 한 단계에 넘는 시험과 초기화 후 이력 삭제를 확인했다.

Unreal Development Editor 빌드 성공. `Powder.DEM.BackgroundBridge`, `Powder.DEM.TrackingBridge` **2/2 Success, 검사 경고 0, 실패 0**이다. 최종 보고서는 `Saved/DEM_task11_automation/index.json`, 로그는 `Saved/Logs/DEM_task11_automation.log`에 있다. 53개 도형을 실제 액터로 만든 뒤 네 영역의 분류, 이동·회전 후 R에 의한 영역 갱신, 300개 수량·질량 보존, ID 조회, 실제 BeginPlay/EndPlay를 통한 계산 스레드 해제를 검사했다.

최종 자동 실행에서 새 스냅샷 81개를 받아 표시했고 최대 액터 Tick은 약 3.20ms였다. 이는 특정 시험의 액터 갱신 측정이며 전체 화면 FPS나 300개 물리 계산 속도를 보장하지 않는다.

실제 L_Main Play에서도 공급부 300 / 관 0 / 수집부 0 / 외부 0, 총질량 25.132741kg, 수지 오차 0kg을 확인했다. Space 실행, 실행 중 R로 Run 2와 단계 0 복원, N으로 단계 1 및 물리 시간 0.000000200초, F 카메라 초점을 확인했다. 최종 에디터는 이 한 단계 진행 후 일시정지 상태로 열어 두었다.

검증 과정에서 자동 시험 월드의 컨텍스트와 액터 초기화가 생략돼 실제 종료 경로를 검사하지 못하던 문제가 드러났다. 월드 컨텍스트·InitializeActorsForPlay·DispatchBeginPlay를 설정하고 Destroy 성공과 EndPlay의 작업자 해제를 직접 검사하도록 고쳤다. 초기화된 월드에서는 Static 벽을 옮길 수 없으므로 재배치 시험에서만 이동성을 잠시 설정하고 변환 적용 성공을 확인했다. 제품의 벽 운동 기능을 추가한 것은 아니다.
