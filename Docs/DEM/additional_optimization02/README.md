# 추가 최적화 02 — GPU 단계별 계측

## 사용법

기본 실행은 기존 fused 커널을 사용하며 GPU 이벤트 계측은 꺼져 있다.

- `-GrainProfile`: 기존 커널의 OpenCL 이벤트 START/END 시간 측정.
- `-GrainProfileSplit`: 진단용으로 입자 접촉과 경계 투영, 속도 갱신과 경계 접촉 탐지를 분리한다. 자동으로 GPU 계측을 켠다.
- 종료 또는 Reset 시 해당 실행의 `Saved/Granular_...`에 `timing.json`, `worker_timing.json`, `display_timing.json`을 저장한다. 비정상 종료 시 완전한 기록은 보장하지 않는다.
- 현재 장면 비교: 에디터 종료 후 `python -B Scripts/run_additional_optimization02.py --run`. 기본값은 각 모드 12초 시뮬레이션 2회, 순차 실행이며 두 번째 반복은 역순이다.

CLI `granular_run`의 기존 인수 뒤에 `profile_split`을 추가했다:
`count duration output [iterations dt rpm gate_time radius fast_bounds profile test_mixer friction history profile_split]`.
분리 진단은 `profile=1`이 필요하다.

## 시간 해석

`timing.json` schema 2의 GPU 초는 OpenCL 이벤트 시간이며 CPU 벽시계 시간과 구분한다.

| 항목 | 의미 |
|---|---|
| grid_clear / grid_build | 연결 리스트 격자 초기화 / 구축 |
| predict | 중력 및 위치 예측 |
| contact_and_boundary | 기본 fused 입자 접촉 + 경계 투영 |
| velocity_and_boundary_probe | 기본 fused 속도 갱신 + 경계 접촉 탐지 |
| particle_contact / boundary_projection | 분리 진단의 입자 접촉 / 경계 투영 |
| velocity / boundary_probe | 분리 진단의 속도 갱신 / 경계 접촉 탐지 |
| snapshot_readback | 입자 위치 GPU→CPU 읽기 이벤트 |
| submit_wall_s | CPU 인수 설정·명령 제출; GPU 실행과 겹칠 수 있음 |
| guard_wait_wall_s | 배치 안전 검사 읽기에서 기다린 CPU 시간; GPU 실행 포함 |
| profile_collect_wall_s | 이벤트 시간 조회·해제 CPU 비용; snapshot에도 포함될 수 있음 |
| advance_wall_s | advance 전체, 제출·대기·이벤트 수집 포함 |
| snapshot_wall_s | 배열 할당·동기 읽기·이벤트 수집 포함 |

`*_calls`는 계측 이벤트 횟수이며 GPU 계측 OFF일 때 0이다(미실행이라는 뜻이 아님).
GPU 이벤트 합계와 CPU 벽시계 시간은 **중복되므로 더하지 않는다**.
분리 진단에는 추가 커널 실행 및 전역 메모리 읽기/쓰기 비용이 있다. 분리 수치를 기본 fused 커널 내부의 정확한 원가로 간주하지 않는다.
기본 경로는 분리용 버퍼를 할당하거나 추가 커널을 실행하지 않는다.

`worker_timing.json`은 통계 계산·파일 기록·상태 게시(잠금 포함)의 CPU 벽시계 시간을 기록한다.
`display_timing.json`은 새 상태 표시 시 복사/잠금, 좌표 변환, ISM 표시 요청의 CPU 시간을 기록한다.
ISM 비용은 생성기의 배열 복사·스케일 지정·렌더 명령 제출을 포함한다. **렌더 스레드 및 그래픽 GPU 프레임 비용을 측정한 값은 아니다.**
가벼운 CPU 시간 카운터는 OFF 비교에서도 활성화되어 있으므로 OFF/ON 비교는 GPU 이벤트 계측의 추가 비용을 뜻한다.

## 계산 유지와 검증 범위

중력·마찰·반지름·입자 수·시간 간격·반복 수·경계 형상 및 투영 순서는 유지한다.
진단 모드는 중간값을 GPU 메모리에 저장하므로 부동소수점 반올림 및 병렬 이웃 순서 차이로 장시간 입자별 궤적이 완전히 같다고 보장하지 않는다.
소규모 시험은 궤적 차이 2μm 이내, 이벤트 횟수, 시간 집계, Reset, 잘못된 진단 설정 거부를 검사한다.
5만 개 시험은 초기 데이터 SHA, 입자 수/그룹/질량/유한값, 마지막 스냅샷의 최대 겹침 및 벽·날개 침투를 검사한다.
최종 스냅샷 검사는 모든 중간 시각의 침투 부재나 실제 분말 정확도를 인증하지 않는다.



측정 장비: NVIDIA GeForce RTX 4060 Ti 16GB, 드라이버 610.88. 동일 프로세스 안의 물리 계산과 언리얼 렌더링이 GPU를 공유한다.
## 2026-10-27 측정 결과

MX301 테스트 레벨, 50,000개, 64.8kg, dt=0.000375s, 접촉 16회, 배치 32, 요청 속도 2배속. 1280×720, 최대 30fps. 각 모드 12초 시뮬레이션 2회.

| 모드 | 실측 배속 범위 | 중앙값 | OFF 대비 소요시간 증가 추정 |
|---|---:|---:|---:|
| OFF (기본) | 0.184–0.196 | 0.190 | 기준 |
| 이벤트 계측 ON | 0.163–0.175 | 0.169 | 약 12.3% |
| 분리 진단 | 0.140–0.142 | 0.141 | 약 34.9% |

소요시간 증가는 배속 중앙값의 역비로 계산했다. 반복이 2회뿐이고 실행 간 변동이 있어 정밀한 계측 오버헤드의 확정값이 아니다. OFF에도 경량 CPU 타이머가 포함되어 있다. 이전 커밋 대비 성능 개선을 주장하는 결과가 아니다.

GPU 이벤트 총시간을 두 반복에 걸쳐 합산한 비중:

| 단계 | 기본 경로 계측 | 분리 진단 |
|---|---:|---:|
| 격자 초기화+구축 | 15.92% | 12.94% |
| 입자 접촉+경계 투영 | 82.37% | — |
| 입자 접촉 | — | 71.75% |
| 경계 투영+속도용 경계 탐지 | — | 14.03% |
| 위치 예측 | 0.44% | 0.76% |
| 속도 갱신 (기본 경로는 경계 탐지 포함) | 1.20% | 0.46% |
| 위치 읽기 전송 | 0.09% | 0.07% |

기본 첫 실행의 CPU 표시 누계는 874회 갱신 동안 복사/잠금 0.054s, 좌표 변환 0.276s, ISM 제출 1.352s였다. 계산과 표시 스레드가 겹치므로 이 값을 solver 시간에 단순 합산하지 않는다.

다음 작업 03–04는 이웃 후보 목록 구축·안전 재사용을 우선한다. 후보 목록으로 격자 재구축 및 반복 접촉 탐색을 줄일 여지가 크다. 이동·위치 보정으로 새로 생기는 접촉을 누락하지 않는 검증이 필요하다. 경계 후보 축소는 이후 작업 05에서 진행한다. 아직 어떤 후보도 생략하거나 물성/시간 간격을 바꾸지 않았다.
