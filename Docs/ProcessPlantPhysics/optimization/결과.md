# 설비 최적화 결과 (2026-10-30)

작업 01~04 완료. 기존 물리 조건을 유지하는 threaded BVH 탐색만 실행에 채택했다.
0.1배속 달성은 아니다. 잔류 제거를 위한 물리 변경이나 장시간 공정 재시험은 하지 않았다.

## 같은 조건의 전후 비교

3만 개(색상별 1만), 반지름 1.25mm, dt 10µs, 접촉 반복 8회, RPM15,
시험 압력차 1000Pa. 워밍업32스텝 후 320스텝, 기준/개선 교대로 각3회.
같은 유휴 에디터 상태, 같은 저장 입자 위치·속도, profiling ON. 컴파일·초기화 제외.

| 상태 | 기준 실행시간 중앙값 | 개선 실행시간 중앙값 | 처리속도 개선 | 개선 후 실제 배속 |
|---|---:|---:|---:|---:|
| 초기 낙하 | 0.2497s | 0.2302s | +8.4% | 0.01390x |
| 칭량 호퍼 이송 시작 | 1.4441s | 1.3803s | +4.6% | 0.00232x |
| 수신기 배출 시작 | 0.4071s | 0.3732s | +9.1% | 0.00857x |

이는 각 상태의 짧은 throughput이며 전체 공정 평균/완료시간/30fps 보장이 아니다.
3200스텝 연장에서도 개선을 확인했다(초기 2.478→2.307s, 이송 14.204→13.576s,
수신기 4.042→3.731s). CPU 시간과 GPU batch span은 `results.json`에 별도 기록했다.
이전 단계별 장시간 시험의 평균 속도와 직접 비교하지 않는다.

## 변경과 채택 판단

- 01: `plant_bench` 계측 도구, plant 경로의 진단용 분리 프로파일 허용.
  호퍼 상태에서 벽 projection/probe가 GPU 시간 약88%여서 실제 병목으로 확인.
- 02: 삼각형 AABB/제곱거리 후보를 비교. 제곱거리 접촉 판정은 수치 회귀로 제거.
  AABB는 호퍼 상태 퇴보가 있어 진단 옵션만 남기고 실행에서는 OFF.
- 03: 원본 BVH의 오른쪽 우선 방문 순서를 유지하는 threaded 노드를 생성한다.
  GPU의 입자별 64칸 탐색 스택을 제거하며, 원본 삼각형·접촉 순서는 유지한다.
- 04: `PowderPlantTest`에서 `plant_threaded=true` 적용. 기존 경로는 비교용으로 유지.
  레벨/모델/재료/입자 수/시간 간격/접촉 횟수/항력/밸브 운전 조건은 변경하지 않았다.

추가 GPU 형상 메모리: 정확히 2,211,520B(약2.11MiB).
형상 버퍼는 14,876,400B→17,087,920B. 업로드 때 같은 크기의 임시 CPU vector가 필요하다.
이는 코드의 실제 할당 크기이며, 드라이버 포함 전체 프로세스 peak VRAM/RAM 측정치는 아니다.
관측 GPU 온도는 약33~56°C였고 테스트 프로세스는 정상 종료했다.

## 검증

통과:
- 초기/이송/수신기 3200스텝 각각 기준과 개선의 모든 위치·속도·색상 ID가 비트 단위 일치.
- 3만 개와 색상별 1만 개, 유한 수치·안전 검사 유지.
- 전체 BVH 삼각형 순서 일치. 3개 단계×3개 회전각에서 23,895개 경계 샘플의
  보정 위치·법선·벽 속도가 정확히 일치. 압력/단계 갱신 후에도 threaded 자료 유지.
- 기존 압력·기체 포트·최소 결합 회귀 3/3, 유한 밸브 가장자리 회귀 통과.
- UE5.8 Development 1062 빌드 성공. 3만 개 표시 및 0.02초 렌더 실행 검사 통과.

채택 실패: 제곱거리 방식의 수치 일치, AABB 후보의 모든 상태 성능 개선.
미실행: 새 코드의 장시간 전체 공정/잔류 0 검증, 30fps 지속 성능, 실물 물성 보정.
기존 흐름 검증을 유지하며 이번 시험을 새 물리 정확도 보증으로 해석하지 않는다.

## 실행과 재현

언리얼: `/Game/ProcessPlant_20261029/L_ProcessPlant_FlowTest`에서 Play.
1~4 확대, Space 일시정지, R 초기화, O 내보내기. 같은 레벨을 에디터 하나에 다시 열었다.

PowerShell, 저장소 루트에서 CMake Release `plant_bench`, `plant_optimization_tests` 빌드 후:

```powershell
# 기준: 마지막 두 값 = triangle AABB OFF / threaded OFF
Intermediate/PowderCore/Release/plant_bench.exe SourceAssets/ProcessPlantPhysics Docs/ProcessPlantPhysics/optimization/fixtures/PlantValidStage1.bin 1 0 320 Saved/base 0 0
# 개선: triangle AABB OFF / threaded ON
Intermediate/PowderCore/Release/plant_bench.exe SourceAssets/ProcessPlantPhysics Docs/ProcessPlantPhysics/optimization/fixtures/PlantValidStage1.bin 1 0 320 Saved/opt 0 1
Intermediate/PowderCore/Release/plant_optimization_tests.exe SourceAssets/ProcessPlantPhysics
```

인수: data, checkpoint 또는 initial, phase, split(진단), steps, output-prefix,
triangle-fast, threaded. 초기 상태는 `initial 0`, 수신기는 `PlantReceiverReady.bin 2`.
스냅샷은 진단 재시작이므로 시계/회전 위상은 초기화한다. 처음부터의 전체 실행과 다르다.
입력 체크섬·CPU/GPU 계측·비교 결과는 `results.json`, 원시 결과는 `evidence/`.

변경 파일: `Physics/PowderCore/include/powder/{plant,granular}.hpp`,
`Physics/PowderCore/src/{granular.cpp,granular_plant_cl.inc}`, `Physics/PowderCore/CMakeLists.txt`,
`Physics/PowderCore/tests/{plant_bench,plant_optimization_tests}.cpp`,
`Source/VirtualGameTeamProj/PowderPlantTest.cpp`, 이 문서 폴더.

남는 병목은 원본 상세 삼각형에 대한 반복 벽 투영이다. 이번 제한된 계획에서는
삼각형 수 축소나 충돌 근사, 시간 간격 확대를 넣지 않았다. 목표 0.1배속과의 격차는 크다.
commit/push는 하지 않았다.
