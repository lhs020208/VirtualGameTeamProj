# 공정 구간별 독립 시험

OBB 접근은 중단하고 `L_ProcessPlant_FlowTest`의 원래 삼각형 충돌을 사용한다. 원래 전체 공정 레벨은 수정하지 않았다. 기본 시작 레벨도 FlowTest로 복귀했다. 새 C++ 모듈은 1067이며, 이미 실행 중인 에디터는 저장 후 재시작해야 새 구간 제어를 사용한다.

모든 새 레벨은 `/Game/ProcessPlant_20261029/`에 있다.

| 레벨 | 초기 입자 위치 | 실행 후 조작 | 시험 경계조건 |
|---|---|---|---|
| `L_Section01_SupplyToWeighing` | 공급기 A/B/C 각 1,000개 | 공급기 A/B/C 열기 | 공급기 대기압, 칭량부 지정 흡입압. 칭량 출구는 닫힘 |
| `L_Section02_WeighingToReceiver` | 칭량호퍼에 3종 각 1,000개 | 공용 칭량호퍼 열기 | 칭량부 대기압 고정, 수취부 지정 흡입압. 수취부 출구 닫힘 |
| `L_Section03_ReceiverToMixer` | 수취부에 3종 각 1,000개 | 수취부→혼합기 열기, 필요시 혼합기 시작 | 양쪽 대기압, 중력 배출. 공압 이송 없음 |
| `L_Section04_MixerOnly` | 혼합기 바닥 위에 3종 각 1,000개 | 혼합기 시작 | 공기 이송 없음 |

시작 및 R 초기화 시 밸브는 모두 닫히고 혼합기는 정지한다. Space 일시정지/재개, O 입자 저장은 유지한다. GUI는 해당 구간의 조작만 노출한다. 표시 모드와 프레임 표시 설정은 물리 충돌을 변경하지 않는다.

## 분리 범위

원래 선택된 충돌 메시를 구간별로 골라 BVH를 새로 만들었다. 메시의 삼각형/단위/좌표를 근사하지 않았다. 불필요한 충돌 데이터는 압축 시 제거했다. 표시용 액터도 관련 설비만 남기고 표시 패널의 액터 참조를 정리했다. 기존 시험 연결 슬리브도 관련 구간에 보존했다.

| 구간 | 정지 삼각형 | 회전 삼각형 |
|---|---:|---:|
| 공급→칭량 | 100,072 | 0 |
| 칭량→수취 | 149,552 | 0 |
| 수취→혼합 | 31,728 | 8,956 |
| 혼합기 | 5,156 | 8,956 |

입자 수 3,000개, 반지름 1.25mm, 밀도 1,200kg/m³, 시간 간격 10µs, 접촉 반복 8회를 유지했다. 전체 공정 레벨은 기존 결합 압력 모델을 계속 사용하며, 새 구간 모델은 데이터 헤더의 section 값이 있을 때만 적용된다.

## 독립 시험의 의미와 한계

두 번째 구간의 대기압 고정 조건은 제거한 상류 설비를 대신하는 시험용 저장조 조건이다. 실제 닫힌 칭량호퍼의 압력 변화나 유한한 펌프 성능을 구현한 것이 아니다. 첫 번째와 두 번째는 기존 준정상 1D 압력·유량 모델, 세 번째와 네 번째는 공기 이송이 없는 시험이다. 제거한 설비의 영향과 전체 공정 연동을 검증하는 용도로 사용할 수 없다.

각 레벨의 초기 입자 배치는 독립적이며 전 구간 결과를 자동으로 다음 레벨에 넘기지 않는다. 구간 2~4는 내부에 겹치지 않는 시험 입자 배열을 새로 배치했다. 처음부터 충분히 침강한 분체층이 아니므로 필요한 경우 먼저 가라앉힌 후 밸브/혼합기를 조작한다. 원래 모델의 입구/개구부 형상도 유지하며, 제거한 장치를 대신하는 임의의 새 벽을 만들지 않았다.

## 검증

- Unreal Editor 빌드 1067 성공.
- 네 레벨 저장 후 다시 로드: section, 데이터 경로, 초기 입자 3,000개 확인.
- `plant_section_tests`: 각 구간 3,000개 전부 초기 벽 침투 없음(최대 위치 보정 0), 닫힌 밸브에서 흐름 없음, 해당 구간 외의 기체 흐름 비활성 확인. 320스텝 계산 및 종류별 1,000개 보존 확인.
- 각 구간 실제 초기 배치로 5,000스텝(0.05초) 계산 완료. 원래 전체 공정 밸브 회귀 검사 통과.
- 각 Unreal 레벨 NullRHI 실행: 0.01초 이상 계산, 3,000개, failed=false. `smoke_*.json` 참조.
- 짧은 벤치마크 속도는 약 0.021 / 0.021 / 0.021 / 0.0147배속이었다. 기존 에디터가 열린 상태의 단회 측정이며 초기 구간만 포함한다. 30fps 표시 성능, 전체 이송 완료, 안정 배속이나 분리 전 대비 개선을 보장하는 결과가 아니다.
- GUI 육안 점검 및 각 구간 전체 이송 완료 검증은 하지 않았다.

## 재생성

`python Scripts/build_plant_sections.py`로 데이터 생성. `Scripts/setup_plant_sections.py`는 FlowTest를 복제해 레벨을 만들며, 이미 있는 새 레벨을 덮어쓰지 않는다. `Scripts/verify_plant_sections.py`로 저장된 레벨 설정을 확인한다. 레벨은 바꿨지만 충돌 데이터가 그대로인 상태를 막기 위해 actor의 SectionTest와 runtime.plant의 구간 번호가 다르면 실행을 거부한다.

OBB 코드/데이터/보고서는 이력으로 남겼다. 취소된 `L_ProcessPlant_OBBTest` 파일은 실행 중인 에디터의 파일 잠금으로 보존되었으며, 기본 시작 레벨이나 새 시험의 기반으로 사용하지 않는다.
