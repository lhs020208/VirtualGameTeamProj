# 충돌 후보 최적화 01~06 결과

2026-11-03. 브랜치 `PowderSimulationOptimization`. 커밋/푸시하지 않았다.

## 적용 결과

현재 Hybrid 레벨은 **3,000개 이상일 때 mode 5(형상별 경계 + 후보 마스크)**, 그보다 적으면 기존 mode 3을 사용한다. 30개에서는 새 방식이 느려 기본 적용에서 제외했다. 3,000은 이번에 효과를 확인한 최소 시험 수이며 모든 입자 수에서의 최적 전환점이라는 뜻은 아니다.

충돌 표면, 처리 순서, 반경 2 mm, 밀도 1,200 kg/m³, dt 10 µs, 접촉 반복 8회, 압력/공기장 및 운영 초기 입자 A/B 각 10,000개와 C 0개를 유지했다. `runtime.plant` SHA256이 작업 전후 동일함을 확인했다. 장면/입자 데이터의 기존 미커밋 변경은 보존했다.

| 작업 | 상태 | 결과 |
|---|---|---|
| 01 비교 기준 | 완료, 계측 범위 제한 | 수정 전 실행 파일/해시와 초기·정체 재현 입력 확보. 경계 투영·경계 프로브·입자 접촉 GPU 시간 분리. 후보 탐색/범위 검사/정밀 접촉 각각의 커널 내부 시간은 독립 측정하지 못했으며, 후보 수 분석과 결합 성능으로 비교했다. |
| 02 경계 사전 계산 | 구현·검증, 단독 채택 기각 | 업로드 시 형상 AABB 생성. 단독 mode 4는 3천 정체 시험에서 약 4% 느려졌음. mode 5의 후보 마스크 구축용으로만 기본 채택. |

| 06 종합 검증·에디터 적용 | 완료, 장시간 전체 공정 미검증 | 3천/2만 반복 비교, 작은 관/회전 혼합기 비교, 같은 입력의 GPU 벽 계산 동시 대조, UE 빌드/PIE 확인. 긴 전체 궤적의 비트 단위 동일성은 기존 솔버도 성립하지 않음. |

## 성능

같은 물성/배치 크기 16/국소 크기 128/렌더 없는 별도 계산 실행 파일 비교. 당시 에디터는 편집 상태로 열려 있었다. 각 조건 3회, 실행 순서를 번갈아 배치한 중앙값이다. **초당 시뮬레이션 초(s/s)**이며 30 FPS 보장 수치가 아니다.

| 조건 | 기존 mode 3 | mode 5 | 속도 변화 |
|---|---:|---:|---:|
| 3천 초기 | 0.02059 | 0.02278 | +10.6% |
| 3천 정체 위치 재시작 | 0.004348 | 0.005018 | +15.4% |
| 2만 초기 | 0.009407 | 0.010152 | +7.9% |
| 2만 정체 위치 재시작 | 0.001625 | 0.001776 | +9.3% |
| 30개 관 구간 | 0.011528 | 0.009596 | -16.8%, 기본 적용 제외 |
| 30개 혼합기, 15 RPM | 0.024891 | 0.023228 | -6.7%, 기본 적용 제외 |

3천/2만 반복 측정은 1,000 step(물리 0.01초), 소수 입자는 3,000 step(0.03초) 구간이다. 정체 위치는 이전 2만 입자 CSV에서 추출했으며 속도를 0으로 재시작했다. 이전 실행 전체를 완벽히 복원한 체크포인트가 아니다. 초기 구간과 정체 구간은 별개이며 하나의 보장 배속으로 합칠 수 없다.

3천 정체의 분리 프로파일 500 step에서 벽 투영 GPU 시간은 1.0075 → 0.9353초, 벽 프로브는 0.1274 → 0.1191초였다. 분리 프로파일은 커널 호출과 계측 비용을 추가하므로 위 일반 실행의 속도와 직접 혼용하지 않는다. 후보의 96%가 겹치지 않았다는 앞선 분석을 96% 시간 절감으로 해석해서는 안 된다.

자료: `paired_summary.json`, `split3000_m*_0.json`.

## 정확성 및 발견된 기존 한계

- mode 4/5/6 각각 157,860개 경계 질의에서 원본 순회와 보정 위치/법선/벽 속도 차이 0.
- mode 5/6 각각 밸브 갱신·회전·반복 질의 등 18,732개 추가 질의에서 차이 0. 각각 891번의 용량 초과 복귀가 실제 실행됨.
- 짧은 3회 반복 비교에서는 모든 위치·속도 성분 차이가 0이었다.
- 2만 입자 5,000 step(0.05초)까지 늘리자 기존 실행 파일을 **그대로 두 번 실행해도** 위치 성분 최대 차이 약 3.28 mm, 속도 성분 최대 차이 약 0.241 m/s가 발생했다. 새 방식과의 차이는 약 3.07 mm/0.215 m/s였다. 이것을 허용 오차로 정해 통과시킨 것은 아니다. 긴 전체 궤적의 동일성 검사는 성립하지 않았다고 기록한다. 이웃 목록의 병렬 생성과 부동소수점 누적 순서가 원인 후보이며, 이번 충돌 최적화 범위에서는 변경하지 않았다.
- 대신 진단용 `plant_boundary_audit`를 추가했다. 같은 GPU 질의의 같은 입력에서 새 계산과 **새 경계/마스크/캐시를 사용하지 않는 원본 순회**를 함께 실행한다. 한 성분이라도 다르면 NaN을 반환해 기존 안전 가드로 실행을 실패시킨다. 단순히 차이를 허용하거나 결과를 원본으로 덮어쓰지 않는다.
- 이 동시 대조를 켠 2만 정체 5,000 step, 30개 회전 혼합기 20,000 step(0.2초), 초기 X 속도 2 m/s인 30개 10,000 step(0.1초)을 모두 통과했다. 진단 대조는 운영에서는 꺼져 있다.

자료: `mode*_regression.json`, `mode*_controls.json`, `nondeterminism.json`, `audit_*.json`, `final_checks.json`. `extended_summary.json`은 처음 발견한 궤적 불일치의 원시 기록이며 삭제하지 않았다.

## 메모리와 에디터

2만 입자 기준 plant GPU 버퍼:

- 기존 mode 3: 78,389,376 bytes.
- 적용 mode 5: 84,418,432 bytes. 추가 경계 정보 6,029,056 bytes(약 5.75 MiB).
- 실험 mode 6: 91,692,736 bytes.
- 입자별 벽 캐시 44,480,000 bytes는 유지된다. 위 수치는 전체 UE 프로세스 VRAM 사용량이 아니라 plant 버퍼만이다. GPU 업로드를 보존하는 CPU 패치 목록도 추가되며 CPU 최고 메모리는 별도 측정하지 않았다.
- 반복 시험 사이 표본 GPU 온도 44~48°C. 시험 스크립트는 시작 전 78°C 이상이면 중지한다. 연속 최고 온도 인증은 아니다.
- UE Development Editor 빌드 성공. 기존 색상 리터럴의 double→float 경고는 남아 있다.
- 재시작 후 `L_ProcessPlant_HybridCollisionTest` PIE 로그: `mode=5 particles=20000`.
- PIE에서 물리 시간 0.30352초, 인스턴스 `[10000,10000,0]`, 오류 빈 문자열 확인. 이때의 약 0.00693배는 밸브가 닫힌 초기 실행의 관측값으로, 이전 값과의 통제된 성능 비교가 아니다.
- PIE를 종료하고 같은 레벨을 편집 상태로 남겼다. 공기장 연결 누락 및 실제 이송 성능 문제는 이번 작업에서 고치지 않았다.

## 재현과 남은 작업

비교용 수정 전 실행 파일은 `Intermediate/CollisionCandidates/reference`에 보존했으며 해시는 `baseline.json`에 있다. 이 경로는 Git 추적 대상이 아니므로 새 체크아웃에서는 비교 기준 빌드를 따로 준비해야 한다. mode 0~3 비교 경로는 코드에도 남아 있다.

장시간 전체 이송·혼합 완료, 모든 밸브 순서/입도/입자 수, 전체 프로세스 CPU 최고 메모리, 경계 커널 내부 세 단계의 개별 GPU 시간, 모든 부품의 충돌 가능성 제거 증명은 미검증이다. 현재 개선은 약 8~15% 수준이며 0.03배/0.1배 목표 달성을 의미하지 않는다. 작업을 막는 빌드/실행 오류는 없으나, 기존 병렬 입자 계산의 긴 궤적 비결정성은 별도 해결 대상으로 남았다.
