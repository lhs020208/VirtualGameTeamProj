# 공정 UI 개발본

기존 프로젝트의 독립 플러그인 `Plugins/ProcessUI`. 기존 Source, Config, L_Main, 팀원 DEM 및 모델은 수정하지 않는다.

## 실행

1. Windows PowerShell에서 `Scripts/ProcessUI/Build.ps1` 실행.
2. `Scripts/ProcessUI/Validate.ps1` 실행. `/Game/ProcessUI/Maps/L_ProcessUI_Test`가 없을 때만 생성하고 저장된 레벨을 로드해 검사한다.
3. 새 플러그인은 기존에 켜진 에디터에 자동 주입하지 않는다. 작업 저장 후 에디터를 다시 열어 테스트 레벨을 열고 Play한다.
4. ‘설정·시퀀스’에서 물질·지름·속도·투입량·RPM·혼합 시간을 입력하고 단계를 작성한다. ‘테스트 예제 채우기’는 테스트 공급원 전용 수치이며 공정 사양이 아니다.
5. ‘실행 전 검증’ 후 ‘운전·상태’에서 시작한다. ‘장비·수동’에서 카메라 이동과 밸브 요청, 장비별 상태를 확인한다.

`Preview.ps1`는 별도 테스트 게임 프로세스에서 예제를 실행하고 일시정지·재개, 장비 카메라, 초기화 후 편집 화면을 확인한다. `Saved/ProcessUI/Preview.png`, `PreviewDevices.png`, `PreviewEditor.png`와 `PreviewResult.txt`를 남긴 뒤 종료한다. 일반 실행에는 자동 시작이 없다.

## 구조

- `ProcessUIRig`: Slate 한국어 UI, 카메라와 상징적 3D 표시. 시퀀스 판정 없음.
- `ProcessContract`: 장비/밸브 ID, 읽기 유효성·단위·시각, 명령/결과/세대, 교체형 공급원 인터페이스.
- `ProcessController`: 단계 전환, 일정 검증, 수취호퍼 점유, 예외 정지, 누적량 기반 재개.
- `ProcessTestProvider`: 시간·질량 장부 기반 모의 상태. DEM·CFD가 아니며 공압 장치 절차를 정의하지 않음.
- `ProcessDEMObserver`: 기준 커밋의 PowderPlantTest 공개 상태를 읽는 어댑터. 실제 제어 명령은 전부 거부.
- `ProcessUIEditor`: 핵심 공정 검사 및 전용 테스트 레벨 생성·로드 커맨드렛.

## 저장과 편집

설정은 `Saved/ProcessUI/Recipes/<이름>.json`에 저장한다. 동일 이름 저장은 덮어쓴다. 파일명에 경로 문자를 허용하지 않으며 임시 파일 후 이동한다. 불러온 설정은 스키마와 공정 조건을 검증하고 편집 상태로만 전환한다. 잘못된 설정은 기존 설정을 유지한다.

운전 중 일반 설정 편집은 잠긴다. 일시정지는 전체 정지·닫힘을 요청하며 재개 전 현재 정지 요청 ID에 대한 실제 확인과 누적량을 대조한다. 잘못된 원료, 예상 밖 누적량·장비 잔류량 또는 초기화 세대 변경은 정상 재개로 처리하지 않는다. 수동 닫기는 전체 정지 확인 전에도 요청 가능하다. 수동 열기는 전체 정지 확인 후 별도로 요청한다. 최초 예외 원인은 후속 버튼 안내와 별도로 보존한다.

칭량·수취 이송 단계는 하나씩 진행한다. 믹서 투입 단계 앞의 물질만 같은 수취호퍼에 모인다. 예약 0초는 초기 투입과 다르며 단일 수취호퍼 때문에 준비가 불가능하면 실행 전 검증에서 거부한다. 혼합 시계는 공급원 시간과 실제 혼합 상태를 사용하며 정지 상태에서는 증가하지 않는다.

## 테스트 공급원의 한계

테스트 용량(칭량 5 kg, 수취 10 kg, 믹서 20 kg), 이송 속도 0.05 kg/s, 안정 대기 0.3초 등은 모의 공급원의 선언값이다. 실장비 크기·성능·물성과 무관하다. 예제에는 가상 물질과 시험용 입력만 사용한다. 운전 UI는 모든 단계에서 테스트 공급원임을 표시한다.

3D 도형과 이동 점은 전체 경로와 현재 이송의 상징적 표현이다. 표시 점 수는 실제 입자 수가 아니고 실제 입자 지름을 표현하지 않는다. 원료별 색상 범례와 장비별 원료 질량 장부를 표시한다. 이동 표시는 버튼 상태 대신 테스트 공급원의 이송 상태를 따른다. 개별 입자 선택·추적은 제공하지 않는다. 실제 DEM 모드의 입자 시각화는 기존 DEM 액터가 담당한다. 실제 장비 카메라는 Rig의 `EquipmentFocusTargets`에 ID와 액터를 명시적으로 지정하며, 연결되지 않은 장비 위치를 추측하지 않는다.

## 병합

추가 경로는 `Plugins/ProcessUI`, `Content/ProcessUI`, `Scripts/ProcessUI`, `Docs/ProcessUI`뿐이다. 게임 모듈 Build.cs, 시작 맵, 팀원 파일 변경이 없어 기능별 병합이 가능하다. 기준 브랜치를 자동 병합하지 않았으며 팀원에게 메시지를 보내지 않았다. 실제 연동은 [IntegrationDraft.md](IntegrationDraft.md)의 합의 전 규약을 검토해야 한다.

빌드 스크립트는 에디터가 열려 있으면 UBT의 DLL 접미사 기능으로 에디터 대상을 빌드한다. 기존에 로드된 DLL을 덮어쓰거나 열린 에디터를 종료하지 않는다. 새 파일은 별도 검증 프로세스에서 로드한다. 에디터가 닫혀 있으면 UI 모듈만 빌드하고 UBT가 생성한 플러그인 메타데이터만 기록한다. 빌드 성공 메시지 외에 실제 DLL 파일도 확인한다.

검증 결과와 미연결 항목은 [ValidationReport.md](ValidationReport.md)를 참고한다.

예약 준비 미완료는 배치 중단·초기화 필수 예외다. 예약 변경이나 늦은 재개를 허용하지 않는다. 정지·닫힘 요청 후 사용자가 배치를 중단하고 실제 상태 확인 후 초기화한다.
